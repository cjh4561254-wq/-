## 1. 为什么是方案 01

十套方案不是"换配色"，它们对"用户打开页面第一件事是什么"给了**互斥的答案**。
唯一事实来源是 **`docs/design-options/00-brief-and-matrix.md`**（共享约束 + 后端能力硬边界在 §2，
10 套方案的坐标分配在 §3）；方案 01 的完整设计说明是 **`docs/design-options/option-01.md`**，
配套高保真原型在 `design-options/option-01/index.html`（原型不进生产页，因此不受前端测试管辖）。

选定 01 的理由，落到可以核对的三条：

1. **它匹配这个产品真实的能力形状。** 后端能做的是"一次提问 → 一份带溯源的报告"，
   它**没有**数据集列表之外的运营指标、没有队列、没有调度视图、没有业务看板聚合接口。
   方案 01 的"先看结论"立场只需要 `history` + `history/{id}` 两个只读接口就能填满首屏；
   而"看队列与状态"（方案 09）或"多业务 KPI 看板"（需要后端聚合销售额/份额/同比）在本项目**没有数据源**，
   真做出来必然是假数据。
2. **它把"可追溯"这个唯一真实卖点放到了首屏。** 主张句是"把市场数据，变成能追溯的决策依据"，
   01 的首屏结构（问题 → 结论 → 取数次数 → 打开原文）就是这句话的界面化，不需要额外发明能力。
3. **它的改造半径可控**：结构层（外框、导航位置、首屏）全换，但**视图键名、后端接口、测试钉住的
   DOM 契约一个都不动**（见 §5 D-8）。这让我们能在 940+ 条用例全绿的前提下完成改版。

**这次重构改了什么的一句话概括**：顶部导航 → **左侧栏 240px（3 组 6 项）+ 顶部命令条（非导航、无全局搜索）**；
首屏 → **战略态势带**；`analysis` 视图里的执行过程拆成独立的 `runs` 视图；设置页补上改密与会话列表；
登录页改成两栏 + 中文主张句。

## 3. 战略态势带的数据口径（**唯一规定**，改口径只改这一处）

态势带一行四列 = **问题 / 结论 / 取数情况 / 动作**。四个字段各有唯一一个来源，实现落在 `app.js` 的
`posture*` 系列函数里，取证与论证过程在 `docs/refactor/05-posture-data-flow.md`（本文不复制）。

| 界面上显示的东西 | 唯一取法 | 为什么是它 | 取不到时说什么 |
| --- | --- | --- | --- |
| 业务问题（第 1 列） | `history.items[].question` **原样**，不截不断句不改写 | 这是用户当时敲进框里的原话，是"业务问题"这个词唯一真实的载体 | 只有全空白 → 「（这条记录没有留下问题文本）」 |
| 一句结论（第 2 列） | `report.sections[0].text` **原样**（CSS 两行截断，`title` 里放全文）；小标题 = `sections[0].heading` | 报告正文第一段才是业务结论 | `sections` 非数组或首段 `text` 为空 → 「这条记录没有可显示的结论正文」，**并说明"不会拿报告总述顶替那一段"** |
| 取数调用 N 次（第 3 列） | `new Set(report.citations).size`，即**成功产出了结果的取数任务数**（空数组就是 0，不是「—」） | `citations` 是"每一次工具调用"的记录；文案刻意写「取数调用」而不是"证据数"，同屏就不可能出现第二个含义不同的"证据数" | 字段不是数组 → 「—（未提供引用信息）」 |
| 行内时间 | `items[].finished_at`，标签写「**分析完成于**」 | 归档库里这条记录跑完的时刻 | `finished_at` 为 null → 退回 `created_at` 并**把标签换成「创建于」**（把创建时间说成完成时间就是编造） |
| 「查看报告」 | 深链到历史记录详情 `#/history/{workflow_id}` | 归档详情走的是 SQLite，重启后仍打得开 | — |

### 3.1 为什么**不用** `summary`

`FinalReport.summary` 实测是"成功 N 个任务 / 未完成任务 M 个"这类**关于这次运行的元说明**，不是业务结论。
把它当结论上屏 = 把元数据当洞察，正是这一版要消灭的东西。落地上还有一条连带禁令：正文角标走
`sections[].cites`（去重并集，用来和证据区逐条对应），**不参与**第 3 列的计数。

### 3.2 取数接口与请求预算（D-6 的落地）

- 首屏最多 **4 个 GET**：`GET /api/workflows/history?limit=12&offset=0` ×1 + 前 3 个合格候选各
  `GET /api/workflows/history/{id}` ×1。资格 = `has_report === true` 且 `status ∈ {SUCCESS, SUCCESS_WITH_WARNINGS}`。
- **禁止**用 `GET /api/workflows/{id}/report`（读的是进程内注册表，重启后 `has_report=true` 也会 404）。
- **禁止**碰 `GET /api/workflows/{id}`：它里面的 `_expire_if_stale` 会**写状态并落库**——看一眼列表就把某条
  工作流判成 FAILED 并归档，这是"探测即污染"。同理禁止任何 POST、禁止在首屏请求图表 PNG。
- 分流只看响应体 `ok` / `error.code`，不按 HTTP 状态码（超时也是 200）。

### 3.3 指标网格的四格同样有口径

`#metric-datasets` = `GET /api/datasets` 的 `total`（全量）；`#metric-running` = **本次会话正在轮询的那一条**
（后端没有"全部运行中"的统计接口）；`#metric-reports` / `#metric-failed` 只统计**本次读取的归档样本**，
并且每格下方都写了这句样本口径（`#metrics-caliber` 整段说明）。拿不到的数字一律写「—」——
「—」是"还没拿到"，不是 0。首屏**不出现**任何需要后端聚合才有的业务指标（销售额、份额、同比、ROI）。

## 4. 命令条与导航上的三条禁令

1. **命令条显示「数据资产更新于 `<max uploaded_at>`」，不显示"数据截至"**（D-7）。
   来源是 `GET /api/datasets` 里最大的 `uploaded_at`，真实可得；而"数据截至"隐含"结论覆盖到哪天"，
   归档链路里**没有 `dataset_id`**，没有任何字段能证明这条结论对应哪份数据、覆盖到哪一天。宁可少画一格。
2. **不自绘业务趋势图**（D-1）。真实图表只有一个来源：后端 matplotlib 渲染的 PNG。
3. **不出现导出 / 下载 / 分享入口**，也不出现"删除任务""重置演示数据"这类后端根本没有的按钮
   （守卫：`test_no_forbidden_entry_points_in_clickable_elements`；`#i-download` 在精灵里保留定义但生产 DOM 不许 `use`）。

## 6. 已知偏差与限制（**这些是决定，不是遗漏**）

1. **不自绘业务趋势图。** 后端只在一次工作流内部做聚合，没有跨期时序接口；
   原型里的"近 6 季度趋势"没有真实数据源，画出来就是假数据。真实图表只有一个来源：`/charts/{filename}` 的 PNG。
2. **不显示"数据截至"。** 归档链路不带 `dataset_id`，无法证明某条结论对应哪份数据、覆盖到哪天。
   命令条改用可真实导出的「数据资产更新于 `<max uploaded_at>`」。
3. **去掉升降 delta（▲12.4% 那一类）。** 后端没有任何同比/环比字段。原型里那些涨跌是占位样例。
4. **`.btn--primary` 的色值仍是 `--brand-600`，没有换成方案 01 的 navy。**
   `tests/test_frontend.py`（`:547` 起的 `_css_rule` 解析 + `:461` 起的 `:root` hex 对比度计算）
   把这个主按钮色值和"禁用态对比度 ≥4.5"一起钉住了；换成 navy 还会同屏出现两种主按钮色。**已知偏差 + 被测试钉住**。
5. **两套墨阶并存，而且这是终态。** 正文与标题走**存量暖阶** `--n-800 / --n-900`；
   新增组件（侧栏 `.sidebar*`、命令条 `.cmdbar*`、态势带 `.posture*` / `.metric*`、报告 `.doc__*`）走**冷阶** `--ds-ink-*`。
   理由：改全站墨阶的影响面（所有旧视图的对比度、所有相关断言）远大于收益，边界已在 `10-integration-log.md` 批次 4 定死。
6. **`--ds-viz-*` 已重指到后端 PNG 的同值（`--viz-legacy-*`）。** 这样前端极小的内联图形与后端 PNG 同色；
   代价是**放弃方案 01 §4 的 navy 图表色板**。根因：PNG 不能被 CSS 重着色，同屏两套色必然分裂，
   而后端饼图色板 `_PIE_PALETTE` 还经过色盲 ΔE 与对比度验证，动它等于动后端。
7. **侧栏 `#badge-runs` 的口径是"本次会话正在轮询的那一条"**，不是"全部运行中"。后端没有这个统计接口，前端不编。
8. **登录页三形态里的"首次建管理员"在交付环境不可自然出现**（账号库非空时 bootstrap 按设计返回 403）。
   `09-e2e-defects.md` P0-1 已如实记录：那一轮用运维脚本建号，bootstrap 的 **UI 全链路属于未实测**。
9. **深浅底对比度的用法守则**：状态底色（`--ok/warn/err-100` 一类）上只许用 `--ds-ink-body`，
   不许用 `--ds-ink-secondary`（实测 4.09–4.39，达不到 4.5）。
10. **深底发丝线**：`--navy-800` 压在 `--navy-900` 上实测 1.24:1，等于不存在；
    新增 `--rule-on-navy: rgba(255,255,255,.16)`（取 .16 不取 .12 是为了过非文本图形 3:1）。
11. **`.statstrip` 与 `.kpi` 的规则留在 `app.css` 里没有删除**，因为删除会连带风险于静态解析类名的断言；
    首屏用的是 `.metrics/.metric`。两套并存是有意的过渡终态。

## 8. 文档锚点腐烂：边界与实测

### 8.1 `check_docs.py` 到底管什么（代码级核实，不是转述）

- `PROJECT_ROOT / "docs" / "HISTORY_ROBUSTNESS.md"` 是**写死的唯一文档目标**（脚本里的 `DOC` 常量）；
  其余文档**一个字都不读**。
- 代码侧锚点只从 `app/`、`scripts/` 下的 `*.py` 收集（`CODE_DIRS` + `rglob("*.py")`），
  而且必须匹配 `# **:NNN** ` + 反引号引文**的声明形态**才成立；省略式 `**:NNN**` 继承上一个文件名。
- 三个核对维度：行号锚点（文档声明 ↔ 代码自证）、用例存在性（`ast` 收集 `tests/` 真函数，不扫文本）、
  断言方向（实际执行用例，比对参数实例数与每个请求的状态码）。
- **`app/web/*` 完全在它管辖之外**：它不读 CSS/JS/HTML，`tests/test_check_docs.py` 也不钉前端 DOM。

结论：**前端行号锚点没有守卫。** 谁想"让 CI 管住前端锚点"，要么扩脚本要么加测试，
那属于守卫扩展，**不在本轮范围**（已单独报给主控，本文只把边界写清楚）。

### 8.2 本轮实测的腐烂量

扫描 `docs/refactor/01..05`、`design-system.md`、`ui-review.md`、`ux-spec-final.md`、`final-report.md`、
`limitations.md` 里所有 `app.js|app.css|index.html|tokens.css|login.*:NNN` 形式的引用：

```
锚点总数 526  ｜  指向越界行（文件没那么长）6  ｜  指向空行 47  ｜  落在非空行 473
分布最多的几个文件：design-system.md 127 / refactor/04-i18n-checklist.md 96 / ui-review.md 73
```

> **同一次会话里这两个数就变过**：第一次量是 `525 / 6 / 52 / 467`，约一小时后并发 agent 往 `app/web` 写了代码，
> 变成 `526 / 6 / 47 / 473` —— 分母在涨、指向空行的反而少了（因为那些空行被新规则填上了）。
> **没有任何一个数字是"错"的，它们都只是时点**，这正是本文不把它们当事实、只当证据链的原因。

"落在非空行"不等于对：Wave A 更严的口径（比对行内是否含声称的符号）量到 **215 条前端锚点里 30 条空行、
154 条符号失配**。两个口径都指向同一件事：**这些数字是写作时点的快照，不是可复核的事实。**

最生动的一条：Wave A 当时报告 `tokens.css` 注释里的 `app.css:282/283/284/775` 已经漂到
`299/300/301/858`；**本轮（几天后）再量，`.dot--ok/.dot--warn/.dot--err` 在 292/293/294，
`.error-box .detail` 在 914，而 `:root` 块从注释里的 `21-113` 变成 `18-105`。**
连"修正后的行号"都留不住 —— 这就是新文档改用符号名的全部理由。
