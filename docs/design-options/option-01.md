方案 01：高端企业战略指挥中心

> 归属：`docs/design-options/option-01.md`，配套 Demo `design-options/option-01/index.html`。
> 坐标（来自 `00-brief-and-matrix.md` 第 3 节，不得偏离）：导航 = 左侧栏 240px（3 组 6 项）+ 顶部命令条；首屏主角 = 战略态势带（3 个业务问题 × 结论 × 证据数）；密度 = 高；数据主角 = 指标 + 结构化表；主题 = 亮；立场 = "决策者要的是现在该看哪里"。

---

## 1. 设计名称

**高端企业战略指挥中心（Executive Strategy Command Center）**。面向企业高管与经营分析负责人的"看结论、定优先级"界面：进入即回答"此刻该看哪里"，而不是"今天想做什么操作"。

## 2. 核心设计理念

这套方案把界面当作一块**决策面板**而非工作流表单。它假设使用者时间稀缺、不需要理解 Agent 怎么跑，只需要三件事：现在哪个业务问题最该关注、结论是什么、这个结论背后有多少可核对的证据。因此首屏不给待办列表、不给图表墙，而是一条**战略态势带**——三个真实业务问题，每个后面紧跟一句结论和一个证据数，决策者扫一眼就知道注意力该往哪投放。所有视觉语言为这个假设服务：中性墨灰承担约九成画面，单一深海军蓝只在"你现在在哪、可以点、正在跑"三处出现；状态色仅在有语义时才露脸。结构化业务表（销售额 / 份额 / 增速 / 区域）作为数据主角，用细线与右对齐等宽数字建立报表级密度，而不是把一切塞进卡片。它刻意区别于面向运维的"看队列与状态"（方案 09）和面向高频操作的"功能页工作台"（方案 06）——这里组织信息的单位是"一个待决策的业务问题"。

## 3. 视觉关键词

`决策面板` `细线分带` `单一深海军蓝` `报表级数字` `克制留白` `高信息密度`

## 5. 页面布局

**外框**：CSS Grid 两列 `240px 1fr`。

- **左侧栏 240px（导航主轴）**：固定、独立滚动、`brand-900` 深底。分 **3 组 6 项**——组「指挥」：战略态势、数据资产；组「分析」：发起分析、Agent 运行；组「成果」：分析报告、历史记录。当前项左侧 3px 竖标 + `brand-800` 底色；两项带计数徽标（数据集数 / 运行中数），数字来自真实接口统计口径。栏底放部署版本与会话时长。
- **顶部命令条（非导航）**：右侧列顶部的粘性细条。它**不含导航、不含全局搜索**，只承载上下文与决策动作：视图标题、`数据截至 2026-10-15`、设计声明"视觉方案示意 · 数据为占位样例 · 未接入后端"、服务健康点（`GET /api/health`）、「发起新分析」主按钮、账户与退出。它是本方案与 06 的关键区别——06 的顶栏是可点击的一级导航，这里的顶栏是一条状态/动作命令条。

**内容栅格**：主内容最大宽度 1220px。首屏态势带为满宽带（4 列：问题 / 结论 / 证据 / 动作），关键指标为 4 列 hairline 网格（分隔线，不用卡片投影），下方为 `1.6fr 1fr` 双列（业务表 + 趋势图）。表格用右对齐等宽数字（`tabular-nums`）压缩列宽、提高密度。

**断点**：
- 1440px 为设计基准宽度。
- ≤ 1080px：态势带转 2 列、指标转 2×2、双列合并为单列。
- ≤ 768px：侧栏转顶部横向标签行（换行），命令条换行，**表格转"标签—值"堆叠**（`td::before` 显示 `data-label`），无整页横向滚动；登录页隐藏左侧品牌面板只留表单。

**与近似方案的 DOM 级区别（自检要求）**：
- **vs 方案 09**：01 根为 `aside.sidebar[三组 nav]` + `header.cmdbar`（无 nav、无搜索）+ `main` 首屏 `posture` 态势带；09 根为 `main.queues` 四列状态泳道（等待/运行/完成/失败）+ 底部固定 `eventstream` 抽屉，暗色外壳。01 的表列为**业务数据**（销售额/份额/增速/区域），09 的表列为**任务数据**（阶段/心跳/重试）；用户分别为业务决策者与平台运维者。
- **vs 方案 06**：01 主导航在**左侧栏**、顶栏是命令条；06 一级导航在**顶部横向**、页内有 `role="tablist"` 的二级 Tab，且首屏是"待办→最近运行→数据集"分区。01 首屏是态势带（结论优先），非待办列表。

## 6. 登录页面

未登录时**隐藏左侧栏与命令条**（`body.in-login`），未认证用户不应看到系统导航。布局为左右两栏（`1.05fr .95fr`）：左侧 `brand-900` 品牌面板，放一句话价值主张"把市场数据，变成能追溯的决策依据"与两条能力事实（6 段流水线 / 100% 结论带证据角标）；右侧白底表单。

覆盖三种形态（原型内用「演示」行切换）：
- **日常登录**：用户名 + 密码，`autocomplete` 正确绑定；提交走 `POST /auth/login`。
- **首次建管理员（`needs_bootstrap`）**：当 `GET /api/auth/me` 返回 `needs_bootstrap=true` 时进入。标题"创建第一个管理员"，副文案说明"该部署还没有任何账号，此入口创建成功后不再出现"；额外出现"显示名称"（可选，对应 `display_name`）与"确认密码"（**仅本地校验**，后端 bootstrap 无此字段），按钮文案"创建管理员并进入"，走 `POST /auth/bootstrap`。
- **失败态**：统一文案，区分 401（账号或密码不正确）、429（限流，按 `Retry-After` 头提示"30 秒后重试"）、503（服务不可用）。alert 区 `role="alert" aria-live="assertive"`。

## 7. Dashboard / 工作台（战略态势带）

用户第一屏即"战略态势带 · 本周该看的三件事"。每行 = 一个业务问题 + 一句结论（带升降色 delta）+ 证据数与来源文件名（含 `cites` 角标）+「查看报告」跳转。三行分别对应"华东 Q3 销售额同比 / 主力品类份额 / 华南促销 ROI"这类真实经营问题，直接回答"现在该看哪里"。

态势带下方依次为：4 个关键指标（hairline 网格，非卡片）、区域业务表（销售额/份额条/增速）、近 6 季度销售额趋势（内联 SVG 折线）。信息按"结论 → 支撑指标 → 明细"的决策顺序纵向组织。

## 8. Market Analysis（市场分析完整路径）

路径：**选数据集 → 用业务语言提问 → 发起 → 在 Agent 运行看状态 → 看结果**。

1. **选数据集**：`<select>` 列出 `GET /api/datasets` 结果（文件名 · 行数 · 上传日），默认按上传时间。右侧同步显示该集画像摘要（列数/行数/缺失最高列/重复行/告警），来自 `GET /api/datasets/{id}/profile`。
2. **输入需求**：`textarea`，实时字数计数并**强制 `question` 2–500 字**真实约束——超 500 或不足 2 字时计数变红、发起按钮拦截。
3. **发起**：`max_steps` 选择器**限定 1–8**（快速 3 / 标准 5 / 充分 6 / 深度 8）。点击"发起分析"→ 文案显示"POST /api/analysis → 202，workflow_id=…"→ 自动转到 Agent 运行视图。
4. **看状态**：见第 9 节。
5. **看结果**：见第 10 节。

原型内点击仅做视图切换，不伪造后端行为。

## 9. Agent Runs（执行可视化）

严守 `00-brief` 2.2-3：**不出现阶段级耗时、阶段时间戳、按时间的进度百分比**。

- **进度用 `step_index / total_steps` 阶梯**：6 段（读取数据 / 制定计划 / 计算中 / 出图中 / 写报告中 / 校验中），已完成段实心蓝、正在执行段浅蓝脉冲、未达段灰轨、跳过段斜纹。上方一行大字标注"进度口径 = step_index / total_steps（3 / 6）"。
- **轮询真实呈现**：头部写"每 1000ms 轮询 `GET /api/workflows/{id}`，非实时推送"，运行态显示"上次更新 2 秒前"+ 轻量 spinner，不画"实时日志流/秒级推送"。
- **任务级状态用后端 TaskStatus 六值中文映射**（等待执行/正在执行/已完成/执行失败/重试中/已跳过），并保留原始枚举可查证（`<span class="sr">`）。
- **工作流状态用十值中文映射**（等待中/读取数据/制定计划/计算中/出图中/写报告中/校验中/成功/带警告完成/失败）。
- **总耗时**：仅在已完成任务显示"总耗时 03:12"，并注明这是整条任务 `created_at→finished_at` 的真实值，非阶段耗时。

## 10. Reports（报告呈现）

文档式单栏（`article.doc`，最大 900px），**核心差异点是可追溯**：

- 头部编号 `R-2026-10-15/01`、生成时间、**数据截至 2026-10-15**、来源数据集、正文来源标注（大模型撰写 / 规则模板）。
- 正文小节（摘要 / 关键发现 / 建议），关键数字带 `.hl`，其后紧跟 **`cites: T1/T2/T4` 上标角标**。
- 数据质量提示块（`data_quality_notes`）。
- 校验结果：按后端 severity 三级 `error / warning / info` 徽标 + 说明。
- **证据来源区**：每条 `T1…T4` 一行 = 数据集 + 计算口径 + 工具调用名（`query:groupby_sum` 等），与正文角标一一对应。

不设导出/下载/分享按钮（后端无接口）。

## 11. 动效（逐条：动效 → 业务价值）

| 动效 | 参数 | 业务价值 |
| --- | --- | --- |
| 视图切换淡入 | `120–200ms` 透明度 + 6px 位移 | 明确"换了一块决策面板"，避免内容跳变造成定位丢失 |
| 阶段推进（等待→运行→完成） | 状态点 `320ms` 底色过渡 | 让 step_index 前进可感知，传达"在推进不是卡住" |
| 运行态脉冲点 | `1.2s` 循环透明度 | 标识"当前正在执行的那一步"，扫读定位 |
| 轮询刷新 | 不做闪烁，仅更新"上次更新 X 秒前"文本 | 遵守 2.2-4：轮询不该伪装成实时推送，避免虚假活跃感 |
| 表格行 hover | `120ms` 背景 | 高密度表内提示"这一行可读"，纯可达性 |
| 骨架加载 | `1.3s` shimmer | 加载态占位，明确"正在取数"而非空数据 |
| 份额条 / 折线 | 首次出现 `500ms` 生长 | 建立数值量级的第一眼感知，仅一次不循环 |

hover 不做缩放装饰；无粒子、无发光。

## 12. 优点

- 首屏即结论，决策者零学习成本，最贴合高管与经营分析负责人。
- 单一品牌蓝 + 中性灰的高密度排版，专业、克制、耐看，适合对外呈现。
- 态势带的"问题 × 结论 × 证据"结构把产品核心价值（可追溯）前置到首页。
- 侧栏 3 组 6 项覆盖后端全部真实能力，无假入口。
- 亮色 + 细线 + 等宽数字，业务表与报告 PNG 图（浅底）风格天然契合。

## 13. 缺点（真缺点）

1. **信息风险**：态势带只放 3 条结论，若业务上"该看的事"超过三条，会被裁掉或需要额外扩展机制，否则遗漏。
2. **实现成本高**：首屏态势带需要把历史报告的"结论 + 证据数"结构化成可排序的卡片流，前端要做聚合与刷新，后端目前无"精选结论"接口，需用 `history` + 逐条 `report` 拼，成本不低。
3. **对新手不友好**：默认假设使用者已知要看什么，缺少引导式待办，第一次用的人可能不知如何发起分析。
4. **密度与可读的张力**：高信息密度在小屏 / 投影仪演示下易显拥挤，依赖 768px 断点的表格转堆叠，但趋势图在小屏仍偏挤。

## 14. 适合的企业类型

中大型消费 / 零售 / 市场研究导向企业，设有经营分析或市场情报团队、以周/季度节奏做区域与品类决策，且使用者以上线看结论的管理者与分析师为主。不适合把平台当调试工具的研发团队（应选 09）或极简单人轻量使用（应选 05/08）。

## 15. 推荐指数

**★★★★☆（4/5）**。理由：定位清晰、专业感强、把"可追溯决策"前置到首屏，适合正式对外与高管日常；扣一星是因为首屏结论流依赖尚不存在的聚合能力，落地成本偏高。
**何时应选它而不是别的**：当用户主体是"没时间操作、只要知道现在该看哪里"的业务决策者时选 01；如果他们要看任务怎么跑（选 09）、要跑高频功能页（选 06）、或要探索式改筛选看图（选 07），就不该用这套。

## 附：与现有代码的落地影响

**结论：纯表现层，不需要动后端。** 本方案所有入口都映射到 `00-brief` 2.1 已存在的接口，无新增后端需求，不破坏现有能力。

需要改的表现层文件（`app/web/`）：

- **`app/web/tokens.css`**：本方案沿用现有 `--brand-* / --n-* / --ds-*` 令牌族即可，无需改值；如需"侧栏深底"可新增少量 `--ds-shell-*` 语义令牌（兼容层仍指向同一 hex）。不引入 `backdrop-filter`、外链字体、`@font-face`。
- **`app/web/index.html`**：把现有"顶部导航 + `#crumb`"结构改为 `240px 左侧栏（3 组 nav）+ 顶部命令条` 骨架；首屏容器改为战略态势带（新增一段聚合结论的区块，数据由现有 `history` + `report` 渲染函数产出）。
- **`app/web/app.css`**：新增侧栏、命令条、态势带、hairline 指标网格的样式；现有表格 / pill / report / stepper 样式基本可复用。焦点用 `outline` 而非发光 `box-shadow`。
- **`app/web/app.js`**：`VIEWS` 增加 `command`（态势带）与分组导航映射；`historyStatusText` / `TASK_STATUS_TEXT` / `CHART_TYPE_TEXT` 直接复用（已是十值 / 六值中文映射）；轮询逻辑（TERMINAL 判定、1000ms 轮询）不变；报告渲染已有 `cites` 角标与来源行，沿用即可。Agent 视图只读 `step_index/total_steps`，不新增任何"阶段耗时"字段读取。

**是否需要动后端：不需要。** 若产品坚持"首屏精选三条结论"想要一个专用排序接口，那是可选增强，不落地也能用现有 `GET /api/workflows/history` + 逐条 `report` 在前端聚合出态势带；当前方案默认不要求后端改动。
