# 方案 06：现代 SaaS 工作台

> 依据 `00-brief-and-matrix.md` 第 3 节坐标：**顶部一级导航 + 页内二级 Tab**；首屏 = 模块分区（待办 → 最近运行 → 数据集）；密度中；数据主角 = 列表 + 进度；亮色。
> 设计立场：**高频操作路径最短**。
> 对应 Demo：`design-options/option-06/index.html`（8 个视图，顶栏固定声明「视觉方案示意 · 数据为占位样例 · 未接入后端」）。

---

## 1. 设计名称

现代 SaaS 工作台（Modern SaaS Workspace）。

一句话识别特征：**一条 56px 顶部一级导航 + 一条 32px 服务状态条，页面内部用「模块分区」自上而下排列，二级维度切换只在页内发生。** 没有侧栏，没有会话列表，没有筛选器抽屉——这三句话把它和 01、02、07 永久区分开。

中文名称用于文档与评审，界面上的产品名仍是「市场情报与智能分析平台 / AI Market Intelligence Studio」。

---

## 2. 核心设计理念

这套方案要回答的不是「这个产品有多厉害」，而是「我今天进来该做哪件事、点哪里、几步做完」。所以它把界面当成一张**值班台**：第一屏只放三块东西——需要你处理的待办、正在跑或刚跑完的分析、你手上的数据集；其余能力全部收在顶部五个一级入口里，每个入口进去后是一个自足的页面，页内再用二级切换组织内容。

「路径最短」在这里是可度量的约束，而不是口号：**发起一次分析最多 3 次点击**（工作台 → 发起分析 → 提交），**回看一次运行最多 2 次点击**（工作台待办 → 回看），**读一份历史报告最多 3 次点击**（运行记录 → 历史归档 → 看报告）。任何需要在两个页面之间来回搬运上下文的设计，都被判定为失败。

第二层理念是**界面不许假装知道得比后端多**。这一点在本方案里比在别的方案里更关键，因为「工作台」这种形态最容易诱人伪造一个任务系统来填充首屏。本方案的「待办」是一个**推导函数**：输入只有 `GET /api/health`、`GET /api/datasets`、`GET /api/workflows/{id}`、`GET /api/workflows/history` 的字段，输出是 0–5 条，规则写死在前端、每条都把自己的推导来源原样显示出来（见第 7 节推导表）。没有新建任务按钮，没有「标记完成」，没有工单。用户能核对每一条。

第三层是**克制的可配置**：只提供表格密度三档（紧凑 32 / 常规 40 / 宽松 48，行高对齐 Carbon 尺度），存 `localStorage`，纯前端真实可实现；不提供「保存视图」「自定义工作台布局」，因为后端没有承载用户偏好的接口，做了就是假功能。

---

## 3. 视觉关键词

**值班台感**（每个模块都在回答「现在要不要你动手」）、**分区明确**（1px 分隔线 + 面板头，不靠阴影分层）、**列表即主角**（信息以行和列组织，不做指标墙）、**进度可核对**（阶梯格 + `step_index/total_steps` 数字同时出现）、**中性灰为主**（品牌蓝只用于「当前在哪 / 可以点 / 正在跑」三件事）。

## 5. 页面布局

### 5.1 骨架

- **顶部一级导航**：56px，`position:sticky`。左侧品牌标记 + 产品名 + 英文名；中间五个一级入口 `工作台 / 数据集 / 市场分析 / 运行记录 / 界面状态`；右侧「待办 N 项」文字计数（**不是铃铛、不是红点**）+ `发起分析` 主按钮 + 账号菜单（当前账号、会话说明、修改密码、退出登录）。
- **服务状态条**：32px，常驻。左端是数据诚实声明徽章，接着是 `GET /api/health` 的真实字段行（`app_name / version / uptime_seconds / llm_configured / upload_dir_ready / status`），右端是三个**原型开关**（服务状态 / 数据集是否存在 / 接口读取结果）与密度三档。原型开关全部带「原型开关（非产品功能）」前缀，避免被误认成产品功能。
- **版心**：`max-width:1320px` 居中，20px 内边距，12px 栅格间距。密度中：正文 14px、行高 40px、面板内边距 12px。

### 5.2 断点

两档硬要求：**1440px**（双栏 `2fr / 1fr`，图表区 2 列）与 **768px**。窄屏行为：
- 顶栏换行（高度自适应），品牌英文名隐藏，状态条换行；
- **所有表格转「标签—值」堆叠**：`thead` 隐藏，每个 `td` 用 `data-label` 生成左侧标签，行变成带边框的小卡；`.tbl-wrap` 的 `overflow-x` 置为 `visible`，**整页不出现横向滚动**；
- 双栏与 2 列图表区降为单列，运行轨道行变成纵向；
- 登录页隐藏左侧价值主张栏，只留表单。

### 5.3 每一处切换属于哪一类（Carbon `tabs/guidelines` 实测结论）

规范：**同一对象的不同维度 → 分段控件 / Content Switcher；多类别内容 → Tab；线性流程 → Progress Indicator。** 本方案全篇只有 4 处切换，逐处归类如下：

| 位置 | 控件 | 归类 | 为什么 |
| --- | --- | --- | --- |
| 数据集页：`数据集列表 / 上传数据集` | **Tab**（`role=tablist`） | 多类别内容 | 一个是读（列表 + 筛选 + 分页），一个是写（multipart 表单），任务性质不同，不是同一对象的两个维度 |
| 数据集详情：`概览 / 字段画像` | **Content Switcher**（`aria-pressed`） | 同一数据集换维度 | 主语始终是同一个 `dataset_id`，只是换 `GET /api/datasets/{id}` 与 `/profile` 两个视角看它 |
| 运行记录页：`当前运行 / 历史归档` | **Tab** | 多类别内容 | 数据源不同：内存态轮询接口 vs SQLite 归档接口；一个是易变的进行时，一个是不可变的过去时 |
| 报告页：`报告正文 / 数据质量与校验 / 来源与引用` | **Tab** | 多类别内容 | 正文是交付物，校验是元信息，来源是取证清单，三类读者（业务方 / 复核人 / 审计）各自只看一类 |
| 市场分析页：`选择数据集 → 描述需求 → 发起` | **Progress Indicator**（`.stepper`） | 线性流程 | 有严格先后与完成态，绝不能被理解成「可以随便切」，所以不是 Tab |
| 运行详情：六个阶段 | **Progress Indicator**（`.stepper` + 阶梯格） | 线性流程 | 同上；阶段不可任意跳转 |
| 界面状态页：空态三成因 | **Content Switcher** | 同一位置换维度 | 主语是「同一个列表区域的三种可能返回值」，对比阅读才是目的 |

Demo 在数据集页、数据集详情页、运行记录页的 Tab/切换控件下方都留了一句**规范说明文字**，把这条例直接写给评审看，避免实现时被随手改成别的控件。

### 5.4 密度三档（真实可实现，不碰后端）

| 档 | `--row` | `--pad` | `--gap` | 字号 |
| --- | --- | --- | --- | --- |
| 紧凑 | 32px | 8px | 8px | 13px |
| 常规（默认） | 40px | 12px | 12px | 14px |
| 宽松 | 48px | 16px | 16px | 15px |

`body[data-density]` + CSS 变量驱动，选择写入 `localStorage` 的 `mis06.density`，刷新后保持。**明确不做**：保存视图、自定义布局、拖拽模块顺序、记住筛选条件到服务端。骨架屏按当前行高占位，所以切换密度时加载态高度同步，不会出现加载完成那一刻的跳动。

## 6. 登录页面

**布局**：左侧价值主张栏（约占 2/3）+ 右侧 420px 表单卡。登录状态下顶栏自动收起一级导航、账号菜单与原型开关（CSS 以 `body[data-view="login"]` 控制），只保留品牌与诚实声明——登录页不该有导航可点。

**视觉重点**：不靠插画靠承诺。左侧大标题是价值主张「把市场数据变成可追溯的决策依据」，下面三条支柱逐条对应真实机制：① 每个数字带角标，点开就是产生它的工具调用（`sections[].cites` → `task_id`）；② 画像先告诉你这份表能回答什么（`/profile` 的语义类型与缺失率）；③ 校验会把不可靠结论降级为「带警告完成」而不是假装成功（`SUCCESS_WITH_WARNINGS`）。脚注直接写 `GET /api/health`，告诉用户登录后第一屏会看到哪里配不通。

**四种登录态（Demo 内分段控件切换，全部真实）**：

| 态 | 触发条件 | 界面行为 |
| --- | --- | --- |
| 标准 | `needs_bootstrap=false` | 账号 + 密码，提交到 `POST /auth/login`，会话写 HttpOnly Cookie `mis_session`（8h） |
| **首次部署** | `GET /api/auth/me` 返回 `needs_bootstrap=true` | 标题改「初始化系统」，多出的字段是真实的 `display_name`（可选，≤64）；提示条写明「库里还没有任何管理员」；提交目标切到 `POST /auth/bootstrap`，成功即签发会话、免二次登录 |
| 401 | 登录失败 / 会话过期 | 统一文案「账号或密码不正确，或登录状态已失效」，界面**不区分**原因（后端也不区分），错误条为 `role=alert` |
| 429 | 触发限流 | 读 `Retry-After` 秒数倒计时禁用提交按钮（Demo 里 45 秒真实倒数），表单内容保留不清空 |

**品牌表达**：登录页是全产品唯一允许出现「讲述」的地方，其余页面一律只讲任务。**已知缺失**：后端没有自助找回密码接口，所以脚注写明「需联系管理员重置」，不放「忘记密码」假链接。密码强度规则不在前端重复定义，由 `POST /api/auth/password` 校验。

## 7. Dashboard / 工作台

用户第一屏看到三块，自上而下按「要不要你动手」排序：

### 7.1 待办（首屏第一块，5 条规则的唯一产物）

待办**不是任务系统**：不能手工新建、不记录谁点了完成、没有截止时间。它是对四个接口字段的纯函数，规则写死在前端，每条都把自己的推导来源以等宽标签显示在条目上。

| # | 优先级 | 推导条件（真实字段） | 标题 | 动作 |
| --- | --- | --- | --- | --- |
| R1 | 阻塞 | `GET /api/health → llm_configured = false` | LLM 尚未配置，报告文字将由规则模板生成 | 看服务状态 |
| R2 | 阻塞 | `GET /api/health → upload_dir_ready = false` | 服务端上传目录当前不可写，无法接收新数据 | 去上传页看说明 |
| R3 | 引导 | `GET /api/datasets → total = 0` | 还没有任何数据集，先上传一份市场数据 | 上传数据集 |
| R4 | 跟进 | `GET /api/workflows/{id} → status ∉ {SUCCESS, SUCCESS_WITH_WARNINGS, FAILED}` | 有一条分析正在执行，可以回去看它跑到哪一步 | 回看运行 |
| R5 | 复核 | `GET /api/workflows/history → items[].status = FAILED 或 SUCCESS_WITH_WARNINGS` | 历史里有需要复核的结果（条数实时由列表算出） | 查看历史归档 |

排序固定为 **阻塞 → 引导 → 跟进 → 复核**。优先级用「文字 + 独立形状（✕ / → / ▸ / !）+ 底色」三重表达。

全部规则未命中时，待办区显示**积极空态**：「当前没有待办」，并逐条说明为什么没有（配置正常 / 已有数据集 / 无进行中分析 / 历史无待复核），最后补一句「这里不会出现手工新建任务——待办只是接口状态的镜像」。

顶栏的「待办 N 项」就是同一个数的镜像，纯文字计数，不用红点、不用铃铛。

### 7.2 最近运行（左栏，占 2fr）

列表列：提问摘要 / 数据集 / 状态 / 阶段进度 / 整条耗时 / 操作（回看、报告）。

三条硬约束直接写进面板脚注：
1. 数据源是 `GET /api/workflows/history?limit=20&offset=0`，**只有 `limit/offset`**，所以表头**不可点击**、没有搜索框、没有状态筛选下拉，顺序即后端返回顺序（库内 `finished_at DESC NULLS LAST, created_at DESC`）。
2. 阶段进度只有轮询接口 `GET /api/workflows/{id}` 才给 `step_index / total_steps`；**归档记录不含这两个字段，那一格就老实写「归档不含 step_index」，不拿 6/6 去糊**。
3. 耗时只有一列「整条耗时」：终态取 `finished_at − created_at`，未终态显示「已用时 + 仍在计」。

### 7.3 数据集（右栏，占 1fr）

按 `sort=uploaded_at&order=desc&limit=5` 取前几条，每行「文件名 — 行数 × 列数」两值结构，脚注写明可排序字段只有 `uploaded_at / filename / rows`。`total=0` 时这里直接换成「尚无数据」空态并把人引到上传。

## 8. Market Analysis：完整路径

顶部用 **Progress Indicator** 表明这是三步线性流程（不是 Tab）：`01 选择数据集 → 02 描述分析需求 → 03 发起并转入运行`，完成一步变绿、当前一步顶部加 2px 品牌线。

1. **选数据集**：内嵌精简列表（前 5 条，`GET /api/datasets?limit=20&sort=uploaded_at&order=desc`），每行一个「选择」按钮；选中即高亮该并把 `dataset_id` 带入提问区（数据集详情页的「用这个数据集提问」按钮会直接跳到本页并完成第 1 步）。
2. **描述需求**：`textarea` 绑定 `maxlength=500` 并实时显示 `N / 500`；脚注写明后端校验 `question` 为 2–500 字。`max_steps` 用真实范围 `1–8` 的三档下拉，并诚实标注「步数越多耗时越长，但不承诺结论更准」。
3. **发起前检查（右栏）**：把四个前置条件列成 `kv` 行——数据集是否可选、LLM 是否已配置、上传目录是否可写、问题长度要求——全部来自 `health` 与 `datasets` 的真实字段。`total=0` 时提交按钮禁用并给出 `404` 说明。
4. **能问什么（右栏）**：由 `/profile` 的语义类型与缺失率生成「可用 / 受限 / 不可用」三档清单，例如 `gross_rate` 缺失 34.1% → 比率类结论会被降级；`remark` 缺失 71.4% 且为自由文本 → 按它分组不可用。这是本方案里最「省路径」的设计：把画像结论前置到提问框旁边，避免用户跑完 4 分钟才被告知问不了。
5. **发起**：`POST /api/analysis` → **202 Accepted**。界面显示一个 `202` 回执块（`workflow_id` + `status=PENDING`）和「去运行记录看它怎么跑」。**不在这里等结果、不放假进度条。**

错误分支：问题 <2 字时前端拦下并说明后端会以 422 拒绝；`dataset_id` 越权或不存在为 `404`。

## 9. Agent Runs：执行过程的视觉化

**Tab 分类**：`当前运行`（内存态轮询接口）与 `历史归档`（SQLite 接口）是两类内容，用 Tab。

### 9.1 当前运行

- **阶梯 + 数字并列**：`step_index=3 / total_steps=6` 用等宽字体写死在旁边，下面才是 6 格阶梯（已完成=实心、当前=描边、失败=红色、未到=空）。阶梯**不代表时间**，只代表「已完成几个阶段」。
- **阶段进度条（Progress Indicator）**：六项 `数据画像 / 任务规划 / 工具执行 / 图表生成 / 报告撰写 / 结果校验`，每项同时显示中文阶段名与原始枚举（`PROFILING…VALIDATING`），当前项附带真实 `step` 小写值（如 `execution`）。`FAILED` 时当前阶段变红并保留，其余保持已完成态。
- **时间**：只有「整条任务已用时 `mm:ss`」（`created_at` → 现在）与终态后的总耗时。**没有任何阶段耗时、没有阶段时间戳、没有甘特图、没有按时间推算的百分比**——`WorkflowState` 只有 `created_at/started_at/finished_at/heartbeat_at`，轮询接口只暴露 `created_at/finished_at`，任何「PROFILING 3.2s」都是造假。
- **轮询语义**：状态条文案「每 1000ms 轮询一次，进入终态即停止」；进入终态后整条提示改为「已进入终态，轮询停止（原始值）」。**没有实时日志流、没有 WebSocket/SSE**。Demo 提供一个明确标注为原型的按钮「模拟下一次轮询返回」，把响应手动翻一格，用来演示 120–200ms 的推进动效。
- **任务简报表**：`task_id / description / status / error` 四列，正是接口 `tasks[]` 给的全部字段（不含 `params`，接口也不返回）。**`SKIPPED` 的任务显式保留在列表里**，脚注解释为什么：用户需要知道哪一环没跑，静默删除会让报告结论的证据链看起来比实际完整。
- **已产出图表**：`charts[]` 缩略图网格，标注 `chart_type`（bar/line/pie/scatter 四种）与真实文件名形态 `{12 位 hex}.png`；生产环境是 PNG 二进制，示意图用内联 SVG 代替并注明。`charts=[]` 时显示「还没有图表产出，等 CHARTING 阶段跑完才会有」。

### 9.2 历史归档

列为提问 / 状态（含 `error_code` 标签，如 `WORKFLOW_TIMEOUT`）/ `llm_used` / 发起时间 / 整条耗时 / 操作。分页只有 `limit(1–100, 默认 20)` 与 `offset`，脚注直说「没有排序参数、没有状态筛选、没有关键词，所以这里不放搜索框和排序表头」。

`enabled=false`（部署未配归档库）被实现成一个**独立空态**：「历史归档当前处于关闭状态 · 请求是成功的，所以这不是错误态」——把 200 + 空数组与 5xx 分开的正是这种区分。

## 10. Reports：呈现与可追溯

Tab 三类内容：正文 / 数据质量与校验 / 来源与引用。

- **头部**：报告标题、**数据截至**（来自 `generated_at`，明确写 UTC）、生成时间、数据集、终态标签。
- **`llm_used=false` 横幅**：用警告样式写明「本次报告由规则引擎生成，数字仍来自真实工具结果，但文字解释是模板拼接的，可信度低于模型撰写版本」。这是本产品最重要的诚实装置之一。
- **正文**：`summary` + 三节 `sections[].heading/text`。每个数字后面挂**角标按钮** `T1/T2/T3`（即 `sections[].cites`），点击自动切到「来源与引用」Tab、定位到对应条目并短暂高亮。角标是真正的 `<button>`，键盘可达、有 `aria-label="查看来源 T1"`。
- **表格**：`sections[].table` 原样渲染（工具结果前 20 行），脚注写明「前端不做二次计算」，这是「每个数字可追溯到具体工具调用」的落地形态。
- **图**：内联 SVG 柱状图 + 图例 + `图注（chart_type=bar，来源 T2）`。
- **反向可追溯**：「来源与引用」页每条以 `task_id` 开头，附产生它的工具名与输出口径（如 `pivot_cross_tab`、有效样本 121,208 行），点角标即可从结论跳到这里。
- **校验**：`validation.issues[]` 按 `severity`（`error / warning / info`）三重编码；出现 `error` 时终态是 `SUCCESS_WITH_WARNINGS` 或 `FAILED`，界面不会把它画成「成功」。`data_quality_notes[]` 单独一栏，标明直接抄自画像 `warnings`、不由模型编造。

**已知限制**：没有导出、没有分享链接、没有下载——接口只有 `GET /api/workflows/{id}/report`。

## 11. 动效（每条都对应业务价值，写不出价值就不做）

| 动效 | 参数 | 业务价值 |
| --- | --- | --- |
| 阶段推进时当前格与当前阶段行的填充/描边过渡 | 140ms ease-out，仅透明度与 3px 内位移 | 让「等待中 → 运行中 → 已完成」的状态变化被看见，用户不必逐字读枚举就知道往前走了一步 |
| 轮询中标签的呼吸点 | 1.6s 循环，只改透明度 1↔0.35 | 表达「进程还活着」。轮询本身**不做闪烁**，因为每秒一次的响应不应该每秒抢一次注意力 |
| 骨架屏脉冲 | 1.4s 循环，透明度 1↔0.45 | 表示请求在途；高度 = 真实行高，避免数据到达时的版面跳动（跳动会让人以为读错了数据） |
| 角标 → 来源条目的滚动 + 1.2s 高亮 | 平滑滚动 + 底色过渡 | 把「这个数字从哪来」变成一次可完成的动作，是核心差异点的操作化 |
| 切视图时 140ms 上浮 | `rise` | 只用于确认「换页了」，因为本方案没有侧栏高亮以外的导航线索 |
| 429 提交按钮倒数 | 文案每秒更新，无动画 | 让用户看见限制何时解除，而不是反复点击失败 |

`prefers-reduced-motion: reduce` 下全部动画关闭。所有动效都不是装饰性缩放。

## 12. 优点

1. **路径真的最短**：发起分析 3 击、回看运行 2 击、读历史报告 3 击；高频动作（发起分析）还额外在顶栏常驻。
2. **待办可被逐条对账**：5 条规则、4 个接口字段、每条自带推导来源标签，没有任何人造任务；空态也解释「为什么没有待办」。
3. **信息密度适中且可调**：三档行高覆盖 32/40/48，纯前端、可持久化，不需要后端支持就能落地。
4. **可访问性扎实**：三级正文灰全部 ≥4.5:1（最坏背景实测 5.05:1）、焦点环改为实心品牌色、状态色形字三重编码、表格 `th scope` 齐全、768px 下表格转标签—值堆叠且整页无横向滚动。
5. **对接口能力的忠诚度高**：连「归档不含 step_index」「接口只有 limit/offset 所以不给排序表头」这种细节都写进了界面脚注，评审无需查代码即可判断方案有没有越界。
6. **实现成本最低的一档**：结构就是「导航 + 面板 + 表格」，与现有 `app/web` 的渲染方式同构，几乎不需要新引入组件范式。

## 13. 缺点（真缺点）

1. **首屏天花板低，不「惊艳」**。评审第一轮看到的就是待办列表 + 两张表格，缺乏 01 的态势带、08 的结论卡那种「一眼看懂产品价值」的瞬间。它必须靠讲解才能被 appreciation，对高层汇报和对外展示是实打实的减分项。
2. **待办只有 5 条规则，容易显得空**。系统健康时首屏很可能只剩「没有待办」+ 两张列表，工作台的存在感被削弱；而规则是写死的，不会因为业务演化自动出现新待办，**要扩规则就得改前端代码**——这不是配置能解决的事，长期会被业务方投诉「工作台不懂我的活」。
3. **顶部一级导航的容量上限是硬伤**。5 个入口已接近极限；一旦后端补齐修改密码页、会话列表（两者接口已存在但前端未做）或新增能力，导航要么挤爆要么被迫做二级下拉，而下拉在 768px 档的可点性明显变差。相比之下 01/07/09 的侧栏天然能长。
4. **列表 + 进度作为主角，牺牲了数据的图形表达**。本方案几乎没有「一眼看出趋势」的图表位（图只在运行/报告页里以缩略图出现）。对以对比和趋势为主要消费方式的分析师，效率低于 07 的图表墙；同一个问题在这里需要多几次点击。
5. **Tab 与分段控件的区分靠约定维持**。评审与后续实现者极易把「概览/字段画像」顺手做成 Tab、或把「当前运行/历史归档」做成切换器。本 Demo 用页内说明文字自我约束，但**约定不会进组件库**，落地后仍有被抹平的风险，需要组件层的用法注释与评审卡口。
6. **密度偏好只存 `localStorage`，换设备/换浏览器会丢**。因为后端没有用户偏好接口，这不是可以修的技术债而是能力缺失；跨设备一致体验在方案层面就承诺不了，必须写进预期管理。
7. **768px 下长表格的可扫读性下降**。标签—值堆叠解决了「不破版」，但同一行的字段被竖排拆开，列间横向对比不再可能；表格型任务在平板档实际上是降级使用。

## 14. 适合的企业类型

- **中型消费/零售/制造企业的内部分析平台**（50–2000 人），用户是天天要跑一批分析的渠道、经营、品类分析师，讲究每天进来十分钟办完事。
- **咨询/研究团队的交付工具**：一份数据反复跑多个问题，最需要「最近运行 + 待复核」的值班台式组织。
- **已有 BI 但缺 Agent 型工作台的部门**：顶部导航 + 页内 Tab 是这类用户最熟悉的形状，培训成本几乎为零。
- **不适合**：面向高管一次性汇报的场景（选 08）、以看板探索为主的分析师团队（选 07）、把分析当对话来做的小团队（选 02）、需要 7×24 盯运行队列的运维组织（选 09）。

## 15. 推荐指数

**★★★★☆（4/5）**

理由：它是十套方案里**落地成本最低、日常效率最高**的一套，接口贴合度接近零改造，可访问性与信息密度都站得住；扣分全在「不好看、不耐看」——它不靠首屏说服人，只靠两周后被持续使用说服人。

**什么情况下应该选它而不是它**：
- 要给董事会/客户做单次演示、追求首屏说服力 → 选 **08**（先给答案）。
- 用户主要工作是翻图表、改筛选、找异常 → 选 **07**（筛选器 + 图表墙）。
- 组织单位是「一次分析会话」、要能接着上次问 → 选 **02**（会话列表 + 运行轨道）。
- 决策者要看业务态势而非待办清单 → 选 **01**（侧栏 + 命令条 + 态势带）。
- 平台可信度要靠「看见它怎么跑」支撑、需要盯队列 → 选 **09**。

## 附：与现有代码的落地影响

**结论：纯表现层改造，不需要动后端一行。** 本方案用到的每一个字段都已在现有 9 个接口里返回（`/api/health`、`/api/auth/me`、`/auth/login|logout|bootstrap`、`/api/auth/password`、`/api/datasets`(+`/{id}`、`/profile`、`/upload`)、`/api/analysis`、`/api/workflows/{id}`、`/report`、`/charts/{filename}`、`/api/workflows/history`(+`/{id}`)）。

| 文件 | 要改什么 | 工作量与风险 |
| --- | --- | --- |
| `app/web/tokens.css` | 替换变量：正文灰收敛为三级（新增 `--ink-3:#5B6878`，把 `--ink-4` 降级为「仅非正文」）、补 `--surface-2/-3`、`--st-*` 五档状态色板与 `--c1..--c5` 图表色板分离、新增 `--row/--pad/--gap/--fs-body` 密度变量与 `body[data-density=…]` 三组取值 | 小。变量重命名会影响既有类，需全站 grep 校验；无后端耦合 |
| `app/web/app.css` | 新增：56px 顶栏 + 一级导航（`aria-current` 下划线）、32px 状态条、`.panel/.panel-head/.panel-foot`、`.tabs`、`.switcher`、`.stepper`（Progress Indicator）、`.ladder/.rail`（阶段轨道）、`.chip` 色形字三重编码、`.todo*`、`.skel`、`.errbox`、`td::before{content:attr(data-label)}` 的 768px 堆叠规则；删除与侧栏相关的旧布局 | 中。是四份文件里改动量最大的一份，但都是新增结构，旧样式可整块替换 |
| `app/web/index.html` | 结构重排：侧栏（若有）→ `header.topbar`（导航 + 状态条 + 账号菜单）；`main` 内改为 8 个 `[data-panel]` 分区视图；数据集页与运行页加 `role=tablist` 工具；数据集详情加 Content Switcher；市场分析加 Progress Indicator；所有表格补 `th scope` 与窄屏 `data-label` | 中。纯 DOM 结构调整，事件委托不变 |
| `app/web/app.js` | 需要新增/改写的渲染函数：`setView`（hash 路由，替代现有单页显隐）、`renderStrip`（health 字段行 + 版本）、**`computeTodos`/`renderTodos`（新增，5 条规则的纯函数，输入来自 `getHealth`、`getDatasets`、`pollWorkflow`、`getHistory`）**、`renderDashboardRuns`（最近运行表，含「归档不含 step_index」分支）、`renderDatasetMini`、`renderDatasets`（把 `q/sort/order/limit/offset` 真正拼进请求，并按 200-空数组 / 筛选无结果 / 非 200 三种成因出不同空态）、`renderWorkflowStatus`（阶梯 + 阶段指示器，仅用 `step_index/total_steps` 与整条耗时）、`renderTasks`（保留 `SKIPPED`）、`renderCharts`、`renderHistory`（不给排序/筛选入口）、`renderReport`（`cites` 角标 → 来源条目定位与高亮、`llm_used=false` 横幅）、`setDensity`（读写 `localStorage`，不进请求）、Tab/switcher 的 `aria-selected/aria-pressed` 同步与左右键漫游、429 的 `Retry-After` 倒数 | 中偏大。轮询节奏保持现状 1000ms 与终态停止，**不改协议** |
| 前端缺口（可选补做，**后端已就绪**） | ① 修改密码：账号菜单里调 `POST /api/auth/password`；② 多设备会话列表：`GET /api/auth/sessions`（只有元信息，无 token） | 各约 30–60 行，不触碰接口 |

**后端**：不需要新增或修改任何接口。明确**不实现**「保存视图 / 自定义布局」——那会要求给 `users` 表加偏好字段并新增读写接口，属于为一个低价值功能扩大契约，反对。
**风险点**：① 灰阶从四级压成三级需全站 grep 旧变量，漏改会让说明文字对比度不足；② 密度变量若被其他组件硬编码行高抵消，三档会失真，需以 `--row` 为唯一行高来源；③ 顶栏 5 个入口的容量上限，未来加页面要先决定是并进现有页还是做下拉；④ `data-label` 需在每一处动态生成的单元格里带上，否则窄屏堆叠会丢标签。
