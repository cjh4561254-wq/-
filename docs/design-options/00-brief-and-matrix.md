# 10 套方案的唯一事实来源：共享约束 + 差异矩阵

> 本文件是 `docs/design-options/option-01..10.md` 与 `design-options/option-01..10/index.html` 的**唯一上游依据**。
> 任何方案作者（含子智能体）**不得偏离本文件第 3 节分配给自己那套方案的坐标**。改了坐标，10 套方案就会塌回"同一套换配色"。

---

## 1. 产品是什么（不可改写的事实）

**AI Market Intelligence Studio / 市场情报与智能分析平台**：用户上传市场数据（CSV/Excel），用自然语言提问，后端多智能体流水线（画像 → 规划 → 执行 → 图表 → 报告 → 校验）产出一份**每个数字都能追溯到具体工具调用**的分析报告。

一句话价值主张（中文，可在各方案里换措辞，但意思不变）：
> 把市场数据变成可追溯的决策依据。

目标用户：企业的市场分析师、经营分析负责人、咨询/研究人员。不是开发者调试工具，不是通用聊天机器人。

## 2. 后端真实能力边界（硬约束：UI 不许画不存在的功能）

### 2.1 已经存在、可以放入口的能力

| 能力 | 接口 | 备注 |
| --- | --- | --- |
| 登录 / 退出 / 首次建管理员 | `POST /auth/login`、`POST /auth/logout`、`POST /auth/bootstrap`、`GET /api/auth/me` | HttpOnly session cookie `mis_session`；会话默认 8h；失败统一文案；限流返回 429 + `Retry-After` |
| 修改密码 | `POST /api/auth/password` | **后端有、前端还没做**，方案里可以设计它 |
| 会话列表（多设备） | `GET /api/auth/sessions` | **后端有、前端还没做**，只返回元信息不含 token |
| 数据集列表 | `GET /api/datasets` | `limit`(1–200，默认 50)、`offset`、`sort`∈{uploaded_at,filename,rows}、`order`、`q`(文件名子串，≤200) |
| 数据集详情 / 画像 | `GET /api/datasets/{id}`、`GET /api/datasets/{id}/profile` | 画像含列数、行数、语义类型、缺失率、唯一值、分位数、top_values、重复行、告警 |
| 上传数据集 | `POST /api/datasets/upload`（multipart `file`） | 返回完整 Dataset |
| 发起分析 | `POST /api/analysis` → **202** | 入参 `dataset_id`、`question`(2–500 字)、`max_steps`(1–8) |
| 轮询运行状态 | `GET /api/workflows/{id}` | 返回状态、`step_index`/`total_steps`、任务简报（`task_id/description/status/error`），**不含报告与结果** |
| 取报告 | `GET /api/workflows/{id}/report` | 含 `title/summary/sections(heading,text,cites[table])/data_quality_notes/citations/generated_at/llm_used` + 校验结果 |
| 取图表 | `GET /api/workflows/{id}/charts/{filename}` | **PNG 二进制**，4 种图型：bar / line / pie / scatter |
| 历史列表 | `GET /api/workflows/history` | **只有 `limit`(1–100，默认 20) + `offset`**，无排序、无状态筛选、无关键词搜索 |
| 历史详情 | `GET /api/workflows/history/{id}` | `{item, report|null}` |
| 服务健康 | `GET /api/health` | `status/app_name/version/uptime_seconds/llm_configured/upload_dir_ready` |

工作流状态枚举（10 个，必须原样映射成中文，不得漏项）：
`PENDING / PROFILING / PLANNING / EXECUTING / CHARTING / REPORTING / VALIDATING / SUCCESS / SUCCESS_WITH_WARNINGS / FAILED`
任务状态枚举（6 个）：含 `SKIPPED`。校验问题 severity：`error / warning / info`。

### 2.2 后端**不存在**、因此所有方案一律禁止出现的东西

违反任何一条，方案直接作废：

1. **报告导出**（无 PDF/CSV/JSON 接口）→ 不许有"导出""下载报告""分享链接"按钮。
2. **数据集删除 / 重命名 / 覆盖**（只有 upload / get / profile / list）→ 不许有删除按钮。
3. **阶段级耗时、阶段时间戳、甘特图、进度百分比（按时间）**：`WorkflowState` 只有 `created_at / started_at / finished_at / heartbeat_at`，轮询接口只暴露 `created_at / finished_at`。→ 只能用 `step_index / total_steps`（**已完成阶段数**）画阶梯，或整条任务的真实总耗时。任何"PROFILING 3.2s"都是造假。
4. **实时推送 / WebSocket / SSE** → 前端是 **1000ms 轮询**。不许画"实时日志流""秒级推送"。
5. **全局搜索 / 通知中心 / 消息提醒** → 不许放搜索放大镜（全局）、铃铛、头像红点。数据集搜索框是**真实存在**的（`q` 参数），可以放。
6. **保存视图 / 团队协作 / 共享链接 / 权限管理 / 评论** → 全部没有后端，不许出现。
7. **用量、成本、Token 消耗、模型选择器** → 后端不暴露，不许出现。
8. **假按钮**：任何不可达的入口一律删掉。宁可少一个入口，不可多一个假入口。

### 2.3 关于"数据"的诚实要求（贯穿所有 Demo）

- 这些 HTML 是**静态视觉原型**，必然使用占位数值。要求：**每个 Demo 首屏左上角或顶栏固定一条不遮挡内容的声明**：
  `视觉方案示意 · 数据为占位样例 · 未接入后端`
  声明本身要遵守该方案的设计语言（不是贴一张红纸），字号小、对比度达标。
- 报告/数字区域必须保留真实的**可追溯结构**（`cites: T1/T2` 角标 + 来源行 + "数据截至"），这是本产品的核心差异点，10 套方案**都必须体现**，只是体现方式不同。
- 空态、错误态、加载态三态必须在**至少一套页面**里被展示出来（可用原型内的视图切换看到）。空态要区分"还没有数据 / 筛选无结果 / 读取失败"三种成因。

**校验规则（作者必须自检）**：把 10 套方案的「导航结构」列出来必须 10 个不同；「首屏主角」必须 10 个不同；「数据主角」至少 6 种。如果你的方案在 03/05/08/10 里只是换了行宽和配色，你写错了，重写。

### 3.1 近似方案之间的强制区分（防止内部塌陷）

- **01 vs 09**：01 面向业务决策者（看结论与态势），09 面向平台运维者（看队列与状态）。01 的表是业务数据，09 的表是任务数据。
- **02 vs 06**：02 的组织单位是"一次分析会话"（左侧是会话列表，进来就能接着问），06 的组织单位是"功能页"（左侧没有会话列表）。
- **03 vs 08 vs 10**：03 是**过程+证据**（章节、脚注、方法说明，像咨询报告）；08 是**取舍+行动**（结论卡、方案对比、行动项，像董事会一页纸）；10 是**出版节奏**（封面、目录、期号、图文混排，像杂志）。三者的 DOM 结构必须明显不同：03 = 长文档 `article`；08 = 卡片栈 + 锚点；10 = 封面 grid + 目录 + 跨栏图文。
- **04 vs 07**：04 暗色、键盘驱动、多窗格、以表格为主，强调"快读"；07 亮色、鼠标驱动、筛选器作用域、以图表为主，强调"探索"。
- **05 vs 10**：05 减到只剩排版（无编号系统、无装饰、一屏一件事）；10 加的是编辑系统（编号、目录、跨栏、说明行）。

## 4. 视觉与代码纪律（对所有方案一致）

1. **单文件 HTML**：内联 `<style>` 与 `<script>`，**零外部依赖**（无 CDN、无外链字体、无图标库、无图表库）。图表用内联 `svg` 或 CSS 绘制。图标用内联 SVG path 或纯字符。
2. **字体**：本机实测只有微软雅黑、黑体、等线、宋体。**没有思源宋体/Noto Serif CJK**，禁止依赖衬线中文；禁止 `@font-face` 外链。统一栈：
   `-apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif`，等宽用 `ui-monospace, "Cascadia Mono", Consolas, monospace`。字族最多两族。
3. **禁止（提示词第十五节 + 实测证据）**：大面积紫蓝渐变、发光边框（`box-shadow` 做霓虹）、玻璃拟态（`backdrop-filter`）、星星/粒子背景、巨大 AI 图标、无意义装饰、`text-shadow`、圆角 >10px 的通用化使用、"所有东西都是卡片"。
4. **中文必须自然**：`欢迎回来` 不是 `Welcome to your workspace`；`暂无数据集` + `上传数据集，开始第一次分析` 不是 `No datasets found`。技术名保留：AI / Agent / RAG / API / CSV / Excel / JSON / SQLite / DeepSeek / PNG。状态枚举必须中文映射（`运行中` / `已完成` / `失败` / `等待中` / `带警告完成`），但**同时保留原始枚举值的可查证性**（如 tooltip 或次要文字），因为这是后端真实值。
5. **注释纪律（提示词第四节）**：CSS/JS 里只写"为什么"的注释。**每个 Demo 的 `<style>` 顶部允许且仅允许一段 ≤12 行的"设计底座"说明注释**，解释这套方案的设计立场与它和第 3 节坐标的对应关系；其余位置不写复述型注释（禁止 `/* 设置按钮颜色 */`、`// 获取数据`）。
6. **可访问性底线**：正文对比度 ≥ 4.5:1，大字 ≥ 3:1；焦点可见（不许 `outline:none` 无替代）；纯图标按钮有 `aria-label`；表格用 `<table><th scope="col">`；状态不只靠颜色（色 + 形 + 字）。
7. **动效必须有业务理由**：状态变化（等待中→运行中→已完成）用 120–200ms 的位移/透明度提示进度推进；轮询刷新不做闪烁动画；hover 只做可达性提示，不做装饰性缩放。每套方案在文档里必须写出**每条动效对应的业务价值**，写不出就删掉该动效。
8. **原型内交互范围**：允许点击切换视图（登录 / 工作台 / 市场分析 / Agent 运行 / 报告 / 空态 / 错误态），用 hash 或 `data-view` 实现。**不许出现需要后端才生效的入口**（见 2.2）。
9. **响应式**：至少保证 1440px 与 768px 两档不破版；窄屏下表格转"标签—值"堆叠，不许横向滚动整页。

## 5. 每套方案的文档必须包含的 15 节（提示词第八节原文要求）

`docs/design-options/option-NN.md`，标题格式 `方案 NN：<名称>`，15 节依次为：

1. 设计名称
2. 核心设计理念（≥120 字，要能回答"这套方案在表达什么"）
3. 视觉关键词（4–7 个）
4. 色彩体系（主色 / 辅助色 / 背景色 / 状态色 / 图表色，全部给 hex 与用途；图表色与状态色**不得互用**）
5. 页面布局（导航在哪、栅格、断点；必须与第 3 节坐标一致）
6. 登录页面（布局、视觉重点、品牌表达；必须覆盖首次部署 `needs_bootstrap` 模式）
7. Dashboard / 工作台（用户第一屏看到什么，信息如何组织）
8. Market Analysis（选数据集 → 输入需求 → 发起 → 看 Agent 状态 → 看结果，完整路径）
9. Agent Runs（执行过程如何视觉化；受 2.2-3 约束，不得出现阶段耗时）
10. Reports（报告呈现方式；必须体现 `cites` 可追溯）
11. 动效（逐条：动效 → 业务价值）
12. 优点
13. 缺点（**必须写真缺点**，不许写"暂无"；至少 3 条，含实现成本与信息风险）
14. 适合的企业类型
15. 推荐指数（★ 1–5 + 一句理由，并说明"什么情况下应该选它而不是它"）

另外文档末尾加一节 `附：与现有代码的落地影响`，说明这套方案落地时需要改哪些表现层文件（`app/web/tokens.css`、`app.css`、`index.html`、`app.js` 的哪些渲染函数），**是否需要动后端**（理想答案是不需要；若需要，必须指出具体接口和理由，并说明不破坏现有能力）。
