# 方案 05：极简高端数据产品

> 依据 `docs/design-options/00-brief-and-matrix.md` 第 3 节坐标：顶部 5 项极窄导航、无侧栏、无面包屑；首屏主角 = 一个巨大的核心数字 + 一句结论；密度极低；数据主角 = 单个指标 / 单张图；亮色。
> 设计立场：**层级只能靠排版建立，不能靠容器。**
> 配套 Demo：`design-options/option-05/index.html`（单文件、零外部依赖、内联 SVG）。

---

## 1. 设计名称

**极简高端数据产品（Quiet Data）**

一套"零容器"的亮色排版系统：整站没有任何卡片、阴影、玻璃、渐变、圆角堆砌；界面由 5 项顶导航、一条全宽文档流和大量有纪律的留白组成；每一屏只把一个东西做到最响——通常是一个数字。

---

## 2. 核心设计理念

这套方案在表达的只有一句话：**决策者买的是结论，不是界面。**

一个经营负责人打开系统，他要的不是"看见平台有多少能力"，而是"现在那个最关键的数是多少、它说明了什么"。所以首屏被压缩成一个 96px 的数字和一句 18px 的结论，其余一切都被判了刑：列表要到 `数据集` 才看得到，过程要到 `运行` 才看得到，长文要到 `报告` 才看得到。低密度不是内容少，而是**一屏只保留一个决策相关的焦点**。

层级怎么建？只用 Apple HIG 原文承认的四件事：对齐（alignment）、缩进（indentation）、留白（negative space）、分隔线（separator lines），再加上强调的三件事：字号、字重、颜色深浅。除此之外，本方案不引入任何第四种层级信号——不用背景色块、不用边框包裹、不用阴影投影、不用图标大小、不用斜体、不用装饰线。一旦允许"容器"参与层级，团队就会开始用卡片表达分组，最终退化成一个普通后台。

因为色彩被剥夺了层级职能，颜色只剩两处合法性：**数据**（图表）与**状态**（成功/告警/失败）。UI 外壳是纯黑白灰，主操作是墨色实心。品牌识别因此只能来自排版节奏与栅格纪律——这恰好是高端产品唯一的护城河：可复制的配色不值钱，可复现的节奏才值钱。

同时承认本项目实测到的一个 P1 缺陷：**"工作台首屏是结构空洞"是缺陷，不是风格。** 所以本方案的留白必须由"信息取舍纪律"挣得，第 7 节逐块回答"这里为什么没东西"；当焦点数字根本不存在时，首屏会切换成空态而不是留一个空心舞台。

## 4. 色彩体系

全部色值取自实测可达标的中性灰阶（对比度已在文档内注明计算基准），并复用现有 `tokens.css` 的 ink/status 语义，落地时几乎不需要新色。

### 4.1 外壳（无彩色）

| 令牌 | hex | 用途 | 对白底对比度 |
| --- | --- | --- | --- |
| `--ink-900` | `#1c1c1a` | 巨大数字、h1、主按钮底色与描边、当前导航下边线 | 16.6:1 |
| `--ink-700` | `#444440` | 正文、段落、表格单元格 | 9.8:1 |
| `--ink-600` | `#5c5c58` | 次级文字、元信息、溯源行、**任何彩色背景上的小字** | 6.7:1 |
| `--ink-500` | `#73736e` | 仅限**纯白背景**上的顶栏声明与图表轴标签 | 4.77:1 |
| `--paper` | `#ffffff` | 默认画布（全宽 section） | — |
| `--paper-alt` | `#f7f7f6` | 交替 section 背景（唯一背景变化手段，替代卡片） | — |
| `--field` | `#fbfbfa` | 当前行/当前阶段底色（ hover 与"这一步"） | — |

`--ink-500` 在 `#f7f7f6` 上只有 4.44:1，因此定死一条规则：**`#73736e` 只允许出现在纯白背景上**，一旦进入彩色区或浅灰行，必须升到 `#5c5c58`。这条规则写进 CSS 注释，避免落地时被随手挪用。

### 4.2 边框四档（Vercel 纪律：border 只有四档）

| 档 | 值 | 用途 |
| --- | --- | --- |
| hairline | `1px solid #ececea` | 行间微分隔、表格行、报告小节 |
| rule | `1px solid #e0e0dd` | section 分隔、溯源行上边、加载分段线待填充档 |
| field | `1px solid #c9c9c5` | 输入控件静置边框（3.25:1，过 WCAG 1.4.11） |
| emphasis | `2px solid #1c1c1a` | 当前导航项下边线、当前阶段左轨、banner 告警左轨 |

分隔线一律**收在容器内侧**（Vercel 规则②：每条边只画一次，交叉处不会变深）。

### 4.3 圆角两档

`--r-1: 2px`（输入框、文本域、下拉）与 `--r-2: 4px`（按钮与需要被按的东西）。两档的语义差别是"读 vs 按"，不是装饰梯度。全站最大 4px，绝不出现 10px 圆角的通用化使用，也没有胶囊形（现有 `--r-pill` 在本方案无消费方）。

### 4.4 状态色（只服务状态，绝不进图表）

| 语义 | hex | 用法（色 + 形 + 字三重） |
| --- | --- | --- |
| ok | `#1a6b42` | `✓ 已完成` |
| warn | `#7a5300` | `! 带告警完成` |
| err | `#9b2c22` | `× 失败` |
| info / 等待中 | `#2c5590` 仅用于极少数信息徽标；本方案默认 `--ink-600` + `· 等待中` | 中性优先，避免彩色噪音 |

状态永远不只靠颜色：形状（`✓ ! × · ▸ –`）+ 中文文案 + 颜色三者同时出现，原始枚举值（`EXECUTING` / `SUCCESS_WITH_WARNINGS` / `SKIPPED`）以小号等宽字保留在旁边，因为它是后端真值。

### 4.5 图表色（单色相顺序阶梯，绝不与状态色互用）

| 档 | hex | 用途 |
| --- | --- | --- |
| c-1 | `#a9c8cc` | 顺序数据最浅档（时间序列最早期） |
| c-2 | `#7fa8ae` | |
| c-3 | `#5b939a` | |
| c-4 | `#2c6a72` | |
| c-5 | `#14434a` | 当前期 / 被结论引用的那一档，最深 |
| 网格线 | `#e0e0dd` | |
| 轴线 | `#c9c9c5` | |
| 轴标签 | `#73736e` 12px | 只在白底 |

选**深墨青**而不是蓝，是为了与 `--info #2c5590` 与品牌蓝彻底切开：数据色不被用于任何 UI 强调，状态绿/橙/红永不被用于任何图形填充。因为一屏只有一张图，本方案放弃多色相分类板，改用单色相明度阶梯 + **数值标签常显 + 类目直接标注**；这是刻意的取舍，代价写进第 13 节缺点。

### 4.6 字重与禁用

只用 **Regular 400 / Medium 500 / Semibold 600** 三档，**禁用 Light / Thin**：一是 Apple HIG 明确不推荐细字重，二是本机只有微软雅黑/黑体/等线/宋体，没有真 thin，写了会静默回退成 Regular 导致层级失效。雅黑实体只提供 Regular 与 Bold，因此 500 与 600 在中文上大概率解析到同一个物理字面——这正是本方案把层级压在**字号与颜色深浅**上、把字重当次要信号的原因（数字与拉丁字母走 Segoe UI，600 真能拉开）。

### 4.7 字号刻度（9 档，全部有角色名，无裸字号）

| 角色令牌 | px | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- |
| `display` | 96 | 600 | 1.0 | 首屏唯一巨大数字（≤900px 降为 40，落回 `metric` 档） |
| `metric` | 40 | 600 | 1.1 | 巨大数字的单位、结果屏关键数值 |
| `page-title` | 28 | 600 | 1.35 | 每屏唯一 h1 |
| `title` | 20 | 500 | 1.5 | 结果标题、作用域行、问题原文 |
| `lede` | 18 | 400 | 1.7 | 一句结论 |
| `section` | 16 | 500 | 1.5 | 小节标题 |
| `body` | 14 | 400 | 1.7 | 正文、报告段落 |
| `compact` | 13 | 400/500 | 1.5/1.4 | 表格单元格、导航项、按钮、字段名 |
| `metadata` | 12 | 400 | 1.4 | 溯源行、时间戳、顶栏声明、轴标签 |

中文行高统一 1.7（Adobe：中日韩取 1.7×），大字号递减到 1.35。数字一律 `font-variant-numeric: tabular-nums`。

### 4.8 间距刻度（7 档 + 整数倍规则）

`--sp-1 4 / --sp-2 8 / --sp-3 12 / --sp-4 16 / --sp-6 24 / --sp-8 32 / --sp-12 48`（px）。

超出 48 的屏幕级留白**必须是 48 的整数倍**（写为 `calc(var(--sp-12) * 2)` = 96px），不允许出现 13/17/40 这类即兴值。Vercel 原刻度中的 5、10、16 档被有意**不实例化**，把阶梯压到 7 档——档位越少，越不可能写错。

正文测度锁死在 `42em`（≈588px），结论句锁死在 `26em`，输入框锁死在 `32em`：这是 Apple 系统 layout guide"限制文本宽度以保证可读"的直接实现，也是本方案最重要的一根隐形线。

## 5. 页面布局

- **导航**：顶部一条 56px 全宽条，三段式：品牌字标（左，13px/600 + 字距 0.08em）→ **5 项导航**（工作台 / 数据集 / 分析 / 运行 / 报告）→ 右侧一条 12px 声明。**无侧栏、无面包屑、无全局搜索、无铃铛、无头像红点**；右上角动作数为 0（用户与退出走品牌字标旁的文字入口在实现里并入浏览器行为，本 Demo 不画假入口）。
- **当前项表达**：只靠 `2px` 墨色下边线 + 字色升到 `#1c1c1a`。这是"分隔线 + 颜色深浅"两件事，不是标签样式。
- **栅格**：单栏 1080px 内容列居中；页内**只有一根左基线**，所有元素（eyebrow、数字、结论、溯源行、表格首列）都贴这根线对齐，缩进只用于表达从属，最多一级（4px）。
- **全宽 section 交替**：`#ffffff` 与 `#f7f7f6` 交替，是替代卡片的唯一区隔手段（Apple"全宽 section 堆叠"的直接照抄）。
- **断点**：1440（默认）/ 900（顶栏换两行——导航占满第二行、字号一律不低于 12px；`display` 96→40；`field.row-2` 转单列；阶梯行隐去序号与英文档）/ 820（`page-title` 28→20、`metric` 40→28，表格转 `data-label` 的"标签—值"堆叠，禁止整页横向滚动）。窄屏降档只允许落到**已有刻度**上，不新增字号档。结构尺寸另立令牌：`--topbar-h 56 / --content-max 1080 / --measure 42em`。
- **报告与正文**：`42em` 测度锁死，其余屏用 1080 列但不填满——极低密度的实现方式是"列宽固定而内容更少"，不是"列宽变窄"。
- **一屏一个焦点**的 DOM 承诺：每个 `.view` 只有一个可见 `h1`，只有一个"主元素"（巨大数字 / 输入框 / 阶梯 / 图表），其余都降到 `metadata` 或 `compact` 层级。

## 6. 登录页面

**布局**：左对齐两段落 + 一个表单，`42em` 测度，整屏只有一根左基线。**不做居中大标题 + 副标题 + 双按钮的 landing page 套路**——那是营销页语言，不是产品入口。

**品牌表达靠排版而不是装饰**：第一屏最响的元素是价值主张本身——`把市场数据变成可追溯的决策依据。`，用 `metric 40px/600` 排成两行，其中"决策依据。"用 `--ink-500` 压暗，形成一句话内部的强弱；下面才回到 28px 的 `登录`。品牌字标 `AI DATA ANALYST` 用 13px/600 + 0.08em 字距（唯一使用字距的地方）。**logo/字标周围留白 ≥ 其自身高度一倍**（Linear 实测结论）。

**表单**：账号、密码、一个墨色实心按钮；输入框 1px field 边框、2px 圆角、focus 用 2px 墨色 outline + 2px offset。按钮旁一行 12px 元信息写真实实现（`POST /auth/login` · HttpOnly 会话 Cookie）。失败文案统一（不区分账号/密码错误）；429 用同一位置显示 `尝试过于频繁，请在 27 秒后再试`（`Retry-After`）。

**needs_bootstrap（首次部署）模式**：`GET /api/auth/me` 返回 `needs_bootstrap=true` 时整屏换掉：主张句改为 `第一次部署 / 先建一个管理员。`，h1 变为 `创建第一个管理员`，字段变为 账号 / 设置密码 / 确认密码，按钮 `初始化`（`POST /auth/bootstrap`）。关键差异：**页面顶部出现一条 2px 告警左轨的说明行**，写清"账号库为空、此界面在第一个管理员创建后不再出现"——这是本方案唯一允许自己使用背景色的地方（`--field`），因为它承担防错职责。成功后自动回到登录态并明确"公开注册不存在，账号由管理员创建"。

登录页顶栏保留声明行，导航整体退场（`display:none`，而不是留下 5 个灰点不可点）。

## 7. Dashboard / 工作台：首屏与每一处留白的理由

**首屏从上到下只有 5 行**：

1. eyebrow（13px/500 `--ink-600`）：`核心指标 · 华东市场销售额同比增速 · 2026 Q1`
2. 巨大数字：`+18.4` 96px/600，单位 `%` 40px/500 同基线，字距 −0.04em
3. 一句结论（18px/400，26em 测度，缩进 4px）：`增速已连续四个季度为正，本季由经销商渠道贡献三分之二增量。`
4. 溯源行（12px，上边 1px rule，间距 24px）：`依据 T1 T2 · 数据截至 2026-09-30 · 口径 sales_amount 季度聚合不含退款 · 来源数据集 …`
5. 两个文字链接（唯一的"下一步"）：`阅读这份报告` / `换一个指标提问`
6. 页脚一行健康度（12px，96px 之后）：`服务正常 · v1.4.2 · 已运行 6 天 14 小时 · 上传目录就绪 · 模型已配置`（`GET /api/health` 真实字段）

**"这里为什么没东西"——逐块回答（本节是方案成立的前提）**：

| 空掉的区域 | 为什么没东西 |
| --- | --- |
| 巨大数字右侧整片 | 侧向填充会立刻把"焦点"降级成"卡片之一"。数字是唯一 96px 元素，任何并排内容都会与它抢基线。 |
| 结论下方到溯源行之间的 24px + 一条线 | 这 24px 是"读完结论再查证据"的呼吸，不是待填槽位。 |
| 没有 KPI 四宫格 | 05 的立场是"一屏一个数"。四个数并列就把决策推回给用户；要更多指标请走 `分析`，那里有明确产出。 |
| 没有最近运行列表 | 列表是**浏览型**任务，与首屏的**判断型**任务无关；放进 `运行` 目的地。首屏只留一个 `阅读这份报告` 直达最近一次成功结果。 |
| 没有数据集/上传区 | 上传是低频动作（每周期几次），不该占一屏；`数据集` 导航项就是它唯一入口。 |
| 没有图表 | 允许"焦点 = 一个指标" **或** "焦点 = 一张图"，不能同时。首屏选了指标；图在报告里作为结论的注脚。 |
| 底部 96px 以上的大片留白 | 是 `--sp-12 * 2` 的刻度值，用来把页脚健康度隔离为"可信度基线"而非数据。 |

**防空洞机制（正面回应实测 P1 缺陷）**：首屏有内容的前提是**存在一个可信的核心指标**。判定条件写死为：至少有一个 `SUCCESS` / `SUCCESS_WITH_WARNINGS` 的运行且其报告有 summary。因此有三种真实形态——
- 无数据集 → 首屏切换为**空态成因一**（`还没有数据集` + 上传动作），而不是留一个 `--` 占位的空心数字；
- 有数据集但没有任何成功运行 → 首屏显示 `还没有可信结论` + 一句 `在〈数据集名〉上提出第一个问题` + 一个动作（引导进 `分析`）；
- 有结论 → 才出现巨大数字。
文档明确指出：**留白是结论已经给完之后的余量，不是内容还没长出来的坑。** 任何评审者看到的空白都必须能落到上表某一行。

信息如何组织：首屏不"组织"信息，只**给出结论 + 证据 + 下一步**。所有其他组织都发生在 4 个目的地里，每个目的地同样只有一个焦点。

## 8. Market Analysis：选数据集 → 提问 → 发起 → 看状态 → 看结果

完整路径实现为**同一视图内的三级渐进披露**，一步占满一屏：

| 屏 | 内容 | 后端 |
| --- | --- | --- |
| 第 1 屏（输入） | `市场分析` h1；**作用域行**：`作用域：中国市场季度销售_2024-2026 · 12,480 行 · 2026-09-28 更新`，同行给 2 个"换一个"文字链；一个 500 字问题输入（带 2–500 计数）；一个 `步骤上限` 下拉（1–8）；一个墨色按钮 `发起分析` + `Ctrl/⌘+Enter 发起` | `POST /api/analysis`（202） |
| 第 2 屏（一屏状态） | `分析已发起` + 一句当前阶段白话 + 6 段阶梯（3 完成 / 1 当前 / 2 待） + `当前阶段 EXECUTING · 第 3/6 步 · 已用时 00:41` + 轮询说明 + `查看运行详情` | `GET /api/workflows/{id}` 每 1000ms |
| 第 3 屏（一个结果） | 一句标题即结论 + 一个 40px 关键数字 + 一句说明 + 溯源行 + `阅读完整报告` / `再问一个问题` | `GET /api/workflows/{id}/report` |

**为什么"选数据集"不单独占一屏**：它是提问的**修饰语**而不是独立决策，所以压成作用域行；同时前端记住上次使用的数据集（纯本地，不需要后端），第二次进来的常见路径只有"输入 → 发起"两个动作。这是本方案对"一屏一件事让流程变长"的唯一解法：**减少屏幕数量做不到，就减少每屏需要判断的量**。

**没有取消按钮**：后端不存在取消接口，宁少一个入口也不画假按钮。第 2 屏因此诚实写明：任务会继续跑到 `max_steps` 上限。

## 9. Agent Runs：执行过程的视觉化

- 一条 h1 `运行`，下面先给**问题原文**（20px/500），因为运行本身不是主语，问题才是。
- 状态行：`运行中 ▸`（色+形+字）+ 原始枚举 `EXECUTING`（12px 等宽）+ `第 3 / 6 步` + 整条任务真实耗时 `00:41`（`started_at` → 当前）。
- **6 级阶梯**（`数据理解/生成计划/执行计算/生成图表/撰写报告/校验` → `PROFILING/PLANNING/EXECUTING/CHARTING/REPORTING/VALIDATING`）：每行 4 列（序号 8px 等宽 / 中文阶段名 / 英文枚举 / 状态）。当前行用 **2px 墨色左轨 + `--field` 底 + 600 字重**；已完成行正常；等待行压暗到 `--ink-600`。**没有阶段耗时、没有时间戳、没有甘特、没有按时间的百分比**——后端只有 `step_index/total_steps`，所以顶部 6 段方块只数"已完成阶段数"。
- **任务简报表**：5 行 T1–T5，含 `已跳过 SKIPPED` 与 `带告警完成 SUCCESS_WITH_WARNINGS`，用 `–`/`!` 形状区分。
- **历史运行**：只有 `limit/offset`，因此不提供排序与筛选，明确写出"后端无排序"；条目**不编号**（无 R-xxxx 期号），用问题文本作主语。
- 轮询说明常驻：`每 1000ms 轮询，不是实时推送`——把技术限制写成一屏可见的事实，是这套极简语言里少见的"解释性文字"，因为它换来的是用户对系统诚实度的信任。

## 10. Reports：呈现与可追溯

- 单栏 `42em` 文档流（`article` + `h1/h2` + `p` + `figure`），**无卡片、无侧边目录、无锚点条、无小节编号 01/02/03**。小节之间只有一条 hairline + 48px 留白。
- 顶部三行元数据：`生成于` / `数据截至 2026-09-30` / `数据集行数与列数 + 缺失率 + 模型已参与生成`——这三行是报告可信度的入口，位置永远在 h1 之后、正文之前。
- **cites 结构（核心差异点）**：正文每个论断后跟等宽角标 `T1`（`sup > a`，12px，下边 1px field 线），文末 `依据` 小节以两列（4em ID + 说明）列出 T1–T5，每条写工具调用名、输出行数、基期与插补情况。角标即锚点，但**不做固定导航条**。
- 一屏最多一张图（本 Demo 一张内联 SVG 柱图，5 档墨青阶梯、当前期最深、数值常显、网格线 `#e0e0dd`、轴标签 12px），`figcaption` 写数据来源与口径。生产中这里是 `GET /api/workflows/{id}/charts/{filename}` 的 PNG，容器与标注规则完全一致（图片不套卡、不加阴影、宽度锁 42em）。
- 校验与数据质量：`告警 1 项 / 错误 0 项 / 提示 2 项` 用色+形+字，`severity` 保留 `error/warning/info` 原值；`data_quality_notes` 写成正文段落而不是徽标墙。
- 结尾状态：`带告警完成 SUCCESS_WITH_WARNINGS` + 接口路径，让读者知道报告从哪来。

## 11. 动效（逐条：动效 → 业务价值；写不出价值的一律不做）

| 动效 | 参数 | 业务价值 |
| --- | --- | --- |
| 渐进披露换屏 | 整屏 `opacity 0→1` + `translateX 8px`，160ms `cubic-bezier(.2,.6,.3,1)` | 没有面包屑，方向感必须由位移承担：向右进入下一步是唯一"我在往下走"的线索。 |
| 阶段推进（当前行换行） | 新当前行 `translateY 2px→0` + 透明度，160ms，仅一次 | 告诉用户流水线在动，节奏与 1000ms 轮询对齐；**不做闪烁**，避免把轮询伪装成推送。 |
| 数字就位 | 结果数字 `opacity 0→1` + 2px 位移，200ms，仅一次 | 区分"这是刚算出来的"与"这是缓存屏"，是结论可信度的一部分。 |
| 加载分段线 | 6 段逐段填充，每段 200ms，一次填充不循环 | 证明请求还活着；分段而非连续，明确它**不是百分比**（后端无百分比）。 |
| hover | 链接下划线 1px→2px；行背景 `--field` | 只做可达性提示，不做缩放、不做阴影抬升。 |
| 焦点 | 2px 墨色 outline + 2px offset | 键盘可达；本方案无自定义焦点动画。 |
| `prefers-reduced-motion: reduce` | 全部关闭 | 位移是本方案的层级手段之一，但可被用户合法取消。 |

**没有的动效**：数字滚动计数、粒子、发光、视差、卡片浮起、骨架屏闪烁。Apple 那句话是本节的总闸：**"Don't mistake delight for decoration."**

## 12. 优点

1. **层级最干净、最抗腐化**：只承认"字号 × 字重 × 颜色深浅 + 对齐/缩进/留白/分隔线"，任何人想加卡片都必须先证明排版做不到——这是一道真正的架构门禁。
2. **首屏决策成本最低**：一个数字 + 一句结论 + 一条溯源，10 套方案里唯一能让非分析角色"读完就走"的方案。
3. **品牌识别来自节奏而非色彩**：96px 单焦点 + 42em 测度 + 48 倍数留白，任何人一眼能认出是这套产品；换主题色也换不走它的长相。
4. **可追溯被推到最强**：数字与溯源行强制同屏、间距 ≤24px，"每个数字可追溯"从后端能力变成视觉契约。
5. **落地改动最小**：墨色主操作 + 中性灰外壳 + 现有状态色，`tokens.css` 的 ink/status 几乎原样可用；新增 9 个字号角色 + 7 档间距；无阴影无渐变意味着可以整体删掉 `--sh-1/2/3` 的消费方。
6. **实现成本可预测**：无第三方库、无图标体系（状态用字符 `✓ ! × · ▸ –`）、组件数量极少（行、表、输入、阶梯、角标）。
7. **暗色几乎免费**：反转 5 个中性阶 + 保留墨青图表档即可得到可信的暗色变体（本方案定为亮色，但纪律允许双主题）。

## 13. 缺点（真缺点）

1. **多步任务的路径成本显著变长**。渐进披露把"选数据集 → 提问 → 发起 → 看状态 → 看结果"拆成 2–3 屏，老用户完成一次标准分析比 06/04 多 1–2 次点击与约 2 秒心智切换；分析频率高的团队会感到阻力。补救只有两条：记住上次数据集（把第一屏压成一行）+ `Ctrl/⌘+Enter` 直接发起，二者都是前端补丁，不能消除结构性摩擦。
2. **极低密度 = 一屏信息容量小，横向比较做不到**。不能同屏看两个指标、不能把 5 张图并排扫读。想看全貌必须连续翻页，对"要看一眼全部渠道"的用户（07、04 的目标用户）是硬伤；这不是可优化项，是这套语言的天花板。
3. **留白极易被误解成"内容不足"，落地纪律成本高**。一旦首屏取不到可信核心指标（新租户、失败运行、画像缺关键字段），这套 UI 会立刻看起来像空壳——正是本项目实测 P1 缺陷的形状。要维持成立，必须为每个焦点数字定义"取不到时显示什么"的降级设计（本方案给了三态规则），否则设计师与前端会开始偷偷加卡片，方案在两个月内塌陷。
4. **单色相阶梯对名义类目的可辨识度弱**。饼图或多类目条形图超过 4 个类目时，明度阶梯会被读成"顺序/大小"暗示，且相邻两档在投影仪/低质屏幕上会糊。真实数据类目常常 6–12 个，届时要么破坏配色纪律，要么降级为"只画前 3 + 其他"。
5. **中文没有真 Semibold**。雅黑只有 Regular/Bold，600 与 500 在中文上落到同一物理字面，层级被压在字号上；字号档一少，小标题与正文的区分在 13–16px 区间会变得吃不住，中文密集的报告页可能被迫额外加档（等于侵蚀刻度）。
6. **无面包屑 + 无侧栏使"我在哪"的可感知性下降**。1080 单栏 + 5 项导航下，深度页（报告 → 某次运行 → 某数据集）容易让人失去位置，只能靠 h1 文案与渐进披露位移补偿；对不常来的用户不友好。
7. **审美门槛高**：这套系统只有一根左基线和 9 档字号，任何一处对不齐都会被立刻看见，对实现质量的容错度接近零；评审者若不看设计声明，很可能第一轮反馈就是"页面太简单/没做完"。

## 14. 适合的企业类型

- **已有 BI 底座、缺"结论层"的中大型企业**：数据团队用 07/04 做探索，管理层用本方案读结论；同一后端、两种前端读法。
- **咨询 / 研究机构 / 战略与经营分析部门**：交付物是"一句话 + 一个数 + 一份可追溯报告"，客户对可信度敏感、对被界面打扰敏感。
- **品牌调性偏克制的高端消费、金融、专业服务公司**：接受墨色无彩色外壳，拒绝炫技式 AI 视觉。
- **面向 CEO/CXO 的对外演示与融资路演场景**：首屏天然是一个可讲述的画面。
- **不适合**：一线运营/分析师的日常高频批处理（选 04、06、09）、需要多面板联动的探索式分析（选 07）、数据尚未治理好、经常取不到可信指标的早期团队（会持续暴露第 13 节第 3 条）。

## 15. 推荐指数

**★★★★☆（4/5）**

理由：它是 10 套里**信息层级最纯净、结论传达最快**的一套，且落地改动最小、可信度表达最强；扣一分是因为它把结构性风险放在了"首屏必须有可信焦点"上，同时天然放弃了横向比较与高密度读法。

**什么情况下应该选它而不是它**：若你的主要用户是每天要看 20 个数、反复改筛选的分析师，选 **07**（筛选联动）或 **04**（键盘高密度多窗格）而不是本方案；若你需要在首屏展示"多个并列结论"，选 **01**；若交付物要以长文档形态被细读、要编号与脚注体系，选 **03**；若你要的是"先答案后理由再证据"的一页纸汇报动线、允许卡片栈与锚点条，选 **08**；若你认为分析成果值得被当作出版物、需要期号与目录，选 **10**。反过来，当用户层级只有"决策者读一眼"这一种、且你能保证每个焦点都有可信数据支撑时，本方案是 10 套里最高端、最低成本的那一个。
