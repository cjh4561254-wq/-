# 方案 10：商业情报杂志 + 数据分析平台

> 依据 `docs/design-options/00-brief-and-matrix.md` 第 3 节坐标撰写，不得偏离：
> 导航结构 = 封面层（主张句）→ 目录层 → 内文层，三级进入；首屏主角 = 本期封面（一个选题 + 期号 `R-2026-10-16/01`）；密度 = 低；数据主角 = 图文混排；主题 = 亮；立场 = "分析成果值得被出版，编号即品牌"。
> 研究依据引用 `docs/design-research.md`（已实测抓取）与其 §13.3 色板结论；未实测的外部印象一律不写。
> 对应样张：`design-options/option-10/index.html`（单文件，零外部依赖，7 个视图）。

## 1. 设计名称

**《市场情报评论》—— 商业情报杂志 + 数据分析平台**
（英文工作名：Market Intelligence Review, published by the Studio）

一句话价值主张在本方案里的措辞：**"把市场数据变成可追溯的决策依据"——本期出版，编号可查。**

界面里的产品不叫"后台"，叫**一份按分析节奏出版的刊物**：每一次成功的分析就是一期，每一期有期号、封面、目录、正文、图、表与注。分析工作台（发起分析、看 Agent 运行）不是并列的另一个产品，而是**内文层里的工具页**——刊物负责组织意义，工具负责生产内容。

---

## 2. 核心设计理念

这套方案在表达一件事：**分析是有限奏的，不是无限流。**

聊天的问题是"下一条在哪"，仪表盘的问题是"还有哪块没看"，而本方案的问题是"这一期说清楚了什么"。把一次分析称为"出版"，会带来三个别的方案不肯承担的义务：**必须选定一件事**（封面只能有一个主张句和一个选题）、**必须给出结构**（目录先于正文，读者知道要多读几节）、**必须留下可核对的编号**（图 G-2、表 T-1、注 [3]、期号 R-2026-10-16/01）。这三项义务恰好对应本产品最难被替代的价值——每个数字能回到具体工具调用。

因此本方案的编辑感只允许来自四个来源：**编号系统、栅格规线、跨栏关系、留白节奏**。零图片铺底、零刊头徽标插画、零衬线中文字体（本机实测无思源宋体/Noto Serif CJK，宋体在小字号下的笔画质量不可接受，见研究 §13.5 的"未做浏览器渲染需实测"纪律）。字族恰好两族：印刷无衬线负责阅读，等宽字体负责**一切标识符**（编号、口径、单位、来源、数据截至、枚举原值）——把"可核对的东西"统一交给等宽字体，本身就是一种层级声明。

出版节奏有真实数据支撑，不是我编的节拍：The Pudding 用**期号 + 月份**（如 #225 Oct 2026）为长文叙事建立"这一篇是一个整体"的完结感；OWID 的每张图卡固定四行（中性名词标题 / 一句话口径或结论 / 单位 / 来源 + 数据截至），且**结论写进描述句、标题保持中性**；IBM IBV 只在封面层使用主张式大标题、内页回归中性名词；WHO 事实表的结构是顶部 Key facts 要点块 → 分节正文 → References。本方案把这四条实测结论分别落到封面层、图卡、标题策略与正文顺序上。**主张句只许出现在封面层与登录页**，这条口号预算不是审美洁癖，而是让"这一期在主张什么"成为唯一的最高优先级信息。

最后一层克制是立场的表达方式而非装饰：品红印色 `#6B1F5E` 只做编辑标记（期号、编号、跳转、角标），**永远不做图表系列色**；图表色走实测色板，**永远不做装饰**。两套色不相交，用户因此能用颜色区分"这是版面标记"和"这是数据"。

## 3. 视觉关键词

**刊面（masthead）· 编号（issue/statement numbers）· 跨栏（span & column）· 规线（rule）· 留白节奏（leading & margin）· 印色（spot ink）· 图卡四件套（chart card）**

反面关键词（同样属于定义）：无图片、无插画、无衬线中文、无卡片化容器分组、无发光、无玻璃拟态。

### 4.3 状态色（只服务状态，绝不进图表）

| 状态 | Hex | 形态 | 中文 + 原值 |
| --- | --- | --- | --- |
| 等待 / 跳过 | `#5A626B` | `○` | 等待中 `PENDING` / 已跳过 `SKIPPED` |
| 进行中（六个阶段） | `#7A5300` | `◐` | 画像中 `PROFILING` … 校验中 `VALIDATING` / 执行中 `RUNNING` / 重试中 `RETRYING` |

| 失败 | `#8E2121` | `✕` | 失败 `FAILED` / 401 / 429 / 5xx |

规则：**数值大小一律用长度/位置，不用颜色深浅**。G-3 里同色的 55% 透明度条表示的是**口径类别**（含大客户 / 剔除大客户），长度才表示数值；因此不违反该条。分类 ≤3 条折线且线端直接标注，构成类不用饼图改用条形（依据 §5.2、§5.3）。

### 4.5 字体与刻度

- 两族：`--sans = -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif`；`--mono = ui-monospace, "Cascadia Mono", Consolas, monospace`。**无 `@font-face`、无外链、无衬线中文族名**。
- 间距刻度：`6 / 12 / 18 / 28 / 44 / 72`，跨栏与留白节奏只由这六档产生。
- 圆角：全站 `2px`（仅控件），杜绝"所有东西都是卡片"。
- 数字一律 `tabular-nums`：纵向可比是口径问题，不是美观问题。

## 5. 页面布局

**导航结构 = 三级进入，不是三张并列页面。** 顶层没有任何传统侧栏菜单，也没有横向主导航；唯一的层级移动方式是"从封面走进目录、从目录走进内文"。

1. **版记条（sticky，全站唯一常驻元素）**：左侧是 `版记｜视觉方案示意 · 数据为占位样例 · 未接入后端`（等宽 11px、字距 `0.14em`，属于刊面语汇而不是贴在脸上的红纸）；右侧是**出版层级坐标** `封面层 › 目录层 › 内文层`，当前层用印色加粗并带 `aria-current="step"`。这条 trail 同时承担面包屑职能——但它表示的是**刊物层级**，不是页面路径。
2. **刊头（masthead）**：纯排字刊题 + 右侧**期号戳**（`R-2026-10-16/01`，26px 等宽印色 + 下一行派生说明）。下沿 `3px double` 双线，是全版面最强的规线。无徽标、无插画、无图。
3. **栅格**：`.grid12` = 12 栏、栏距 24px、版心 1360px。三档跨度承担语义：正文跨 9 栏（`.body-text--span`）+ 右侧 3 栏边注、图卡跨 6 栏或 8 栏、目录跨 8 栏 + 出版信息 4 栏。**跨栏关系本身就是编辑立场**：占 9 栏的是"要读完的"，占 3 栏边注的是"为什么这样算"。
4. **目录层（CONTENTS）**：条目表（章节 01—04 + 副条目 + 落点标记）、图目录（G-1…G-4）、表目录（T-1、T-2）、注目录（[1]—[4]）、**往期**（真实来自 `GET /api/workflows/history`）、本期出版信息块、编号系统说明块。
5. **内文层**：编号小节 + 跨栏图文 + 四件套图卡 + 证据表 + Endnotes + 引用口径；两个工具页（市场分析、Agent 运行）与状态页（空/加载/错误）也归入内文层，用 `tag-kicker` 标注其性质（"内文层 · 工具页"/"内文层 · 运行"/"版式状态"）。
6. **样张架（页脚）**：本文件的 7 个视图索引，等宽小字、明确标注"原型导航，非产品功能"，避免被误读成产品菜单。

**断点**：`≤1100px` 主张句与刊题降档、正文跨栏改为满栏；`≤768px` 栅格退为 6 栏且所有 `.c*` 满宽、表格转"标签—值"堆叠（`data-label` + `thead` 视觉隐藏，**不整页横向滚动**）、`pull` 句降为 18px、目录三列栅格（样张架、往期门）自动单列。两档均已按 1440/768 实测排布，无溢出。

## 6. 登录页面

登录被解释为**"翻开一份需要凭证的刊物"**：左侧 7 栏是本期主张（`知识即权力。让每一个数字可追溯。` + 一段把口号限定在封面层与登录层的说明），右侧 5 栏是凭证面板。上下结构、不居中堆叠、不做整屏渐变。

- **品牌表达**：登录页复用刊头与期号戳，让用户在进入前就接受"这里的东西是有编号的"。口号只在这里和封面出现——文案里明确写出这条纪律是出版纪律，不是装饰偏好。
- **真实能力声明**（左下提示块）：六阶段服务端流水线（画像 → 规划 → 执行 → 图表 → 报告 → 校验）、本地 SQLite 存储、HttpOnly 会话 Cookie `mis_session`（默认 8h）。**没有**找回密码与自助注册接口，所以页面上不给任何对应入口，并把这句写在表单旁而不是藏起来。
- **首次部署 `needs_bootstrap` 模式**：成套切换三处文案（`kicker` 凭证·会话 → 首次部署·初始化；标题 登录本期 → 创建管理员并进入；主按钮 登录 → 创建管理员并进入），并**多出一个"确认密码"字段 + 弱密码提示行**（长度不足 10 位或缺少大小写与数字混合）。主按钮全页唯一，切换模式时不换第二主按钮。真实调用 `POST /auth/bootstrap`。
- **失败文案三种互不相同且可断言**（原型内用 `原型` 标记的一组按钮切换比对）：
  - `401` → **用户名或密码不正确**，附一行"失败文案不区分账号是否存在（防枚举）"；
  - `429` → **尝试次数过多，请 30 秒后再试**，读取 `Retry-After` 做逐秒倒计时（等宽数字不跳动布局），**倒计时期间提交按钮 `disabled`**；
  - `5xx` → **服务暂时不可用**，并写明"5xx 与 401 的文案必须互不相同：一个是'你输错了'，一个是'我们这里出问题了'"。
- 密码字段 `autocomplete="current-password"`，bootstrap 新密码 `autocomplete="new-password"`；错误块 `role="alert"`，倒计时行 `aria-live` 语义由 `hint mono` 承担。
- 表单提交 `preventDefault()`，页内直接注明真实接口 `POST /auth/login`，并给出"进入本期封面"的文本级链接（次级动作，不与主按钮争权重）。

## 7. Dashboard / 工作台 = 本期封面

**用户第一屏看到的是"本期"，不是一个待办队列。**

封面只有一件事：一个主张句 + 一个选题 + 一个期号 + 三条要点 + 一张缩印图 + 目录预览。

- **首屏主角**：`本期主张 · 封面层` 黑底印色标签条 → 主张句（56px，"把市场数据变成可追溯的决策依据"，跨 8 栏）→ `本期选题` → 选题中性标题（`三区域渠道结构的同期对比`）+ 一行副题说明"结论写进描述句，标题保持中性"。
- **期号戳**：`R-2026-10-16/01`，右侧带派生说明一行（见 §7.1）。
- **本期要点（KEY FACTS）**：WHO 事实表式的顶部要点块，悬挂序号 01/02/03（等宽、序号由 CSS counter 生成），每条尾随一个 `[T1]` / `[§04]` 角标——**要点即目录**，读者在封面就能核对每一条数字的落点。
- **封面缩印图 G-1**：四件套图卡（编号行 / 中性名词标题 / 一句话口径或结论 / 单位 / 来源 + 数据截至），并注明"全图见内文第 03 节"。
- **目录预览**：章节 01—04 的极简三列行（编号 / 标题 / 落点）。
- **六扇"门"（D-1…D-6）**：封面 → 目录层、封面 → 内文全文、封面 → 发起新分析、封面 → 查看运行中、封面 → 版式缺页处理、封面 → 登录层。每扇门前有编号、下方一行说明它通向什么真实路径。**封面是进入方式，不是替代功能**：六扇门里三扇通向功能页。

### 7.1 期号派生规则（必须可复核，不许凭空编号）

```
期号 = R-〈generated_at 的 UTC 日历日〉/〈当日第几份出报〉  · 校验位 = report_id
```

- 日期段：`GET /api/workflows/{id}/report` 的 `report.generated_at`（UTC）截到日 → `2026-10-16`。
- 期序 `NN`：当日已经出版的份数 + 1，来源是 `GET /api/workflows/history` 的 `limit/offset` 翻页统计 `has_report = true` 的记录（后端只有 `limit` 1–100 与 `offset`，**无日期筛选参数**，因此这个数只能由前端翻页得到——这一点在界面上如实写明）。
- 校验位：`report.report_id`（`uuid4().hex[:8]`）随附显示，用于把"期号"与"某一份具体报告"钉死，避免同日多份报告互相顶替。
- **不出版就不编号**：`has_report = false`（失败、进行中）的归档记录没有 `report_id`，往期列表里显示 `—（未出版，无 report_id）`，绝不补一个号。
- 界面出现位置（4 处，规则文字 3 处）：① 封面刊头期号戳 + `#cover-derived` 派生一行；② 目录层右上 `#contents-issue-line` 与"本期出版信息"块（含 `generated_at`/`report_id`/`llm_used`/`status`）；③ 内文层每层右上的 `issue-line`（4 个视图都有）与引用口径块 `#cite-line`（**完整写出派生公式**，含"当日序号由 history 分页统计得出"）；④ 登录层刊头期号戳。

## 8. Market Analysis（完整路径）

路径：**选数据集 → 输入需求 → 设 `max_steps` → 发起 → 看 Agent 状态 → 看结果**。全部是真实接口，一步不落。

1. **第 1 步 · 选数据集**：列表即目录，条目编号 `D-1/D-2/D-3`（等宽印色），每行显示 `original_filename`、`row_count`、`column_count`、上传日期，未生成画像的条目标注 `尚无画像`。真实来源 `GET /api/datasets?limit=50&offset=0&sort=uploaded_at&order=desc`；文件名搜索（`q`，≤200 字符）是后端真实能力，样张里声明而不重复实现。**没有删除/重命名/覆盖入口**（后端只有 upload/get/profile/list）。
2. **第 2 步 · 提问**：`textarea` 计数行实时显示 `n / 500 · 至少 2 字`，超限或不足时计数行转失败色（`data-over`），**"发起分析"按钮 `disabled`，且禁用原因写在按钮旁边**（"问题为空 / 不足 2 字 / 超过 500 字"），不只靠悬浮提示。
3. **第 3 步 · `max_steps`**：1–8 的等宽芯片单选（`role="radiogroup"`），旁边一行说明"步数是'最多允许几步工具执行'，不是进度百分比"。
4. **发起**：`POST /api/analysis` → **202 Accepted**。界面显示"已受理"回执块，内含真实请求体 JSON（`dataset_id/question/max_steps`）与响应里的 `workflow_id`、`status = PENDING`、`step_index/total_steps`，并写明"后端已把工作流放进后台线程，此刻还没有报告；页面每 1000ms 轮询 `GET /api/workflows/{id}`，这一步不做闪烁动画"。回执末尾一个链接直接进入运行视图。
5. **右栏三个说明块**：入参只有三个字段且没有模型选择器/Token 用量/保存视图（后端不暴露）；选中数据集的画像摘要（`GET /api/datasets/{id}/profile`：列数、行数、语义类型、缺失率、唯一值、分位数、top_values、重复行、告警）；`error` 级校验问题会让 `passed = false`，报告照常出版但顶部挂红条——**"出版不等于背书"**。

## 9. Agent Runs（执行过程的视觉化）

组织单位是"本期是怎么跑出来的"，视觉上只有两件合法的东西：**阶梯**与**任务简报**。

- **阶梯**：6 格（`PROFILING → PLANNING → EXECUTING → CHARTING → REPORTING → VALIDATING`），每格三列 = 编号 `01…06`（等宽）/ 中文阶段名 + 原始枚举小字 / 状态文字（`已完成 / 正在进行 / 此处失败 / 尚未进入`）。语义严格绑定 `step_index / total_steps`（已完成阶段数 / 总阶段数），**没有任何按时间的百分比**。
- **整条任务的真实耗时**：单独一个说明块，写 `整条任务 10 分 18 秒（created_at 09:31:04 → 09:41:22）`，并紧跟一句约束说明：`created_at → finished_at` 是轮询接口唯二的时间字段，**阶段级耗时、阶段时间戳、按时间的进度百分比后端不提供，因此这个界面上一个都不画**。
- **任务简报表 R-1**：`task_id / description / status / error` 四列（这正是轮询接口真实返回的内容），含 `SKIPPED` 行与"返回 0 行（EMPTY_RESULT）"的错误文本；表下补一行 6 个任务状态枚举的中文 + 原值映射（`PENDING/RUNNING/SUCCESS/RETRYING/FAILED/SKIPPED`）。
- **状态映射清单**：10 个工作流状态一枚不落（等待中 `PENDING`、画像中 `PROFILING`、规划中 `PLANNING`、执行中 `EXECUTING`、绘图中 `CHARTING`、成文中 `REPORTING`、校验中 `VALIDATING`、已完成 `SUCCESS`、带警告完成 `SUCCESS_WITH_WARNINGS`、失败 `FAILED`），每行都是"色 + 形 + 字 + 原值"。
- **原型交互**：四个状态演示按钮（运行中 / 已完成 / 带警告完成 / 失败）+ 一个"模拟下一次轮询"按钮（明确标注原型用途，等价于一次 `GET` 回来后阶梯推进一格；推到最后自动落为带警告完成）。真实节奏 1000ms 轮询在 `poll-note` 里声明，**样张不做自动轮询**（自动刷新的视觉噪声会让用户误判哪个格子刚变过）。
- 运行层不显示报告与结果（轮询接口不含），要读报告走 `GET /api/workflows/{id}/report`，界面上用一句 hint 说清这个分工。

## 10. Reports（报告呈现 + 可追溯）

报告 = **内文层的正文**，顺序参照 WHO 事实表与 OWID 页面节奏：要点 → 方法与数据 → 结论分节（图文跨栏）→ 结论的边界 → 注 → 引用口径。

- **编号小节 01—04**，节标题一律中性名词（`方法与数据`、`三区域销售额的同期对比`、`剔除单一大客户后的结构`、`结论的边界与数据质量`）。主张句已经在封面向你喊过一次，进来之后不再喊第二次（IBM IBV 的实测做法）。
- **`cites` 的可追溯呈现**：正文句子尾随角标 `[T1]` / `[G2]` / `[§04]`（等宽印色上标，`.cite--table` 前缀"表"、`.cite--fig` 前缀"图"，`href="#t1-row-2"` 精确落到**某一行**，`aria-label="跳到表 T-1 华东行"`；点击后目标行加 `.target` 印色外框 900ms 提示落点——只在用户主动跳转时出现）。
- **图卡四件套**：每张图固定四行——编号行（`图 G-2 · 内文第 02 节`）/ 中性名词标题 / 一句话口径或结论（**结论写在这里，不写在标题里**）/ 单位 / 来源 + 数据截至。来源行同时写明真实接口 `GET /api/workflows/{id}/charts/G-2.png`（服务端渲染 PNG，四类图型 bar/line/pie/scatter），样张以内联 SVG 同构示意并注明这一点，不假称接口返回 SVG。
- **证据表 T-1**：`ToolResult.data["rows"]` 前 20 行原样复制，前端不再计算；表头用 `<th scope="col">`，每格带 `data-label` 供窄屏堆叠；含"剔除大客户后份额"这一列，让口径与结论同表可见。
- **数据质量与校验一起出版**（第 04 节）：`data_quality_notes` 两条告警不淡化；校验明细显示 `checked_numbers 126`、`0 error / 2 warning / 1 info` 与机器码原值（`MISSING_CHART_FILE`、`EMPTY_RESULT`、`SHORT_REPORT`、`UNSUPPORTED_NUMBER` 等），并解释 `passed = true` 只由 error 级决定。图 G-4 因 PNG 缺失被登记在图目录里但标注"未采信"——**缺陷也要有编号，才能被追踪**。
- **Endnotes [1]—[4]**：悬挂编号列表（CSS counter），内容是数据来源、季度口径、再计算声明、未采信图表；目录层的"注"目录与之同源。
- **引用与口径块**：一个 `code-line` 写明 `report_id / generated_at / llm_used / 派生公式 / 引用写法`。**没有导出、下载、分享、评论入口**（后端没有），并在同一块里说明"为什么这一层不提供下载：引用以'期号 + 图/表编号 + 注号'为准，人读即可复原全部口径"。

## 11. 动效（逐条：动效 → 业务价值；写不出价值的不做）

| 动效 | 参数 | 业务价值 |
| --- | --- | --- |
| 阶梯推进（格位下移 + 行底 `#F1F2F3`） | 120–200ms 位移 + 透明度 | 用户能确认"是这一格刚完成，不是整页刷新"，`step_index` 的变化被看见而不是被猜 |
| 跳转落点提示 `.target` | 印色外框，200ms `outline-color` 过渡，900ms 后移除 | 长跨栏版面里"点了角标到底跳去哪"必须可指认；只在用户主动跳转时出现，不做常驻高亮 |
| 状态切换（等待 → 进行 → 完成/警告/失败） | 150ms 颜色 + 字形（`○◐●◆✕`）变化 | 三重编码同帧改变，避免"颜色变了但不知道变成什么"；形变即语义 |
| 429 倒计时（`Retry-After`） | 等宽数字逐秒，无动画 | 用户能判断"还要等多久"而不是反复提交；数字等宽保证不引起行跳动 |
| 加载骨架呼吸 | `1.6s` 透明度 1→0.55→1，**仅加载态使用** | 表明"在取数，不是没数据"；`prefers-reduced-motion: reduce` 下停止动画 |
| 焦点可见 | `2px` 印色 `outline` + `2px` offset，无 `outline:none` | 键盘用户可在目录、门、单选芯片、`max_steps` 组里连续移动；`:focus-within` 覆盖被视觉隐藏的 radio |
| hover | 只做可达性提示（边框/下划线转印色、行底 `#F1F2F3`），**无缩放、无阴影** | 杂志版面靠栅格对齐，任何缩放都会破坏规线；hover 只回答"这里可点" |

明确**不做**：轮询刷新时的整屏闪烁/淡入（会让用户误读为新报告）、卡片浮起、视差滚动、页面切换动画（三级进入是**层级**不是**转场**，加动画会把出版节奏稀释成应用切换）、滚动进度条（无业务含义）。

## 12. 优点

1. **给分析一个"完结"形态。** 期号 + 目录 + 正文 + 注的结构，天然回答了"这次分析说完了没有"，而仪表盘与聊天流都答不出这个——这是本产品"每个数字可追溯"最贴合的容器。
2. **编号系统是免费的信任机制。** `G-2`、`T-1`、`[3]`、`R-2026-10-16/01` 让引用、复盘、口头沟通（"第 02 页那张图"）都有唯一落点；角标直达表格行，核对成本接近零。
3. **密度低但信息不稀。** 12 栏 + 跨栏关系 + 边注，使同一屏能同时容纳结论、口径与出处三类信息，而不必把它们塞进一堆卡片容器。
4. **实现门槛可控、零依赖。** 两族系统字体、纯排字刊面、无插画无图片（后端图表本就是 PNG，样张用内联 SVG 同构），版面成本主要在栅格与间距，不美术预算。
5. **与产品定位（分析师、经营负责人、咨询/研究人员）高度同频。** 这批用户日常的交付物就是报告与简报，"刊物"隐喻不需要培训。
6. **对比度与可达性有余量。** 文字最浅一档 4.88:1（其余均 ≥5.5:1），图形最浅一档 3.03:1，状态四重编码，1440/768 两档不破版且表格能堆叠。

## 13. 缺点（真缺点）

1. **实现成本明显高于其他方案：编辑版式不是组件。** 跨栏（正文 9 + 边注 3）、悬挂编号、`3px double` 分节线、图卡四件套、期号戳这些都不对应现有组件库里的任何东西，需要重写 `app.css` 的排版层与 `index.html` 的 DOM 骨架；而现有报告 DOM 是"标题 + 段落列表"，改成编号小节 + 跨栏图文 + Endnotes 是一次结构性返工。**估算工作量在 10 套方案里属最高档。**
2. **信息风险：低密度 × 长版面 = 首屏承载力弱。** 封面只放一个选题，意味着"还有另外三件事也重要"时必须等下一期或走目录层。对需要一次扫完多张面板的用户（对照方案 07 的图表墙），本方案的读取效率天然更低；一旦选题判断错了，用户会感到"整份刊物只讲了一件不相关的事"。
3. **期号与"出版"隐喻带来误读风险。** 用户可能把"本期"当成"人工编辑过的权威结论"，而它只是某次 `max_steps` 下的机器产出；`llm_used = false` 的规则模式报告与带 error 的报告若同样以"一期"呈现，会**用版面气质替内容做背书**。必须靠第 04 节与红条把边界喊回来，这是持续的文案负担。
4. **无导航栏 = 可发现性差。** 三级进入意味着"发起新分析"藏在封面的门（D-3）里；高频用户（每天问十几次）会嫌绕。本方案对它唯一的补偿是运行/分析页也保留期号与层级坐标，但路径长度确实比 06 的"功能页直达"长。
5. **历史只能翻页，不能归档成"往期年鉴"。** `GET /api/workflows/history` 只有 `limit/offset`，所以目录层的"往期"只能按接口原序（新→旧）显示当前窗口，并必须标注样本口径；想要"按月分组/按数据集筛选"的档案视图，本方案在现有后端下**做不到**，用户若期待"杂志合订本"会失望。
6. **视觉人格有单一化风险。** 纯排字 + 印色 + 零装饰的刊物气质，对强调品牌彩度的企业客户偏"克制过头"；换 Logo 与主色的空间小（品红印色一旦换成高彩度蓝，编号系统与图表色的区分度就要重做）。

## 14. 适合的企业类型

- **研究/咨询机构、智库、行业分析部门**：交付物本来就是"报告/季报"，客户会引用报告编号；把 `report_id` 变成可对外引用的期号有直接商业含义。
- **消费/零售/区域经营类企业**：数据按区域、季度、渠道天然分章，跨栏图文版面能承载"一段结论 + 一张图 + 一张表"的叙事单元。
- **有稳定分析节奏的公司**（周会、月度经营分析）：出版节奏与会议节奏对齐，"这周的一期"就是会议材料。
- **面向外部发布洞察内容的 B2B 企业**（IBM IBV 式）：封面主张句 + 编号即引用单位，适合做轻度公开传播。
- **不适合**：以实时监控/告警为主的运维场景（→ 方案 09）、以高频批量提问为主的分析师团队（→ 方案 02/06）、需要极端密度的金融终端用户（→ 方案 04）。

## 15. 推荐指数

**★★★★☆（4/5）** —— 它是 10 套里**最能表达"分析成果是作品而不是日志"** 的一套，编号即品牌的立场贯彻到底，且与"可追溯"的产品内核同向；扣掉的一星在实现成本与低密度带来的读取效率损失。

**什么情况下应该选它而不是它：**
- 只想要"最快问完一组问题" → 选 **02**（会话式）或 **06**（功能页最短路径），别选 10。
- 要给高管一页纸拍板（结论 → 取舍 → 行动） → 选 **08**（结论卡栈 + 锚点，无封面、无期号）。
- 要一份可打印、可长读的单一文档（章节 + Endnotes + 证据表） → 选 **03**（单栏 `article` 长文档），别选 10：10 的正文是跨栏的，读长文的连续性不如单栏。
- 想让界面"看起来什么都不多余" → 选 **05**（无编号、无目录、一屏一件事）；10 恰恰是**加**编辑系统。
- 用户要"改一次筛选、全部图联动" → 选 **07**（BI 面板），10 没有筛选作用域这条路径。

**跨栏栅格落到 `app/web/` 的具体影响（最容易做错的三处）**：

1. **报告区不能再用 `max-width` 单列。** `.grid12` 要求报告 DOM 的每一段成为栅格子项（正文 `c1 / span 9`、边注 `c10-12`、图卡 `c1-8` 或 `c1-12`），因此 `renderReport()` 里"一节 = 一个 wrapper"的结构要改成"一节 = 一个栅格容器 + 若干跨栏子块"。窄屏必须显式把 `.body-text--span` 降为满栏、边注改为上方细线分隔（本样张已验证 768 档）。
2. **图表 `<img>` 是 PNG，栅格要按 4 种图型给不同跨度。** bar/line 适合 8 栏（横向展开），pie/scatter 适合 6 栏配右侧 6 栏的证据表；`charts/{filename}` 的返回是二进制，不能像 SVG 那样自适应，需要在图卡里用固定 `aspect-ratio` 容器 + `object-fit: contain`，否则跨栏时图会把行高撑坏。
3. **编号必须来自数据而不是 CSS 计数器兜底。** 章节号取 `sections` 下标、图号 `G-n` 取图表文件名序号、表号 `T-n` 与 `cites` 里的 `task_id` 建立映射（`T1 → t1-row-k`）。如果只靠 CSS counter，导出/打印或换序后编号会与引用错位——这是"编号即品牌"承诺的破裂点。`counter-reset` 只允许用在要点块与 Endnotes 这类**纯展示序号**上。

**是否需要动后端：不需要。** 不改任何请求契约、不新增字段依赖、不影响既有深链接与轮询逻辑；所有新增 DOM 都在现有渲染函数的输出边界内。若将来产品要求"按期次归档/检索"，需要 `GET /api/workflows/history` 增加日期或数据集筛选参数——那是新需求，不是本方案落地的前置条件。
