# 方案 03：国际咨询公司商业分析平台

> 坐标（不得偏离，取自 `00-brief-and-matrix.md` 第 3 节）：顶部横向主导航 + 页内左侧章节目录锚点｜首屏主角 = 报告文档流（编号小节 01/02/03）｜密度 中｜数据主角 = 长文正文 + 图表四件套｜主题 亮｜立场「交付物本身即界面」。
>
> 对应 Demo：`design-options/option-03/index.html`（单文件、内联 CSS/JS、零外部依赖）。

## 1. 设计名称

**国际咨询公司商业分析平台（Deliverable-first / 交付物即界面）**

一句话：用户打开这个产品时，看到的不是"分析工具的面板"，而是一份**已经在排版中的报告**——有目录、有编号小节、有脚注、有口径块。工具退到文档的缝隙里。

## 2. 核心设计理念

这套方案表达的是"分析工作的成品感"。咨询交付物之所以可信，不因为它图表多，而因为它**交代过程**：问题怎么定义、口径怎么选择、数字从哪一次计算里来、结论受什么限制。因此本方案把产品界面做成文档本身，而不是把文档塞进界面的一个模块里。

具体主张有四条。第一，**层级只由排版建立**：编号（小节 01–07、图 1/表 1、角标 [T1]、注 1）、行宽、分隔线、字号；不用容器堆叠、不用阴影浮起。这有实测依据——研究 §3.7 记录 Pentagram 全站只用 `#767676 / #000000 / #6f6f6f` 三个灰阶、可见文本 26,530 字符为全部 42 个 URL 之首，仍然辨识度极高，说明"命名秩序 + 排版"足以取代彩色装饰。第二，**读者的位置感优先于操作效率**：长文档必须有左侧章节目录锚点并随滚动高亮，这是文档产品的基本礼貌。第三，**结论写在描述句里，标题保持中性**：这是 OWID/WHO 一类数据机构图卡的通行做法（研究 §4.4 A14、§5.2 要求每图有纯文本替代与明确口径），本方案把它固化为"图卡四行"组件。第四，**诚实优先于完整**：界面只暴露后端真实存在的能力，并显式写出"本视图不含的入口"（导出、删除、实时流），宁可少一个入口。

与相邻方案的分工：03 卖的是**过程 + 证据**；08 卖取舍 + 行动；10 卖出版节奏；05 卖一屏一件事。

## 3. 视觉关键词

编号秩序 · 窄行宽 · 纸白墨蓝 · 哑光印刷色 · 脚注与口径 · 等宽数字 · 无装饰

（补充：全站**零阴影、零渐变、零圆角堆叠**——`box-shadow` 出现 0 次，`linear-gradient` 0 次，唯一圆角是 `border-radius:2px` 的角标与标签。）

**图表色与状态色不得互用**（硬约束）：两套 hex 无一重合；状态色只出现在 `.tag/.notice/.dot` 上，图表色只在 `.chart` 内出现。运行页图 2 的阈值虚线故意用 `#1C2530`（墨）而不是警告色，避免"阈值"被读成"报错"。

## 5. 页面布局

- **导航结构（本方案身份）**：① 应用顶栏 `56px` 深墨蓝，横向 5 项主导航（工作台 / 市场分析 / 运行记录 / 报告中心 / 账户与安全）+ 用户名 + 退出登录；**没有全局左侧栏、没有面包屑、没有第二层 Tab**。② 报告阅读页额外有**页内左侧章节目录**（`232px`，sticky，随滚动高亮）——它属于这份文档，不属于产品导航，离开报告页即消失。
- **栅格**：容器最大 `1240px`。报告页为 `232px | minmax(0,1fr) | 268px` 三列，中列内部再限 `max-width:672px`（≈42 个全角汉字），保证行长不受窗口拉宽影响。其余页面为 `minmax(0,1fr) | 316px`（工作台/分析）或 `minmax(0,1fr) | 300px`（运行）。
- **分节方式**：`.block` 用 `border-bottom:1px` + `block-head` 的 `2px` 墨线分段，**不用卡片分组**。卡片只保留三处有语义的地方：登录表单（输入需要边界）、图卡（四行需要边界）、空态块。
- **断点**：`1240`（附录列落到文档下方，图录/口径卡转为横排）、`1180`（右侧说明列落底换行）、`960`（登录与报告页转单列，目录变横排 chips）、`768`（表格转「标签—值」堆叠 `.tbl.kv`，长文降为 15.5px，指标条满宽）。
- **密度=中**的具体含义：正文 16px/1.85，列表 13px，元信息 11.5px；每屏最多两个层级组；表格行高 38–40px。

## 6. 登录页面

**布局**：左右分栏 `1.1fr / .9fr`。左为机构主张（这是咨询公司网站的通行做法，研究 §3.2 Huge 首页 H1 只有一个 `Hello.` 而由 meta description 承担完整定位；§3.5 IDEO `/about` 的 H1 是一整句），右为表单卡。

- 左栏：品牌行（英文等宽 `AI MARKET INTELLIGENCE STUDIO` + 中文副名）→ eyebrow `Deliverable-first · 交付物即界面` → H1「把一次分析，做成一份**可以交付的报告**。」（强调部分用 `#F3E7E3` 底色标记，不是渐变高亮）→ 副标题按 Stripe 的一句话范围句式（研究 §4.2 第 24 条 `from your first transaction to your billionth`）：「从一份 CSV 或 Excel，到一份每个数字都能回溯到具体工具调用的分析文档」→ 编号 01/02/03 的三条机构承诺（结论与证据同页 / 图表按研究文档排版 / 数据留在本机）→ 底部小字交代 Cookie 与"没有找回密码接口"。
- 右栏：`seg` 两个模式——`已有账户` 与 `首次部署 · 建管理员`。**needs_bootstrap**：切到后者时表单上方出现一条虚线说明块，原文写明「账户库为空，`GET /api/auth/me` 返回 `needs_bootstrap = true`，本页已自动切换为『建立第一个管理员』模式，提交将调用 `POST /auth/bootstrap`」，并追加"确认密码"字段、按钮文案改为「创建账户并进入工作台」。真实实现里这个分支不是用户选的，而是 `me` 接口驱动自动进入，seg 的另一半会禁用。
- 状态覆盖（均可在 Demo 里触发）：空字段提示、`401` 统一文案（不透露哪个字段错）、连续 3 次失败后 `429 + Retry-After: 900`（写成"15 分钟"而不是"稍后再试"）、用户名 `maintenance` 触发 `503`（同时底部健康指示灯变红、文案改为"上传目录未就绪"）。
- 品牌表达：无插画、无大 AI 图标、无渐变；权威感由编号承诺 + 分隔线节奏 + 等宽接口名建立。

## 7. Dashboard / 工作台

**用户第一屏看到的是报告，不是模块入口。** 页眉标题「从上一份成稿接着读」，右侧只有四个事实数（数据集 / 运行记录 / 已成稿 / 带警告），每个都是一个可核对的数，不写"业界领先"这类无法核对的形容词（研究 §3.2 第 4 条：Huge 用具名事实 `Born in Brooklyn.`、`Independent again.` 而不是形容词；§3.8 第 16 条：信任状用客户名清单，不配形容词）。

- **01 最近在读的报告**：文档行列表（不是卡片栈）。每行 = 报告编号 `R-2026-10-16/01` + 标题 + **委托提问原文**（用 `委托提问` 徽标引出，这是咨询交付物的语言）+ 首段摘录（最新一条给正文摘录，让文档"露出正文"）+ 元信息行（终态标签 + 成稿时间 + 小节数 + 引用工具结果数 + 数据集名）+ 右侧单个「阅读报告」。
- **02 仍在推进的运行**：一张密排表，列为 运行编号 / 提问 / 数据集 / 状态 / **已完成阶段（2 / 6）** / 提交时间。表上方显式写明"历史接口只有 `limit` 与 `offset`，没有排序与筛选，因此界面上不放排序下拉"。
- **03 数据集**：真实存在的文件名搜索（`q`）+ 三种真实排序（`uploaded_at / filename / rows`）+ 上传入口（原生 `input[type=file]`，选择后只回显文件名并标注"本机演示不发送数据"）。每行操作只有一个「选它提问」。
- **右侧说明列**：两个"文档性质"的块——报告的固定五段式、状态口径对照（10 个枚举中文映射 + 原始值同行保留）。它们不是操作面板，而是把方法说明放进界面。
- 空态：搜索无命中与"暂无数据集"文案不同（见第 13 节与 Demo 的状态屏）。

## 8. Market Analysis（完整路径）

路径：**选数据集 → 写提问 → 设阶段上限 → 发起（202）→ 看 Agent 状态 → 读结果**，页面顶部用 `01–05` 步骤条标出当前位置（步骤条是"你在文档流程的哪一步"，不是进度百分比）。

1. 数据集为单选卡列，卡上直接写规模、上传时间、画像发现的关键事实（缺失率最高列、重复行、告警数），并用 `可分析 / 有告警` 标签给出决策提示。
2. 提问区 `textarea` 4 行，右下实时字数 `n / 500`，超出 2–500 范围时数字转红并阻止提交；帮助句写的是业务理由（"越具体，规划阶段拆出的子问题越接近你的决策颗粒度"），不是"请输入内容"。
3. `max_steps` 用 `select` 暴露 3–8（后端契约 1–8），旁边一句话点明它限制的是任务数上限，**不是进度百分比**。
4. 发起后出现 `202` 受理回执块：运行编号 / 数据集 / `PENDING · 等待中` / 受理时间 / 阶段上限，并写明"状态接口此刻不含报告与图表；报告只在 `REPORTING` 之后由 `/report` 单独取回"，出口按钮只有一个「看 Agent 怎么跑 →」。
5. 右侧列为画像摘要（`GET /api/datasets/{id}/profile` 的真实字段：列数、行数、语义类型分布、缺失率、分位数、重复行、告警）与两块"文档式说明"：好提问的三要素、以及**本视图不含的入口**（无导出/下载/打印、无删除或覆盖、无实时日志流）。

## 9. Agent Runs（执行过程如何视觉化）

**只用 `step_index / total_steps`。** Demo 与代码注释都遵循后端语义：`step_index` = 已完成阶段数（`orchestrator._enter` 用 `_STEPS.index(step)`），正在进行的那一阶段**不计入**，因此运行中的 wf_4a71f0c3 显示「已完成 2 / 6」而当前阶段是 `03 计算执行`。

- **六阶段阶梯**：`01 数据画像 → 06 校验数字`，每级三行信息——编号 + 阶段名 + 状态标签（原始枚举留在 `title` 里可查证）+ 一句该阶段做了什么的事实描述（如"14 列语义类型判定 · 缺失率与分位数已登记 · 2 条告警写入报告的数据质量说明"）。**没有任何一处出现秒数**。阶梯底部固定一段说明：后端没有阶段级时间戳，任何"本阶段 3.2 秒"都是编造；只有整条任务在终态时才用 `created_at → finished_at` 算一次真实总耗时（失败示例里就给了这一条：41 秒）。
- **推进方式**：Demo 用「演示：推进一次轮询」按钮手工推进，而不是前端计时器自动跑——避免用假定时器伪造任务进度。终态时状态转「已完成 · SUCCESS」，按钮禁用并长出「阅读成稿报告 →」。
- **任务简报表**：列只给 `task_id / description / status / error(备注)`，并说明工具参数属于排查信息、不给读者。覆盖 6 个任务状态：`PENDING 等待中 / SUCCESS 已完成 / RETRYING 重试中 / FAILED 失败 / SKIPPED 已跳过`，且写明"SKIPPED 只影响显式声明依赖的任务，不搞连坐"。
- **失败终态示例**：错误框 + `error.code = PLANNING_NO_MATCHING_COLUMN` + 人话解释（"规划阶段找不到提问涉及的字段"）+ 两个出口（回到提问改口径 / 回报告中心），同时指出"失败时 step_index 不再推进，进度条不会假装走满"。
- 右侧列：为什么没有百分比、校验三级 `severity`（阻断 error / 提醒 warning / 说明 info）、角标与 task_id 的对应关系。

## 10. Reports（报告呈现方式）

**报告中心**：一份报告对应一条 `has_report = true` 的运行。台账表列为 编号 / 标题 / 委托提问 / 终态 / 成稿时间 / 引用数 / 操作，只有翻页（`offset 0`、每页 20），顶部一条 `filterline` 直接展示取数 URL 与"没有排序与筛选所以不放控件"的理由。未成稿与失败记录也在台账里，标题位置写「（尚未成稿）/（无报告）」并划掉，操作改为「看运行详情」——列表不隐藏失败。

**报告阅读页（本方案首屏主角）**，DOM 结构是一个 `<article class="doc-body">`：

- 扉页：eyebrow → `h1` 标题（两行）→ `byline`（委托提问原文 / 编制方 / 数据集与规模 / 成稿时间 / 终态标签 / 校验结论"核对 17 处，一致 17 处"）。
- **编号小节 01–07**：01 执行摘要与关键发现（`lead` 段 + `Key Findings` 要点块）→ 02 研究问题与统计口径（含"方法说明·三个口径先说清"表）→ 03 总体增长结构（含 `3.1`、`3.2` 二级锚点）→ 04 折扣依赖度与边际关系 → 05 局限与数据质量说明 → **06 Endnotes（编号脚注区，悬挂缩进、等宽序号）** → **07 引用与口径块（证据表）**。这就是研究里"目录 → 编号小节 → 关键发现要点块 → Endnotes → 引用与口径块"的五段式落地。
- **图卡固定四行**（`.fig-l1 … .fig-l4`，Demo 中图 1/图 2/表 1 全部遵守）：① 中性名词标题「2026 年 Q3 线上销售额同比增量按子品类拆解」——**判断不进标题**；② 一句话口径或结论「增量集中在护肤礼盒与精华类两项…」；③ 单位「单位：百万元（CNY，含税，未扣退款）」；④ 来源 + 数据截至「来源：`aggregate_sales_yoy` [T1] 与 `group_stats_by_category` [T4]；图中数值取自报告表格原值，未二次计算。数据截至 2026-09-30；纵轴自 0 起，未截断」。
- **`cites: T1` 角标可点击**：正文每个关键数字后跟 `a.cite[href="#en-T1"]`，点击后滚动到第 07 节证据表、目标行整行高亮（`.hl`）、角标自身反色保持"我刚点了哪一个"的记忆；再点另一角标会清除旧高亮。证据表由接口 `citations` + `sections[].cites` 渲染，列出**未被正文引用的调用**（T7，标注"0 处"），因为只挑对自己有利的证据是交付物最常见的失信方式。每行交代：工具调用名、产出、取数口径、正文引用处数。
- 报告内不放任何操作按钮。唯一的出口在右侧附录列（图与表目录 / 数据质量说明 / 这份报告怎么来的：运行编号、6/6、工具调用 8 次引用 17 处、`llm_used = true`），底部出口按钮只有「回到那次运行的阶梯」。
- 尾部固定「引用本报告时的三句话」：说清账面口径还是中性口径（相差 15.5 个百分点）、带上数据截至日、转述四条局限。

## 11. 动效（逐条：动效 → 业务价值）

| 动效 | 参数 | 业务价值 |
| --- | --- | --- |
| 视图切换淡入 + 4px 上移 | 180ms ease | 确认"换了一页"，避免整页突变让人以为出错；对应"翻开新的一页" |
| 目录当前项边框/底色切换 | 140ms | 长文档里读者始终知道读到哪一节，这是目录唯一的存在理由 |
| [T#] 角标 hover/激活反色 | 140ms | 建立"角标 ↔ 证据行"的成对反馈，让追溯动作可确认 |
| 证据行高亮 + 平滑滚动 | 滚动 700ms 上限，高亮持续 | 点击后必须"看得见落点"，否则读者会以为链接没生效 |
| 柱图入场逐柱生长 | 500ms，柱间 120ms | 只在报告首次进入时播放一次，价值是"这是一份成品稿"的完成感；`prefers-reduced-motion` 下直接静态显示 |
| 进行中阶段的圆点慢闪 | 1.6s 透明度 | 唯一一处循环动效，语义是"仍在推进、非卡死"；轮询本身**不做**闪烁 |
| 骨架块慢闪 | 1.6s 透明度 | 表明"内容在取，不是没有"，配合骨架宽度对应标题/摘要/小节三层 |
| hover 反馈（行、按钮、链接） | 140ms 背景/边框/下划线 | 可达性提示；**不做缩放、不做位移浮起** |

写不出业务价值的动效一律不加：全站无粒子、无霓虹发光、无渐变流动、无 hover 放大。

## 12. 优点

1. **可信度最高**：口径、方法、脚注、证据表都在正文里，读者不用跳出文档去别处核对——这正是本产品"每个数字可追溯"卖点的最佳承载体。
2. **与产品差异点同构**：报告是本产品真正的产出物，界面与产出物形状一致，销售话术不需要额外解释。
3. **零装饰、可访问性好**：正文对比度 11–12.8:1，全站零阴影零渐变，弱网与投影环境都不塌；打印友好。
4. **实现成本相对可控**：一个 `article` + 一套图卡组件即可覆盖核心页；不需要复杂栅格状态与联动逻辑。
5. **长文档可读性最佳**：672px 受控行宽 + 编号 + 目录锚点，是十套方案里唯一为"读 4000 字"优化的。
6. **约束落地明确**：状态中文映射保留原始枚举、`step_index/total_steps` 读法、无导出/删除入口，都在界面上写了理由而不是靠评审口头解释。

## 13. 缺点（真缺点）

1. **首屏对"想马上动手"的用户效率低**：文档流要求先读，操作入口（发起分析、上传）被推到第二屏之后。高频分析师每天用会嫌绕。
2. **长文本身是信息风险源**：正文一旦超过 3000 字，移动端与 1280px 以下的阅读体验明显退化；目录高亮也无法救回"段落太长不想读"的情况。
3. **脚注/口径块的维护成本高**：图卡四行、引用表、Endnotes 三套结构互相牵连，后端 `sections[].cites` 与前端锚点 id 一旦命名不一致，角标就会指向空锚点（Demo 里已用"锚点必须存在"的兜底逻辑，但真实数据仍需测试覆盖）。
4. **辨识度依赖排版，风险是"看起来像没设计"**：没有彩色与阴影，若字体回落（本机无思源宋体、无中文衬线）或行宽被业务方改动，整套方案会退化成"一篇普通网页"。
5. **密度中偏高，不适合做首页仪表盘**：管理层如果只想 30 秒看完，本方案不如 08；这套界面里没有为"扫一眼"准备的结论层。
6. **实现上需要真正的长文渲染与换行治理**：中文正文的标点悬挂、数字与单位不成行断、表格横向溢出都得逐处调；比写卡片多约 30% 的收尾工时。

## 14. 适合的企业类型

- 咨询、研究、市场洞察外包机构，交付物形态本就是"文档"；
- 有正式研报/尽调/经营分析制度大中型企业（快消、医药、汽车、金融机构研究部），报告会被转述与引用，因此口径与脚注不是冗余而是合规需要；
- 需要把分析结论交给第三方决策者（董事会、监管、客户）的组织；
- 不适合：追求"打开即操作"的高频运营团队、需要多面板联动探索的分析团队（那是 07）、以及平台运维视角（那是 09）。

## 15. 推荐指数

**★★★★☆（4/5）**——理由：它是十套方案里唯一把"可追溯"这一核心差异做成阅读体验的方案，落地成本与风险都居中，几乎不需要后端配合就能实现。

什么情况下应该选它而不是它：
- 若首要目标是"高管 60 秒内拿到判断并决定资源投向"，选 **08**（结论卡 + 方案对比矩阵 + 行动项）而不是 03；
- 若目标是把分析成果经营成对外内容品牌、强调发布节奏与期号识别，选 **10**（封面/目录/跨栏图文）；
- 若用户每天要发起十几次分析、更在意路径最短，选 **06**；若想强调"和 Agent 协作"的过程感，选 **02**；
- 若读者只需一个数字一个结论（如周报卡片推送），选 **05**。
