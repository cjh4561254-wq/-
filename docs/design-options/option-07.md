# 方案 07：商业情报 BI 面板 / 探索式分析台

> 遵循 `00-brief-and-matrix.md` 全部硬约束。坐标：左侧筛选器面板 260px（作用域标注）+ 顶部时间控件；首屏 = 12 栏栅格图表墙（面板尺寸档位）；密度高；数据主角 = 图表（bar/line/pie/scatter）；亮色；立场"探索式分析：改一处筛选，相关图全部联动"。

---

## 1. 设计名称

**商业情报 BI 面板 / 探索式分析台**（Exploratory BI Canvas）。

一句话：把一次可追溯分析的运行结果铺成一整面图表墙，让用户用鼠标改筛选、换尺寸、切时间窗，在同一屏内反复"翻动证据"，而不是在页面之间往返。

## 2. 核心设计理念

决策者看市场数据的方式不是"读一份文档"，而是"盯着一组图反复推敲"：把华东去掉，曲线还成立吗？把散点放大到半屏，异常点落在哪个渠道？本方案把界面做成一块**探索式分析台**——左侧 260px 筛选器面板常驻，每个筛选器明确标注自己的作用域（全局 / 分区 / 单卡）并实时显示"影响 N 张卡"；主区是 12 栏栅格图表墙，每张面板可在 S(3 栏)/M(4 栏)/L(6 栏)/XL(12 栏) 四档间切换。"联动"的真相被诚实地画出来：后端没有服务端再聚合接口，筛选只作用于**本次运行已取回的结果集**（报告 `sections[].table`，工具结果前 20 行）——表格行被过滤、卡片按命中显隐，而图表 PNG 保持原样并明示"静态图片不随筛选重绘"。高亮度的密排栅格 + 明确的因果提示（哪几张卡动了），让"改一处、看一片"的推敲成本降到最低。

## 3. 视觉关键词

密排栅格、作用域可见、联动高亮、图表为主、克制亮色、专业仪表盘感、静态图片诚实化。

## 4. 色彩体系

图表色与状态色为两套独立映射，**任何情况下不互用**（状态色不进图表系列，图表色不表达运行状态）。

**主色**
- `#0F5F73` 深青蓝：导航激活项、筛选面板标题栏、主按钮、分区标题左规则线。
- `#0B4A59` 主色深档：按钮 hover、主色文字态。

**辅助色**
- `#4C5A66` 次级文字（说明行、图注）。
- `#5D6B76` 弱文字（13px 以上的次要标注，白底对比 ≥4.5:1）。
- `#D3DBE2` 分隔线 / 卡片描边；`#E2E9EF` 表头底线。

**背景色**
- `#F3F6F8` 页面底色；`#FFFFFF` 卡片面；`#EAEFF3` 筛选面板底；`#EEF3F6` 时间控件带底。

**状态色（仅用于状态徽标、运行阶梯、历史条目；一律"色 + 形 + 字"三重编码）**
- `#5C6A77` 等待中（PENDING）
- `#0E6B8C` 运行中（PROFILING / PLANNING / EXECUTING / CHARTING / REPORTING / VALIDATING 的进行态）
- `#1D7A4C` 已完成（SUCCESS）
- `#96690B` 带警告完成（SUCCESS_WITH_WARNINGS）
- `#B23A31` 失败（FAILED）
- 徽标用对应色的浅底 + 深字（如完成 `#E7F0EB` 底 / `#145A38` 字），保证正文对比度。

**图表色（仅用于图表区内的系列着色；bar 的数值对比一律用文字/表格补充，不单靠颜色）**
- `#3563A5` 系列蓝（bar 主系列）
- `#2C8C7D` 青绿（line 主线）
- `#9561B1` 紫罗兰（pie 分片之一）
- `#C4762F` 赭橙（scatter 点）
- `#5A7FB5` / `#55A899` 多系列延展（第二、第三条线）。

## 5. 页面布局

- **顶栏**：48px，产品名 + 原型视图切换 + 固定声明条（`视觉方案示意 · 数据为占位样例 · 未接入后端`，小字号、对比达标）。
- **左侧筛选器面板**：固定 260px，含标题注记"仅作用于本次运行结果集"；每个筛选器组带作用域徽标（全局/分区/单卡）与"影响 N 张卡"计数；底部写明"布局仅本次会话有效，后端无保存视图接口"。
- **顶部时间控件带**：主区顶端 40px 条带，时间窗按钮（近 24 小时 / 近 7 天 / 近 30 天 / 全部）+ 样本注记"前端过滤，样本 N 条（上限 100）· 非全库查询" + 数据截至时间；其下为已取回运行（历史条目）的芯片条。
- **主区**：12 栏栅格（`gap:10px` 高密度），分区标题横跨 12 栏；卡片尺寸档位 S=3 栏、M=4 栏、L=6 栏、XL=12 栏，档位按钮在卡头，仅鼠标驱动。
- **卡片内部**：图注行 → PNG 占位区（内联 SVG 示意 + 真实 URL 路径文本 + "PNG 静态图片，筛选不重绘"标注）→ 本卡结果集数据表（前 20 行截断，显示"命中 x/y 行"）。
- **断点**：1440px 完整 12 栏；≤900px（含 768px 档）筛选面板折叠为顶部可展开区块，卡片档位映射为 S→6 / M→6 / L→12 / XL→12，卡内表格转为"标签—值"堆叠，不出现整页横向滚动。

## 6. 登录页面

居中的品牌带（左：主张句"把市场数据变成可追溯的决策依据"+ 密排小栅格装饰线，非粒子非渐变；右：420px 登录表单）。登录是本方案唯一允许的独立卡片，以保持"面板即界面"的第一印象留给主界面。

- 常规模式：账号 + 密码 → `POST /auth/login`（HttpOnly `mis_session`，会话 8h）。失败统一文案"登录失败，请检查账号密码或稍后重试"，不泄露账号是否存在（401）。
- **needs_bootstrap 模式**：首次部署（后端指示尚无管理员）时表单切换为"初始化管理员账号"，提交 `POST /auth/bootstrap`；界面显式标注当前处于初始化模式与切换原因，避免用户误以为账号被锁定。
- **429 限流**：显示固定等待提示"尝试过于频繁，请 34 秒后重试（响应含 Retry-After）"，提交按钮在提示期间禁用并给出禁用理由。
- 底部一行小字列出会话与安全的真实边界：仅 Cookie 会话、退出走 `POST /auth/logout`。

## 7. Dashboard / 工作台

用户第一屏就是**分析台**（图表墙），没有中间页：

1. 顶部时间带先回答"我在看哪一批运行"：按时间窗对已取回的历史样本（`GET /api/workflows/history?limit=20`，前端过滤）筛选运行芯片；选中一次运行后，全墙数据范围标注为"本次运行 wf-2041 · 结果集为报告各小节表格（每表前 20 行）"。
2. 左侧筛选器是主角：图表类型（全局，显隐卡片）、区域/渠道（分区，过滤命中卡的表格行）、增长率下限（单卡）。每次改动，受影响卡片做 160ms 联动提示并更新"命中 x/y 行"，未命中的分区卡淡出隐藏——联动只发生在结果集内，界面各处如实写明。
3. 卡片尺寸即分析姿态：把疑似有异常的散点卡一键放大到 XL 细看，再缩回。布局不持久化（"仅本次会话有效"）。
4. 图表墙为空时进入三态分支（见 Demo 三态视图）：还没有数据 / 筛选无结果 / 读取失败，成因分开提示。

## 8. Market Analysis（完整路径）

选数据集 → 输入需求 → 发起 → 看 Agent 状态 → 看结果：

1. **选数据集**：`GET /api/datasets`（limit/offset/sort/order 真实参数；文件名搜索框走真实 `q` 参数，非全局搜索）。选中后展示画像摘要（行数、列数、缺失率，来自 `GET /api/datasets/{id}/profile`）。
2. **输入需求**：问题输入框实时校验 **2–500 字**并显示剩余字数；`max_steps` 数值输入 **1–8**（默认 6），标注"执行代理允许的最大步数"。
3. **发起**：`POST /api/analysis` → 界面立即切换为 **202 已受理**状态卡（展示返回的 workflow id），不出现"生成中…"式假进度百分比。
4. **看状态**：前端每 **1000ms** 轮询 `GET /api/workflows/{id}`，用 `step_index/total_steps`（已完成阶段数）画阶梯；轮询期间不做闪烁动画。
5. **看结果**：SUCCESS / SUCCESS_WITH_WARNINGS 后拉取 `/report` 与 `/charts/{filename}`，并给出"载入分析台"动作——把本次运行结果集接入第 7 节的筛选联动，形成"发起 → 探索"闭环。

## 9. Agent Runs（执行过程视觉化）

- **六阶段阶梯**：画像 → 规划 → 执行 → 图表 → 报告 → 校验，以"已完成台阶数 = `step_index` / `total_steps`"呈现；原始枚举值（PROFILING 等）以小字与 tooltip 保留可查证。
- **禁止阶段耗时**：后端不提供阶段级时间戳，界面上不出现任何"PROFILING 3.2s"式标注；只允许整条任务真实总耗时（`created_at → finished_at`）。
- **状态映射（10 项，中文 + 原始值）**：等待中 PENDING / 画像中 PROFILING / 规划中 PLANNING / 执行中 EXECUTING / 图表生成中 CHARTING / 报告生成中 REPORTING / 校验中 VALIDATING / 已完成 SUCCESS / 带警告完成 SUCCESS_WITH_WARNINGS / 失败 FAILED；徽标一律色 + 形（圆点/勾/叹号形状）+ 文字。
- **任务简报**：表格展示各任务 `task_id / description / status / error`，任务状态含 SKIPPED（跳过）共 6 项，失败任务行内直接展示错误文本。
- **数据来源标注**：区顶部固定一行"状态每 1000ms 轮询更新，无推送通道"。

## 10. Reports（报告呈现）

报告以"小节卡"形式落在同一 12 栏栅格里（保持本方案的空间语言），而非长文档流：

- 每小节 = 标题 + 正文 + 结论句内联 **`cites` 角标（如 T1/T2）**；点击/悬停角标显示对应引用条目（指向具体工具调用）。
- 卡底来源行固定格式：`来源：T1 = 工具调用 query_market_sales · 展示结果集前 20 行 · 数据截至 2026-08-31`——追溯链是界面的一部分，不是附录。
- 小节内嵌该节 `table`（同一张被筛选器作用的结果集表格，报告与图表墙共享数据源）。
- 校验结果独立条带：按 `severity`（error / warning / info）三档展示，使用状态色 + 形状 + 文字；附 `data_quality_notes` 与 `llm_used` 说明、`generated_at` 与"数据截至"双时间。
- 无导出、无分享：报告只能留在站内（后端不存在导出接口）。

## 11. 动效（逐条 → 业务价值）

1. **筛选联动提示**：受影响卡片 160ms 的透明度回升 + 1px 上浮，同时"影响 N 张卡"计数即时更新 → 业务价值：探索式分析最怕"改了筛选不知道动了谁"，联动高亮让因果即时可见，用户才敢连续试。
2. **状态推进提示**：运行徽标从等待中→运行中→已完成切换时 140ms 淡入位移；阶梯新增一档时 200ms 伸展 → 业务价值：1000ms 轮询的结果变化需要被"标记"而非"闪烁"，让用户确认进度确实推进了一次。
3. **档位切换**：卡片改变栅格跨度时 180ms 宽度过渡 → 业务价值：让"放大细看/缩回总览"的空间变化可追认，避免密排栅格重排时用户丢失视线焦点。
4. **hover 仅做可达性提示**（按钮底色加深、卡片描边加深），无缩放无位移 → 业务价值：高密度界面里装饰性 hover 是噪声，可达性提示才帮助鼠标驱动。
5. 轮询刷新**不做任何闪烁/呼吸动画**（静态"每 1000ms 轮询"文本代替）→ 业务价值：防止把轮询伪装成推送，界面对数据新鲜度的表达保持诚实。

写不出业务价值的动效（粒子、入场渐入堆量、数字滚动）一律不设。

## 12. 优点

- 图表墙 + 尺寸档位天然适配"数据主角 = 图表"的坐标，一屏可同时总览 6–8 张图，密度真实可用。
- **作用域标注是本方案最大的诚实创新**：筛选器明确"管到哪、影响几张卡"，把后端能力边界（无服务端聚合）翻译成了可理解的界面语言，而不是假装能查库。
- 联动高亮给出清晰的因果反馈，探索效率高；纯鼠标驱动，分析师门槛低。
- 亮色密排适合投屏到会议室大屏，BI 从业者心智迁移成本几乎为零。
- 布局切换、筛选、时间窗全为前端逻辑，落地不动后端。

## 13. 缺点

1. **"联动"预期落差风险高**：图表是静态 PNG，筛选不能重绘图内聚合口径；用户第一次看到"图表不随筛选变化"可能觉得面板"坏了"，需要多处标注来教育用户，标注本身又挤占密度。
2. **筛选器语义依赖人工预标注**：结果集列名与筛选器的映射（哪些卡含"区域"维）需要分析师运行后手工确认，未标注的筛选只能退回全局；这一步的成本和心智负担不小。
3. **12 栏 + 四档尺寸的适配工程量大**：栅格重排、档位映射、768px 下表格转"标签—值"都要专门处理，前端表现层改动比其余多数方案重。
4. **时间控件只能"装成"筛选器**：受历史接口仅 limit/offset 的限制，时间窗只是对 ≤100 条前端样本的过滤，样本外运行不可见——对把它当真 BI 用的用户存在误导风险，标注文字不可省略。
5. **表格可读性弱于 04**：卡片内小表格行数被压到前 20 行的子集，速读型用户会觉得"看不清全貌"，需要跳去报告视图补。

## 14. 适合的企业类型

- 中大型消费品/零售/电商平台的市场分析、经营分析部门：已有 Tableau/PowerBI 使用习惯，团队把"面板 + 筛选联动"当成默认工作方式。
- 咨询/研究机构中做对外汇报大屏的场景：亮色密排、可投屏、每张卡自带来源标注。
- 不适合：以键盘速读数据表为主的金融交易型团队（选 04）、只要结论一页纸的高管场景（选 08）。

## 15. 推荐指数

**★★★★（4/5）** —— 它把"不可再聚合的 PNG 结果集"做成了仍值得一遍遍推敲的分析台，作用域标注是全组最诚实的交互设计；扣一星是因为"图表不重绘"与样本级时间窗需要靠文字维持诚实，天花板受后端能力限制。
什么时候选别的：数据主角若是结构化表格且用户拒绝碰鼠标，选 04；首屏要的是"现在该看哪里"的结论态势而非图表总览，选 01；决策层只读简报不探索，选 08。

## 附：与现有代码的落地影响

全部为表现层改动，**不需要动后端**（筛选、作用域、尺寸档位、时间窗均为前端对既有接口返回值的再处理，未新增任何接口需求）。

- `app/web/tokens.css`：新增 12 栏栅格令牌（列数、`gap:10px`）、面板宽度 `--filter-panel-w:260px`、图表系列色 `--chart-c1..c6` 与状态色令牌（两组分离定义）；亮色主题变量沿用现有值微调。
- `app/web/app.css`：主区从现有单列布局改为 12 栏 `grid`（`.grid-12` + `.span-3/.span-4/.span-6/.span-12`）；新增筛选面板栏、时间控件带、卡片档位按钮组、联动动画（160ms）、768px 折叠与表格"标签—值"堆叠规则。
- `app/web/index.html`：新增左侧筛选面板容器（作用域徽标 + "影响 N 张卡"占位）、顶部时间带与运行芯片条、图表墙骨架。
- `app/web/app.js` 涉及的渲染函数：
  - `renderCharts` / `loadChartsFor` / `clearCharts` / `showChartsEmpty`：PNG 按 12 栏卡片渲染，加"图片占位 + 真实 URL 路径文本 + 尺寸档位"结构；`showChartsEmpty` 改为"本次运行无图表"横带形态。
  - `renderReportInto` / `renderTable`：`sections[].table` 拆分内联到各卡与报告小节卡，登记每表列名供筛选器映射；`cites` 角标交互保留。
  - `paintSteps`：阶梯改为本方案的台阶样式（仍只用 `step_index/total_steps`）。
  - `startPolling` / `pollOnce`：逻辑不变，新增状态变化时 140ms 推进提示钩子。
  - `fetchHistory` / `loadHistory` / `historyRow`：返回的 `items` 缓存为前端样本，供时间窗过滤与运行芯片渲染（仍只以 limit/offset 取数）。
  - `renderDatasetRows` / `fillDatasetPicker`：市场分析视图数据集选择沿用，新增画像摘要展示。
  - 新增前端模块：筛选状态与作用域映射、联动计算、档位切换（会话级、不持久化）。
- `app/web/login.html` / `login.css` / `login.js`：改为"品牌带 + 表单"两栏结构，补 `needs_bootstrap` 模式切换与 429 `Retry-After` 提示（后端已有对应行为）。
