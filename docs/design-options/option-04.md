# 方案 04：金融机构数据终端

> 坐标（来自差异矩阵，不得偏离）：**无侧栏**；顶部窗格标签 + 命令面板（Ctrl/Cmd+K）+ 键盘可达全界面；首屏 = 多窗格分屏（2×2，可切 1×3）；密度**极高**；数据主角 = **高密度表格 + 状态时间线**；主题**暗**；立场：**熟练用户不该碰鼠标**。

---

## 1. 设计名称

**MIS Terminal — 金融机构数据终端风格**（市场情报终端）。命名取自 Bloomberg / Refinitiv 终端的操作范式：窗格（Block）分屏、单色底、语义色极少、键盘优先。产品全称仍为 AI Market Intelligence Studio，界面署名 `MIS>TERM`。

## 2. 核心设计理念

这套方案表达的是一台**给熟练用户的读数机器**。市场分析师每天要看几十次运行状态、翻上百行数据、比对十几份报告；对TA而言，鼠标移动 300 像素去点一个按钮就是 300 次微小的摩擦。所以界面被压缩成三样东西：**窗格（数据）、命令行（意图）、状态栏（反馈）**——装饰、容器、留白全部让位给字符与数字。

暗色不是氛围，是工效：盯盘场景长时间注视高密度数字，暗底 + 等宽数字 + 涨/跌双色能把视觉疲劳和误读率压到最低（NN/g 实测：暗色利于长时间盯盘与眩光人群；同时保留亮色切换建议，见缺点 3）。彭博配方被完整继承：**单色底 + 极少量语义色 + 等宽数字（tabular-nums）+ 无圆角 + 涨/跌双色**；Grafana 的字段级 unit/decimals/no-value 配置直接落到表列定义上——缺失值显示 `N/A` 而非 `—` 或空白，因为空白在密排表里会被读成 0。

一切"看起来高级但 slows down 熟练用户"的东西都被剔除：没有卡片阴影、没有动画过渡（除状态推进的 120–200ms 位移）、没有需要加载的插画。新用户前 10 分钟会觉得它生硬，第 10 天起会觉得别的界面都太慢——这就是本方案要服务的对象。

## 3. 视觉关键词

单色底、等宽数字、无圆角、双色涨跌、密排表格、窗格标签（Block Label）、终端绿只在错误时出现。

## 4. 色彩体系

所有对比度按 WCAG 2.1 对 `--bg0 #0A0D12` 计算，正文均 ≥ 4.5:1。

**基底（单色底，杜绝大面积渐变/发光）**

| 令牌 | hex | 用途 | 对比度 |
| --- | --- | --- | --- |
| `--bg0` | `#0A0D12` | 桌面底色（终端屏幕） | — |
| `--bg1` | `#10151C` | 窗格底 | — |
| `--bg2` | `#161D26` | 表头 / 选中行 / hover | — |
| `--line` | `#27303D` | 1px 分隔线（唯一的"容器"手段） | 非文本 ≥3:1 |
| `--ink` | `#D8DFE8` | 正文 | ≈15:1 |
| `--ink2` | `#9AA5B4` | 次要文字/说明 | ≈7.8:1 |
| `--amber` | `#FF9F2E` | 唯一强调色：焦点环、当前窗格标签、命令面板光标 | ≈8.7:1 |

**状态色（语义三色 + 中性，与图表色完全隔离，不得互用）**

| hex | 含义 | 三重编码 |
| --- | --- | --- |
| `#3DD68C` | 成功 / 涨 ↑（≈10.4:1） | ■ + `✓` + 文字"已完成" |
| `#FF6B6B` | 失败 / 跌 ↓（≈7.0:1） | × + `✕` + 文字"失败" |
| `#FFD166` | 带警告 / error severity（≈12:1） | ▲ + `!` + 文字"带警告完成" |
| `#7FB3FF` | 运行中 6 态（≈8.2:1） | ◐ + 文字阶段名 |
| `#9AA5B4` | 等待中 / SKIPPED | ○ / ◇ + 文字 |

10 个工作流状态原样可查证：中文主文案 + 等宽次要文字保留原始枚举（如 `运行中` + `EXECUTING`），`PENDING→等待中 / PROFILING→画像中 / PLANNING→规划中 / EXECUTING→执行中 / CHARTING→图表中 / REPORTING→报告中 / VALIDATING→校验中 / SUCCESS→已完成 / SUCCESS_WITH_WARNINGS→带警告完成 / FAILED→失败`；任务 6 态含 `SKIPPED→已跳过`。

**图表色（仅用于内联 SVG，与状态色不同相位，禁止表达状态）**

`#59C2D6`（主序列）· `#6D9BD3`（对比序列）· `#8FA1B3`(参照) · `#9187D6`（第四类）。全部 ≥3:1（非文本 UI）。后端 PNG 图表不走此表——见第 10 节的"分层"处理。

**圆角：0。全界面不允许 border-radius。**

## 5. 页面布局

- **导航**：无侧栏、无面包屑。顶部 28px 窗格标签条（`F1 终端 | F2 分析 | F3 运行 | F4 报告 | F5 三态`，实际键位为数字 1–5）+ 右侧健康灯（`GET /api/health`）+ 声明区。命令面板（Ctrl/Cmd+K）是唯一"全局入口"，不存在全局搜索（后端没有）。
- **首屏**：2×2 窗格矩阵。P1 数据集（高密度表格，粘性表头 + 列过滤 + 分页按钮，分页映射 `limit/offset` 真实参数，**不用前端假虚拟滚动**）；P2 最近运行（`/api/workflows/history`，仅 limit/offset）；P3 服务健康 + 会话；P4 快速分析入口。顶部 `[2×2] [1×3]` 两键切换：1×3 为单列三窗格，P3 隐藏（健康信息顶栏已有，不重复占屏）。**布局只在本会话生效，界面写明"布局不持久化（后端无保存视图能力）"**。
- **栅格**：1440px 起，列宽按字符数定（终端思维），窗格内边距 6px，行高 20px，字号 12–13px。
- **断点**：768px 以下窗格纵向堆叠，表格由 JS 把表头名写入 `data-th` 转"标签—值"堆叠行，禁止整页横向滚动。
- **底部状态栏**（22px）：左 = 模式指示（NORMAL/DETAIL/PALETTE，vim 式），中 = 键盘提示，右 = 声明与登录原型入口。

## 6. 登录页面

- 布局：全屏 `--bg0`，左上角一个 24 列宽的"登录终端框"：`MIS>TERM` 字标 + `auth: login` 提示行 + 用户名/密码两行**行内输入**（无卡片、无居中 hero，label 用行前缀 `user:` `pass:`）。回车提交。品牌表达就是这台终端的"冷"：一句话主张"把市场数据变成可追溯的决策依据"以小号等宽体打在框底。
- `needs_bootstrap` 模式：健康检查返回未初始化时，登录框整体切换为 `auth: bootstrap` 标题 + 单个"创建首个管理员"表单（`POST /auth/bootstrap`），并显示一行说明 `首次部署 · 尚无管理员账号`；两种模式互斥、由同一区块原地替换，不做跳转。
- 错误：统一文案"用户名或密码错误"（与后端一致，不泄露账号存在性）；`429` 时禁用提交并显示 `Retry-After` 剩余秒数（真实字段，不是编造倒计时文案）。会话 8h 过期后回到本屏并提示"会话已过期"。
- 预留（后端已有、前端未做）：`修改密码`（`POST /api/auth/password`）与 `会话列表`（`GET /api/auth/sessions`）以命令面板命令 `passwd / sessions` 的形式出现在设计里，不占首屏。

## 7. Dashboard / 工作台

用户第一屏就是 2×2 窗格，没有"欢迎回来"式废话。信息组织按熟练用户的动线：**左手数据资产（P1）、右手运行历史（P2）、右下发起入口（P4）、右上角平台是否活着（P3）**。P1 表格列：文件名（等宽）/ 行数（千分位 tabular-nums）/ 列数 / 上传时间，排序映射 `sort=uploaded_at|rows` 真实参数，过滤框映射 `q`。选中行（↑↓ 或 j/k）后按 Enter → 右侧滑出详情覆盖层（Bloomberg 的 QR 语义）：显示数据集画像摘要（行数/列数/语义类型/缺失率 top 列/告警），来源 `GET /api/datasets/{id}` + `/profile`。数字精度按 Grafana 式字段配置思想呈现：`rows` 整数千分位、缺失率固定 2 位小数带 `%`、无值一律 `N/A`。所有分页/排序/过滤控件在原型中为视觉占位并标注真实参数名。

## 8. Market Analysis

完整路径：`选数据集 → 输入需求 → 发起 → 看 Agent 状态 → 看结果`，全程不出终端。

1. P4（或 F2 全屏分析视图）：数据集行内选择器（输入 `ds:` 或点击列表）+ 问题输入区（`question`，2–500 字，右下角实时字数 `132/500`）+ `max_steps` 数字选择（1–8，默认 6）。
2. 发起 = `Ctrl+Enter`（也提供 `[发起]` 按钮给鼠标用户）。202 返回后**当前窗格原地**切为运行态（F3），不跳页——终端思维里"新任务占据一个窗格"。
3. 运行状态：1000ms 轮询 `GET /api/workflows/{id}`，窗格顶部显示真实轮询时间戳 `上次轮询 14:02:11 · 间隔 1000ms`（明示非推送）。
4. 完成后按 Enter 或 `[R]` 打开报告窗格。禁止出现任何导出/分享入口（后端没有）。

## 9. Agent Runs

执行过程 = **一条状态时间线 + 一张任务表**，两窗格并排（1×3 时纵向）。

- 阶梯条：`step_index / total_steps` 已完成阶段数（如 `6/8`）画实心块，未完成画空心块；当前阶段名用 `◐ 运行中 EXECUTING` 三重编码。**没有任何阶段耗时**——后端只有 `created_at/finished_at`，阶段时间戳不存在。
- 真实耗时只有一处：整条任务 `总耗时 = finished_at − created_at`（完成后）或运行中的实时差值，明确标注"整条任务耗时（真实可算）"。
- 状态时间线：以本次会话内轮询**观察到的状态推进**为节点（PENDING→PROFILING→…），每块 1px 边框 + 形状 + 文字；节点标注的是"观察时刻"而非"阶段起止"，并在旁注 `阶段边界以轮询粒度近似（1000ms）`。这是诚实的退化：见缺点 1。
- 任务表：`task_id / description / status（6 态中文+原枚举）/ error`，FAILED 行错误列红色截断、Enter 展开。
- `llm_used=false` 时报告窗格显示降级标注（真实字段）。

## 10. Reports

- 双窗格：左 = 报告文档流（`title / summary / sections(heading+text) / data_quality_notes`），右 = **证据窗格**（citations 全列表 + `cites` 对应工具调用 + 校验结果 + `generated_at` + "数据截至"）。
- 可追溯 = 本方案主角而非装饰：正文角标 `[T1]` 用琥珀色等宽上标，Tab 可达；Enter/点击 → 证据窗格对应行高亮并滚动定位；hover 时行内即时显示来源摘要。角标与来源行**同时**存在，缺来源行的段落不允许渲染。
- 暗色可读性专门设计（长文在暗底最大的坑是行疲劳）：正文窗格行高 1.9（表格区 1.2 不变，**两种节奏分区**）、字号升一档至 14px、行长 72 字符定宽、`--ink` 不用纯白降眩光；校验 severity 用色+形+字三重（`error ▲ #FF6B6B / warning △ #FFD166 / info ○ #7FB3FF`）。
- 图表：后端 PNG 是**浅底 matplotlib 图**，暗壳内直接贴会造成"白斑"反模式。采用**分层**：图窗外壳仍暗色，图区本身衬 `#E9ECF1` 浅底容器 + 1px `--line` 边框 + 下方说明行（图型、来源、截至时间），文档与 Demo 均明示这一取舍；图表色仅用于内联 SVG 示意图，不用于重绘后端图。

## 11. 动效

每条都有业务理由，reduced-motion 全关：

1. 状态块推进（等待→运行→完成）：160ms 透明度+2px 位移 —— 用户扫一眼即知"哪一格刚变了"，轮询界面里变化点即信息。
2. 选中行移动：0 动画（即时）—— 键盘用户的移动速度就是界面节奏，加动画是负反馈。
3. 命令面板开合：120ms 高度展开 —— 确认"进入模式"的心理边界，防止误按后不知身在何处。
4. 角标→证据行高亮：180ms 背景扫过 —— 建立"数字↔来源"的因果视线。
5. 轮询刷新：**不做任何闪烁动画**（刷新是常态，闪烁等于噪声）；只更新时间戳文字。

## 12. 优点

1. 熟手效率天花板：全程手不离键盘，读一屏顶别的方案三屏；10 套方案中"每日 50 次以上使用的重用户"留存体验最好。
2. 密度直接服务产品核心卖点——可追溯：`cites` 角标、来源行、枚举原值都在同一屏内可核对，不需要滚动拼图。
3. 暗色 + 等宽数字 + 涨/跌双色 + 三重编码，是长时间盯盘和色盲场景下最优的误读控制组合。
4. 无侧栏、无卡片、零装饰 → 表现层实现极简（全是 1px 线和字重），CSS 体量小、渲染快。
5. 窗格模型天然对应真实接口边界（一窗格一接口），前端状态管理清晰。

## 13. 缺点

1. **键盘可达"全界面"在本期 Demo 中未完全兑现**：实装范围 = Cmd/Ctrl+K 面板（过滤/上下/Enter/Esc）、数字键 1–5 切视图、↑↓/j/k 表格选行、Enter 开详情、Esc 回退、`[2×2]/[1×3]` 布局切换（按钮+面板命令）。未实装：面板命令是硬编码清单而非动态索引全部控件、窗格间 Vim 式焦点跳转（`Ctrl+W` 系）、`:` 行命令模式。落地需按 WAI-ARIA APG 逐控件补，估计 3–4 人周；文档不掩饰这一点。
2. **阶段时间线因后端无阶段时间戳而退化**为"会话观察到的状态推进 + 轮询粒度近似"，比概念图弱；要恢复完整时间线必须后端在 `WorkflowState` 增记阶段时间戳（改动 `POST /api/analysis` 流水线与轮询 DTO），属新增能力而非表现层改造。
3. **暗色与现有设计系统正面冲突**：`tokens.css` 明确"故意不在这里启用"暗色（matplotlib 浅底 PNG + 数字可核对的展示取向），NN/g 也提示多数场景 light mode 表现更好。本方案若上生产必须**双主题**而非单暗，切换机制（新增 `[data-theme]` 令牌覆盖块）本身是额外工程量，且每屏都要重新验一遍对比度。
4. 新手不友好是真实代价：无引导、无空态插画，首周培训成本高于其他 9 套；不适合低频用户组织。
5. 布局不持久化（后端无保存视图），终端用户最在意的"我的屏幕布置"每次都要重排，削弱方案灵魂体验——只能寄望 localStorage 级补偿，但那不是"后端能力"，文档与界面均如实声明。
6. 极高密度在小屏（768px）严重降级，只能纵向堆叠，"多窗格"身份消失；本方案实质上要求 ≥1366px 主战场。

## 14. 适合的企业类型

金融机构、量化/宏观研究团队、数据服务商内部分析台、任何有专职分析师且把该平台当**每日主力工作台**（而非偶尔看看）的组织；也适合多屏大屏工位文化的外贸/能源/咨询数据组。不适合低频使用、以业务方自助看报告为主的组织。

## 15. 推荐指数

**★★★★（4/5）** —— 理由：在"高频专业用户"这个场景里它是 10 套中唯一把读屏效率做到极限的方案，且与产品"每数字可追溯"的卖点同构；扣一星是因为暗色与现有 tokens.css 的正面冲突、阶段时间线的后端缺口和新手成本。

**何时选它而不选别的**：用户是每天盯着它 6 小时以上的分析师 → 选 04 不选 07（07 亮色鼠标驱动适合探索）、不选 09（09 面向平台运维者看队列与事件流，04 面向业务分析者读数据窗格）；若用户每周只用两次 → 选 06/08，别用 04 惩罚他们。

## 附：与现有代码的落地影响

**结论：不需要动后端。** 所有入口映射到 2.1 已有接口；命令面板中 `passwd / sessions` 对应后端已有、前端未做的两个接口，属纯增量。

1. **`app/web/tokens.css` —— 必须新增暗色主题层**。该文件目前白纸黑字"深色模式：故意不在这里启用"。本方案要求双主题，落地方式遵守它的既有架构：不改兼容层任何 hex，在品牌层 `--ds-*` 之外新增 `[data-theme="dark"] { --ds-color-ink: …; }` 覆盖块（值仍回指兼容层或新增暗色专用 hex 段落），主题切换由 `<html data-theme>` 控制。注意文件自身声明的顺序铁律：tokens.css 排页面样式之前，覆盖块才能生效；且需同步扩展 `tests/test_frontend.py` 的 `_css_tokens()` 解析（它只取第一个 `:root`，新增属性块不会破坏它，但暗色令牌需另写断言）。
2. **`app/web/app.css`**：新增窗格栅格（`2×2/1×3` 两套 grid 模板）、粘性表头、28px 标签条、状态栏、`border-radius` 全局清零、tabular-nums；两套密度节奏（表格 20px 行高 / 报告 1.9 行高）。
3. **`app/web/index.html`**：DOM 从"页面流"重排为"窗格容器 + 面板 + 覆盖层"；无新增后端入口。
