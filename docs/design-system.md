## 0. 怎么用这份文档

### 0.1 三种读者，三个入口

| 你要做的事 | 从这里开始 | 必须遵守的硬规则 |
| --- | --- | --- |
| 改一个颜色 / 间距 / 字号 | 第 2 章（令牌表） | 只改 `tokens.css`，不在页面里写死值 |
| 新增一个组件或页面 | 第 8 章（组件）、第 15 章（执行步骤） | 先查有没有同类组件，先复用再新增 |
| 评审 / 交接 / 验收 | 第 11 章（可访问性）、第 16 章（已知问题） | 结论必须能重跑脚本复现 |

### 0.2 样式分三层，禁止跨层写死

```
第 1 层  兼容层      tokens.css 里非 --ds-* 的令牌（71 个）
                     = app.css 现状 :root 的逐字复制。存在的唯一理由是
                       tests/test_frontend.py 只认 app.css 的 :root，
                       在测试改口径之前必须保持"同名字、同值"。
   ↓ 只允许向下引用
第 2 层  品牌层      tokens.css 里的 --ds-* 令牌（137 个）
                     语义命名：--ds-color-ink-subtle 而不是 --n-500。
                     页面与组件只许用这一层。
   ↓
第 3 层  组件层      app.css 里的 .card / .btn / .table-wrap 等
                     只写布局与结构，颜色尺寸一律 var(--ds-*)。
```

**为什么要有第 1 层**：`tests/test_frontend.py:431-435` 的 `_css_tokens()` 用
`:root\s*\{(.*?)\n\}` 只抓 `app.css` 的第一个 `:root` 块，任何 `var()` 引用的名字
必须在里面能找到（否则报"用了未定义的令牌"）。所以本轮的策略是**兼容而不是搬迁**：
`tokens.css` 把现状令牌原样再声明一遍，两处值逐字相同，视觉零变化；等测试口径升级为
"先读 tokens.css 再读 app.css 覆盖"之后，再删 `app.css` 的 `:root`（见第 15.3 节）。

### 0.3 引用顺序（新页面必须照抄）

```html
<link rel="stylesheet" href="/static/tokens.css">   <!-- 必须先 -->
<link rel="stylesheet" href="/static/app.css">      <!-- 页面样式在后 -->
```

顺序不是风格问题：`app.css` 的 `:root` 与媒体查询里的 `:root` 覆盖
（`app.css:1040` 的 `--sidebar-w: 190px`、`app.css:1048` 的 `--topbar-h: 52px`）
靠"后出现者胜"生效。`tokens.css` 在前，`app.css` 才能继续覆盖它，现状零变化；
反过来写会让窄屏侧栏宽度失效。

`index.html:11-12` 已是这个顺序。**新建 `login.html` 时必须自带
`tokens.css` + 自己的 `login.css`**（登录页不加载 `app.css`，否则会继承工作台布局）。

### 0.4 两个可重跑的核对脚本

```powershell
# 令牌对账：兼容层是否与 app.css 逐字同值、品牌层是否自洽、文档表是否对得上
& ".\.venv\Scripts\python.exe" ".tmp\design\token_parity.py"

# 对比度实测：WCAG 2.1 比值，正文 ≥4.5、大字 ≥3.0、非文本 UI ≥3.0
& ".\.venv\Scripts\python.exe" ".tmp\design\contrast_check.py"
```

两个脚本都会打印结论并把报告写到 `.tmp/design/*.txt`。退出码 `0` = 全过，
`1` = 有问题（对账脚本报违规，对比度脚本报未达标）。**对比度脚本本轮退出码是 1**，
原因见 16.1（存量问题，不是本轮引入）。

## 1. 视觉定位与设计原则

### 1.1 一句话定位

**给做决策的人看的市场情报工作台**：像金融终端一样可靠，像研究报告一样好读，
但绝不假装自己知道得比数据多。

### 1.2 五条原则，每条都能被检验

| 原则 | 落地表现 | 怎么算违反（评审时直接判红） |
| --- | --- | --- |
| 数据可信优先 | 每个数字都能追到后端字段；比率标基准（占谁的比例）、不确定的标"样本不足" | 前端算出后端没有的数字；把 AI 解释写成"事实" |
| 过程透明 | 六阶段执行状态如实显示，等待时解释"在等什么" | 用 `setTimeout` 假装进度；失败时只写"出错了" |
| 克制的商务感 | 单色品牌蓝 + 中性灰阶；阴影只用于层级（3 档）；圆角 ≤10px | 大面积渐变、发光边框、卡片套卡片、装饰性插画 |
| 信息密度有节奏 | 表格行高 7px 纵向留白；卡片内 20px；区块间 20px | 所有区域都是一样的白矩形；为了"高级感"把内容摊到 3 屏 |
| 中英混排的专业度 | 品牌区英中双行；界面文案中文；数字等宽对齐 | 中文里夹杂无意义英文缩写；数字不对齐导致竖着没法比 |

### 1.3 方向融合说明（哪条来自哪套方案）

- **来自"高端数据产品与商业情报平台"（主）**：品牌蓝阶 + 中性灰阶的双色系统；
  顶栏深色（`--brand-900`）压重品牌识别；页面标题 25px/600 的编辑部式排版；
  报告区 78ch 行宽；图表白底不透明、图注带单位。
- **来自"信息密度纪律"**：指标卡最小 150px 自动铺开而不是一行四个大卡；
  表格 sticky 表头 + 数字右对齐；字段结构用 `table.kv` 的 34% 标签列。
- **来自"智能体执行过程透明"**：`.steps` 六阶段（理解→规划→执行→可视化→报告→校验）
  四态可视；`.tasklist` 事件流水带 `tid`；错误框给"重试"而不是只给红字。

### 1.4 明确不做的事（每条给替代做法）

| 不做 | 为什么 | 替代做法 |
| --- | --- | --- |
| 大面积渐变 / 霓虹光效 | 与"数据可信"冲突，且离线环境无法保证渲染一致 | 纯色 + 1px 边框 + 三级阴影 |
| 装饰性卡片（无业务内容的图/文块） | 占屏幕但不提供信息 | 空位就留白；需要引导时用 `.empty` 给下一步动作 |
| 无功能的图标和按钮 | 用户点一次就失去信任 | 图标必有 `aria-hidden` 或 `title`；按钮必须有真实动作（见 9.6 导出） |
| 深色模式（本期不做） | ① 后端 matplotlib 出的是浅底 PNG，图区会出现白斑；② 全站对比度要重算；③ 离线三文件没有主题切换接口。决定原文在 `app.css:1108-1126` | 令牌层已把深色候选值算过一遍（`.tmp/design/contrast_report.txt` 第 2 节，25 对全部达标），将来做的时候换 `:root` 覆盖即可 |
| 需要网络资源的字体 / 图标库 | 项目硬约束：无构建、无 CDN、离线可用 | 系统字体栈（`--font`）+ 内联 SVG symbol（`index.html:30-56` 共 18 个图标） |

## 2. 设计令牌体系

### 2.1 命名规则

```
--ds-<类别>-<角色>[-<状态>][-<强度>]
     │        │        │         └ surface / line / strong / muted / faint
     │        │        └ hover / disabled / selected
     │        └ ink / surface / line / action / on-action / canvas ...
     └ color / font / fs / weight / leading / space / radius / border-w /
       elevation / z / dur / ease / bp / content-max / chart
```

命名只用**语义**，不用外观（`--ds-color-danger` 而不是 `--ds-color-red`）：
将来暗色模式或品牌换色时，名字不用改，只有值跟着主题变。

### 2.3 兼容层为什么要"多余一份"

兼容层的 71 个令牌是本项目的历史包袱，也是本轮最关键的兼容决策。三个必须知道的点：

1. **值必须逐字相同**。对账脚本的第 2 节会逐名字比对，差一个字符就判红。
   改 `tokens.css` 里的兼容层值 = 改了两套视觉，先改 `app.css` 再同步这里。
2. **品牌层引用兼容层，不引用裸值**。`--ds-color-canvas: var(--n-50)` 而不是 `#f7f7f6`，
   这样删除 `app.css` 的 `:root` 时只需要改兼容层一处。
   > **⚠️ 口径更正（2026-10-17，主控裁定 D-3）**：上面这半句和"待删除的历史债"那个说法**作废，不许再写**。
   > `app.css` 自己那份 `:root` 副本**必须保留**：`tests/test_frontend.py` 的禁用态按钮对比度断言
   > 是**直接静态解析 `app.css` 内 `:root` 的 hex** 去算的（`:461` 起取块、`:547` 起取 `.btn--primary` 规则），
   > 把 hex 搬空 → 断言**假红**（配色根本没变，测试先死）。这块副本的身份是**被测试钉住的第二事实来源**，不是债。
   > 新增令牌**只进 `tokens.css`**，不要往副本里加；两边同名同值由
   > `tests/test_frontend_command_center.py::test_root_token_copies_stay_identical` 守着。
   > 裁定原文见 `docs/refactor/06-leader-decisions.md` D-3，落地记录见 `docs/COMMAND_CENTER_MIGRATION.md` §5。
3. **有 4 个颜色只能先由品牌层自己持有**（`--ds-color-bar-dot-ok/warn/err`、
   `--ds-color-danger-strong`）：它们在 `app.css` 里今天就是裸 hex
   （`app.css:282-284`、`app.css:775`），没有对应的 :root 令牌可引用。
   对账脚本把这 4 个列为"已申报例外"，`app.css` 瘦身替换后必须清零（见 15.3）。
   > **已清偿（Wave A 的 1C 段）**：这 4 个 hex 已迁进 `tokens.css` 兼容层（`--bar-dot-ok/warn/err`、`--err-deep`），
   > `app.css` 现在这三条 `.dot--*` 规则里写的就是 `var(--ds-color-bar-dot-*)`，"已申报例外"清零。
   > **顺带一条实证**：原文那两个行号在今天指向的已经不是这些规则（三条 `.dot--*` 实测在 `app.css` 的 292/293/294，
   > `.error-box .detail` 在 914；Wave A 当时量到的却是 299/300/301/858）—— 同一批锚点在几天里漂了两次。
   > 这就是本仓库新文档改用**符号名**（选择器 / 令牌名 / 函数名）引用的全部理由，
   > 量化数据与 `check_docs.py` 的管辖边界见 `docs/COMMAND_CENTER_MIGRATION.md` §8。

### 2.4 断点令牌只能给 JS 读

`--ds-bp-sm/md/lg/xl` 存在的意义是**留一个统一口径**，不是给 CSS 用：
CSS 规范不允许 `var()` 出现在媒体查询条件里，所以 `@media` 必须写字面量，
而这些字面量必须与令牌一致：**480 / 760 / 1080 / 1320**。
改断点时要改两处（媒体查询 + 令牌），第 13 章列了每个断点的完整行为。

## 3. 色彩规范

### 3.1 品牌蓝阶（`--brand-*`）：只有两个用途

| 档位 | 值 | 允许的用途 | 禁止 |
| --- | --- | --- | --- |
| `--brand-50` | `#f4f7fb` | 选中项底色、上传区 hover 底、摘要块底 | 大面积铺页面底（会显脏） |
| `--brand-100` | `#e6edf7` | 输入框聚焦光晕、顶栏次要文字（反白） | 当文字色用 |
| `--brand-200` | `#c9d9ee` | 主按钮禁用边框、顶栏最弱文字（反白） | 当文字色压浅底 |
| `--brand-300` | `#9bb8dd` | 选中/hover 边框、上传区悬停边框 | 承载文字 |
| `--brand-400` | `#648fc7` | **当前无消费方**（`app.css` 里没有引用） | — |
| `--brand-500` | `#3d6fae` | 焦点环（2px outline）、聚焦边框、头像底 | 主操作按钮（对比度不够 7:1） |
| `--brand-600` | `#2c5590` | **主操作色**：主按钮底、链接、当前导航项标记、图标强调 | 写长段正文 |
| `--brand-700` | `#234371` | 主按钮 hover、链接 hover、选中文字 | 大面积底色 |
| `--brand-800` | `#1c3557` | 顶栏下边框、用户菜单按钮 hover 底 | — |
| `--brand-900` | `#14263f` | 顶栏底、顶栏上的反白文字底 | 内容区底色（太重） |

品牌蓝只承担"可操作 / 已选中 / 品牌识别"三类语义。**状态色一律不用品牌蓝**，
`--info-*` 是状态语义（例如"信息提示"），`--brand-*` 是交互语义，两者值相同也不许互相替代。

| `--n-150` | `#e9e9e7` | — | — | 卡片内部分隔线、图表网格线 |
| `--n-200` | `#e0e0dd` | — | — | **常规边框**（卡片、表格、徽章） |
| `--n-300` | `#c9c9c5` | — | — | 装饰性分隔（空状态虚线框、注释竖线） |

### 3.3 状态四色 × 三件套

每个状态都由三个令牌组成一套，**必须成套使用**，不许跨状态拼：

| 状态 | 文字 `*-fg` | 底色 `*-bg` | 边框 `*-line` | 用于 |
| --- | --- | --- | --- | --- |
| 成功 | `--ok-fg` #1a6b42 | `--ok-bg` #eef6f1 | `--ok-line` #bcdcc9 | 上传成功、任务完成、校验通过 |
| 警告 | `--warn-fg` #7a5300 | `--warn-bg` #fdf6e7 | `--warn-line` #e6cf95 | 数据质量问题、样本不足、降级 |
| 危险 | `--err-fg` #9b2c22 | `--err-bg` #fceeec | `--err-line` #edbfb8 | 请求失败、校验不通过、分析失败 |
| 信息 | `--info-fg` #2c5590 | `--info-bg` #eef3fa | `--info-line` #c9d9ee | 中性提示、运行说明 |

各自的对比度（压自己的 `*-bg`）：成功 7.47、警告 8.29、危险 7.17、信息 7.48（详见报告）。
错误详情的长文本用更深的 `--ds-color-danger-strong` #7a2b23（8.46:1），
它在 `app.css:775` 今天就是裸 hex。

**颜色不是唯一载体**（硬规则）：状态必须同时有文字或图标表达。项目已有实现：
`.badge` 里图标 + 文案、`.steps__state` 写出"已完成/进行中"、
`.banner h4` 带图标、顶栏 `.dot--ok/warn/err` 配 `title`。

### 3.4 反白配色（顶栏）

顶栏是深底（`--brand-900`），它的"层级"只能靠明度差，不能靠灰阶：

| 令牌 | 值 | 对比度（压 `--brand-900`） | 用途 |

### 4.5 数字与单位排版

- **数字一律等宽**：`font-variant-numeric: tabular-nums` 用在

  理由：用户的真实动作是"竖着比一列数字"，比例字体会让小数点上下错位。

- **单位比数值小一档**：`.kpi__unit` 用 `--fs-sm` + 字重 400（:805），不抢数值的权重。

## 5. 空间与形状

### 5.1 间距：4px 基准，8 档

| 令牌 | 值 | 典型用途 |
| --- | --- | --- |
| `--sp-1` | `4px` | 图标与文字 gap、面包屑下边距、指标标签下边距 |
| `--sp-2` | `8px` | 徽章左右内边距、时间线步骤间距、列表行间隔、中文副名上边距 |
| `--sp-3` | `12px` | 卡片内元素间距、表格单元格左右内边距、指标卡之间的 gap、列表行内边距 |
| `--sp-4` | `16px` | 卡片内边距（指标卡/上传区/banner/空状态）、图表 grid gap、区块下边距 |
| `--sp-5` | `20px` | 卡片正文内边距、区块间距、页面左右内边距、页面标题下边距 |
| `--sp-6` | `24px` | 内容区上边距、会话门卡片内边距、大区块分隔 |
| `--sp-8` | `32px` | 大块留白（当前用于设置页分组） |
| `--sp-10` | `40px` | 内容区底部留白（`app.css:488` 的 `padding: 24px 24px 40px`） |

**留白节奏**（页面从上到下）：顶栏 56 → 内容区上边距 24 → 页面标题块下边距 20 →
卡片之间 20 → 卡片内边距 20 → 卡片内元素 12 → 图标与文字 4。
不允许出现"随手写的 18px / 15px"：要么用档位，要么说明为什么新增一档。

### 5.2 圆角：大面块 ≤6px，胶囊与圆形是仅有的两个例外

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--r-sm` | `4px` | 骨架屏、图表图片、注释块、图标底 |
| `--r-md` | `6px` | 按钮、输入框、表格容器、指标卡、banner、时间线步骤 |
| `--ds-radius-surface` | `6px` | 大面块：卡片、上传区、用户菜单、会话门盒子、通用弹窗 |
| `--r-pill` | `999px` | 徽章、工作区标记、用户菜单按钮、标签按钮 |
| `border-radius: 50%` | 几何常量 | 只给状态圆点与头像（不做成令牌：它不可调，不是设计变量） |

**裁决（采纳 D1 线框纪律）：大面块圆角 ≤6px。** 理由：10px 放在 1320px 宽的卡片上偏软，
而且同框时和 6px 的控件圆角套在一起会出现"圆角套圆角"的黏连感；6px 与控件圆角同值，
整个界面只有"6px 面块 + 4px 小元素 + 胶囊 + 圆形"四种形状，纪律更强。具体做法：

- 兼容层的 `--r-lg`（`10px`）**值不动**（它与 `app.css` 现状必须逐字同值，动它会让 §2.3 的对账判红），
  而是新定义 `--ds-radius-surface: 6px` 让它在第二阶段替换 `app.css` 里的 4 处 `var(--r-lg)`：
  `app.css:316`（会话门盒子）、`:396`（用户菜单）、`:513`（卡片）、`:678`（上传区）。
- 这 4 处替换是**可见的视觉变更**（10px → 6px），属 frontend-engineer 的写权限，需要 Lead 排期；
  `--r-lg` 在此之前是"待退役的兼容值"，新组件不得使用。
- 规则：**同一个卡片内部不要出现和卡片同值的圆角再套一层**。卡片 6px，里面的按钮也是 6px，
  所以卡片内的"块中块"（图注、注释块）改用 `--r-sm`（4px），或者只用 1px 边框分隔，不靠圆角造层次。

### 6.4 长文可读性

`#report { max-width: var(--ds-measure-report) }`（当前 `78ch`，实现在 `app.css`）：

**行宽一律引用令牌：measure = `var(--ds-measure-report)`（当前 78ch）**，不要在组件里手写数字。
78ch 在中文下能放几个字不是固定值 —— `1ch` 是当前字体里数字「0」的宽度，中文是 1em，所以随字体变。
实测（`.tmp/design/measure_report_line.py`，正文 14px，原始输出 `.tmp/design/measure_report_line.txt`）：

| 字体 | 字号 | 1ch | 1em | 78ch | ≈ 中文字/行 |
| --- | --- | --- | --- | --- | --- |
| Microsoft YaHei（`--font` 首选） | 14px | 8.00px | 14.00px | 624px | **44.6 字** |
| SimSun | 14px | 7.00px | 14.00px | 546px | **39.0 字** |

即 **78ch ≈ 39–45 个中文字**，都落在中文长文阅读的舒适区（30–45 字），所以 78ch 不改
（决策记录里写的 76ch 以令牌为准，ux-architect 会把那处改成引用本令牌）。
窄屏（≤760px）取消这个限制，因为屏幕本身已经比它窄；**新增长文阅读区必须继承这个宽度**，
不要让文字铺满 1320px。

## 7. 动效

### 7.1 时长与缓动

| 令牌 | 值 | 用在哪 | 理由 |
| --- | --- | --- | --- |
| `--dur-1` | `120ms` | 颜色 / 边框 / 背景的 hover 与 focus | 短到感觉是"立刻"，但能遮住状态跳变 |
| `--dur-2` | `200ms` | 抽屉位移、侧栏滑入 | 位移类动效需要更长一点才不突兀 |
| `--ds-dur-slow` | `320ms` | 品牌层预留（当前无消费方） | 大面板展开时才用 |
| `--ds-dur-spin` | `700ms` | 按钮加载转圈 | 一周的时长，慢了显得卡 |
| `--ds-dur-pulse` | `1100ms` | 进行中步骤的呼吸点 | 与人的呼吸节奏接近，不催人 |
| `--ds-dur-shimmer` | `1400ms` | 骨架屏扫光 | 慢到不吸引注意力 |
| `--ease` | `cubic-bezier(.2, .6, .3, 1)` | 全部过渡 | 起步快、收尾缓，符合"内容先到、装饰后到" |

### 7.2 允许与禁止

- **禁止前端计时器伪造进度**。六阶段状态由后端 `steps` 字段驱动，
  前端只做"如实翻译"（`app.js:1319 paintSteps` + `app.js:73 STEP_STATE_TEXT`）。
  后端只给总状态时，界面如实显示并记一条改造项，不许用 `setTimeout` 补中间态。
- **加载反馈就近**：按钮用 `data-loading`（`:626` 的转圈伪元素）而不是盖全屏遮罩；
  区块用骨架屏（`:902`）；长任务用时间线（`.steps`）+ 事件流水（`.tasklist`）。
- **只在状态真的变化时动**：轮询（`app.js:1418 pollOnce`）拿到与上次相同的状态时
  不重启动画，避免"一直闪"。
- 禁止装饰性动画（漂浮、渐变流动、无意义的入场动画）。

### 7.3 减少动态效果（必须遵守）

`app.css:1106` 有全局降级：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
  }
}
```

注意：降级只停动画，**信息不能只靠动画传达**——所以 `.steps` 的每个状态都配了
状态文字（`.steps__state`），转圈按钮旁边一定有"上传中…"这类文案。

## 8. 组件规范

本章是"照着写就能用"的规格。每条都标了**实现位置**（`app.css` 行号 / `index.html` 锚点 / `app.js` 函数），
新增同类组件必须复用同一套令牌，**不允许在页面里另写一份尺寸**。

### 8.1 按钮

四种形态，语义从强到弱：

| 类名 | 何时用 | 外观 | 实现位置 |
| --- | --- | --- | --- |
| `.btn--primary` | 一屏**只有一个**的主操作（开始分析、上传、登录） | 实心品牌蓝 `--brand-600`，白字 | `app.css:591` |
| `.btn` | 次要操作（重试、取消、查看详情） | 白底 + `--n-400` 边框 + `--n-800` 文字 | `app.css:558` |
| `.btn--ghost` | 第三级（卡片头部的轻操作） | 同 `.btn`，边框更浅 `--n-200`，文字 `--n-700` | `app.css:607` |
| `.btn--chip` | 筛选/标签式切换（如示例问题） | 药丸形，`--n-25` 底 + `--n-200` 边框 | `app.css:610` |

- 尺寸：`padding: 7px var(--sp-4)` + `line-height: 1.5` + `font-size: --fs-sm`，
  实测高度约 **35.5px**；`gap: 6px` 用于图标与文字。
- 四种状态：`hover`（底色加深一档）/ `active`（再深一档）/ `disabled` / `data-loading`。
- **禁用态禁止用 `opacity`**（`app.css:578-583` 写了原因）：主按钮白字一旦和浅底做 alpha
  混合会掉到 1.00:1，按钮看起来像"渲染坏了"。禁用态一律换显式配色：
  次按钮 `--n-100` / `--n-300` / `--n-600`，主按钮 `--brand-100` / `--brand-200` / `--brand-700`
  （`app.css:584` 与 `:601`，两套都过 WCAG 4.5:1，`tests/test_frontend.py:469` 会验）。
- 加载态：`data-loading="true"` → `pointer-events: none` + 12px 转圈伪元素
  （`app.css:626`，`border-top-color: transparent`，0.7s 一圈）；同时文案要换成"上传中…"。
- 触控目标：桌面 35.5px 可接受，**移动端主操作按钮必须 ≥44px**（加 `min-height: 44px`），
  否则违反移动可用性；当前 `.btn` 未加，属已知待办（登记在 §16）。

### 8.2 输入框与表单

- 结构：`.field-label`（`app.css:642`，`--fs-sm` / 600 / `--n-700`，上边距 `--sp-4`）

- 控件（`app.css:650`）：`padding: 9px var(--sp-3)`、`border: 1px solid var(--n-400)`、

  （`app.css:663`）。**注意**：这是唯一允许"去掉 outline 自己画焦点"的地方，

### 8.3 上传区（数据集上传）

  段落 `line-height: 1.8`；`.cites`（`:1029`）是等宽 `--fs-xs`/`--n-500` 的引用来源。
- 九段顺序固定：标题信息 → 核心指标 → 主要发现 → 图表与趋势 → 分类/产品比较 →
  详细数据表 → 数据质量 → 局限性 → 完整报告入口。
- **必须区分三种内容**：原始数据（表格）、计算结果（指标）、AI 生成解释（段落）。
  实现手段：解释性段落前用 `.sub-title` 标注，AI 段落末尾带 `.cites`。

### 8.16 状态与反馈的通用规则

| 场景 | 必须出现 | 组件 |
| --- | --- | --- |

## 9. 数据与图表规范

### 9.1 先认清技术现实：图表是后端生成的 PNG

本项目的图表由 `app/agents/charts.py` 用 matplotlib 在后端渲染成 PNG，前端只负责摆放。
三条硬事实（决定了本章所有规则）：

1. `_DPI = 120`（`charts.py:62`），`figure.savefig(target, dpi=_DPI)`（`charts.py:156`），
   **没有传 `facecolor`** → PNG 底色就是 matplotlib 默认的白。
2. 中文字体靠 `plt.rcParams["font.sans-serif"] = list(_CJK_FONT_NAMES)`（`charts.py:107`），
   候选顺序 `("Microsoft YaHei", "SimHei", "DejaVu Sans")`（`charts.py:82`）；
   `plt.rcParams["axes.unicode_minus"] = False`（`charts.py:108`）——
   微软雅黑没有 U+2212 减号，不关掉负号会变成方框。
3. 配色**写死在后端**：`_BAR_COLOR = "#3b6ea5"`、`_LINE_COLOR = "#c0504d"`（`charts.py:69-70`），
   分别用在 `axes.bar(...)`（`charts.py:303`）、`axes.plot(..., marker="o")`（`charts.py:305`）
   和 `axes.scatter(...)`（`charts.py:311`）。

推论（不是偏好，是约束）：`.charts figure` 必须固定白底（`app.css:978-980` 的注释），
本轮不做深色模式的理由之一就在这里（见 §11）；前端**不能**给既有 PNG 换肤。

### 9.2 图表色板令牌

| 令牌 | 值 | 对应后端常量 | 语义 |
| --- | --- | --- | --- |
| `--ds-chart-1` / `--ds-chart-bar` | `#3b6ea5` | `_BAR_COLOR` | 条形图、散点、主系列 |
| `--ds-chart-2` / `--ds-chart-line` | `#c0504d` | `_LINE_COLOR` | 折线、对比系列 |
| `--ds-chart-3` | `#2f7d6b` | — | 分类扩展第 3 色 |
| `--ds-chart-4` | `#a5701a` | — | 分类扩展第 4 色 |
| `--ds-chart-5` | `#5b5fa8` | — | 分类扩展第 5 色 |
| `--ds-chart-6` | `#8a5a8f` | — | 分类扩展第 6 色 |
| `--ds-chart-surface` | `var(--n-0)` | — | 图表容器底色（永远白） |
| `--ds-chart-grid` | `var(--n-150)` | — | 网格线 |
| `--ds-chart-axis` | `var(--n-300)` | — | 坐标轴 |
| `--ds-chart-label` | `var(--n-600)` | — | 轴标签、刻度文字 |

规则：**新增图表优先复用 `--ds-chart-1/2`**；只有当一图里必须区分 3 个以上系列时才启用 3–6，
且按顺序取用、不跳号（跳号会让同一张图在不同页面含义不一致）。
若确实要改颜色，必须**同时改 `charts.py` 的常量和这里的令牌**，两边值必须逐字相同。

### 9.3 色盲安全：颜色不能是唯一编码

`contrast_check.py` 的色盲筛查（4 条提示，见 `contrast_report.txt`）指出：
浅色下 `--ds-chart-1` 与 `--ds-chart-5` 在红色盲/绿色盲模拟下的色距只有 0.045 / 0.021
（深色候选 0.047 / 0.011）。这意味着**只靠颜色区分系列是不可靠的**。

因此多系列图必须叠加至少一种非颜色编码：

- 标记形状（`marker="o"` / `"s"` / `"^"`）或线型（实线 / 虚线）；
- 直接标注（在系列末端写系列名）而不是只靠图例；
- 图例文字本身带形状符号。

单系列图（如只有一个指标的条形图）不受此限。

**这条规则对后端出图同样有效，不只是前端。** 图表是后端 `matplotlib` 生成的 PNG
（`app/agents/charts.py:303` 柱状、`:305` 折线、`:311` 散点），前端 CSS 管不到它：
多系列图必须在 `axes.plot()` 里给出不同 `marker` 或 `linestyle`，不能只靠两个颜色常量区分
（当前后端只有 `_BAR_COLOR = "#3b6ea5"`、`_LINE_COLOR = "#c0504d"`，见 `app/agents/charts.py:69-70`；
多系列时应扩成与 §9.2 `--ds-chart-*` 对齐的色板，并把中文标注与单位写在图上）。

### 9.4 图表容器与图注

- `.charts`（`app.css:972`）：`auto-fit / minmax(320px, 1fr)`，`gap: --sp-4`；
  ≤1080px 最小宽降为 280px；≤760px 单列。
- `.charts figure`（`app.css:973`）：`padding: --sp-3` + `1px --n-200` + `--r-md` + **白底**。
- `.charts img`（`app.css:982`）：`display: block; width: 100%; height: auto; --r-sm`。
- `figcaption`（`app.css:983`）：上边距 `--sp-3` + 上分隔线 `1px --n-150`；内部两行：
  `.ctitle`（`--fs-sm`/600/`--n-800`，图表标题）、`.cmeta`（`--fs-xs`/`--n-500`/`tabular-nums`，
  放数据范围、样本量、单位、生成时间）。
- 图表容器高度不要写死：按 `width: 100%` 让 PNG 保持纵横比；一屏图表顺序与报告小节顺序一致。

### 9.5 数字与单位格式

**全部由 `app.js` 的格式化函数产出**，模板里不许手写数字格式（否则同一数字会出现两种写法）：

| 函数 | 位置 | 输出 | 用在哪 |
| --- | --- | --- | --- |
| `fmtInt` | `app.js:249` | 千分位整数 | 行数、订单数、计数类指标 |
| `fmtBytes` | `app.js:260` | 人类可读体积 | 数据集文件大小 |
| `fmtPercent` | `app.js:274` | 百分比（1 位小数） | 占比、增长率 |
| `formatSeconds` | `app.js:237` | 秒/分秒 | 分析耗时 |
| `fmtDateTime` | `app.js:494` | 本地时间（含日期） | 创建时间、报告时间 |
| `parseUtc` | `app.js:224` | 解析后端 UTC 串 | 上面两个函数的输入 |

配套要求：数值用 `tabular-nums`；单位比数值小一档（`--fs-sm`/400/`--n-600`）；
比率必须写基准（"占订单量的 12.3%"）；同一指标在不同页面的精度必须一致。

### 9.6 图表必须自解释（题目要求，来自任务书 7.5）

- 标题要写清"**什么指标 × 什么维度 × 什么时间范围**"，例如
  "各地区销售额（2024Q1，n=1,842 条订单）"，而不是"销售额"。
- 坐标轴必须有单位；时间轴必须标出区间。
- 图例、轴标签、单位、数字格式全站统一（同一类图不换写法）。
- **不许为视觉效果编造趋势**：数据不足就说"样本不足，未绘制趋势图"，
  不能用平滑曲线把 3 个点画成一条趋势。
- **无数据不等于 0**：没有数据的维度不画 0 高度柱子，改在 `.empty` 里说明。

### 9.7 数据质量与局限性的呈现

- 用 `.note`（`app.css:545`）或 `.banner--warn` 列出：缺失字段、缺失比例、
  样本量不足、时间范围偏差、口径变更。
- 位置固定：数据质量说明排在详细数据表之后、结论之前（任务书 7.5 的九段顺序）。
- **AI 解释与计算结果必须可区分**：解释段落前用 `.sub-title`（"解读"），
  并在段末用 `.cites`（`app.css:1029`）列出依据字段/图表编号。

## 10. 图标原则

- **现状**：`index.html` 里有一段内联 SVG 精灵（`<svg class="icon-sprite">`），
  共 18 个 `<symbol>`：`i-upload`、`i-dataset`、`i-analysis`、`i-report`、`i-history`、
  `i-settings`、`i-check`、`i-warn`、`i-error`、`i-info`、`i-refresh`、`i-close`、
  `i-chevron`、`i-help`、`i-spark`、`i-menu`、`i-download`、`i-external`。
  使用方式：`<svg class="icon" aria-hidden="true"><use href="#i-xxx"></use></svg>`。
- **尺寸与描边**（`app.css:172`）：`1.05em`（跟随字号）、`fill: none`、
  `stroke: currentColor`、`stroke-width: 1.7`、圆角端点与连接、`vertical-align: -.16em`。
- 原则：
  1. **一个动作全站一个 id**；不要为同一含义新增第二个图标。
  2. 图标**不单独承担语义**：旁边必须有文字，或元素本身有 `aria-label`。
  3. 纯装饰图标加 `aria-hidden="true"`（品牌 mark、按钮内图标都是）。
  4. 只用内联 sprite，**不许**图标字体、外链 SVG、CDN——离线硬约束，
     而且 `tests/test_frontend.py:139` 会扫描 `http://` / `https://`（连注释里都不能出现）。
  5. 精灵里的 `<symbol>` 不写 `xmlns`：这是 HTML 内联场景，解析器会自动补命名空间；
     **不要**为了"看起来规范"把它加回去（加了反而等于在文件里写了一个绝对网址）。
- 新增图标流程：先在内联 sprite 末尾加 `<symbol>`（保持 `viewBox="0 0 24 24"` 与现有笔画粗细一致），
  再用 `.icon` 引用；不要用 `width/height` 覆写尺寸，用 `font-size` 控制。

## 11. 明暗主题：只做浅色，且这是决定不是遗漏

**决定：本轮不提供深色模式。** 依据写在 `app.css:1114-1126`（代码里就有，不靠本文档口口相传）：

1. 图表是后端 matplotlib 的**浅底 PNG**；做深色就必须让图表容器永远白底，
   页面上会出现一块块突兀白斑，而要真正做好得让后端出两套配色。
2. 项目的展示价值在"**数字可核对**"，不是主题切换。深色会引入一整套需要重新核算对比度的
   令牌——文件里所有 4.5:1 / 3:1 的核算结论全部作废。
3. 离线三文件、零依赖，没有主题切换接口，只能跟随 `prefers-color-scheme` 自动切换，
   用户无法手动选择，体验反而更差。

具体表现：**故意不写** `@media (prefers-color-scheme: dark)`；`.charts figure` 固定白底
（`app.css:980`）是为将来留下的正确起点。

**已为将来预留的候选深色色板**（`--night-*`，定义在 `.tmp/design/contrast_check.py:48-84`，
25 组配对的对比度核算全部通过）：画布 `#12161b`、卡片 `#1a2027`、正文 `#e6e6e4`、
主色 `#6d9ed4`（配深底文字 `#0e1319`）、危险 `#f0917f`、成功 `#5fc494`、警告 `#e3b968`。
若将来要上线深色，三件事必须同时做：① 后端出深色图表配色（或改前端渲染）；
② 把令牌双主题化（`[data-theme="dark"]` 覆盖，而不是复制一整套 CSS）；
③ 重跑对比度脚本且 0 不达标。

**禁止"半套深色"**：只把 `body` 改暗、卡片仍白，或用 `filter: invert()` 糊弄，
或把 `.charts figure` 的固定白底当 bug"修"掉。

## 13. 可访问性

### 13.1 键盘

- 第一个 `Tab` 是"跳到主内容"（`.skip-link`，`app.css:151`，聚焦时回到左上角）。
- 全局焦点环 `:focus-visible { outline: 2px solid var(--brand-500); outline-offset: 2px }`

- 焦点顺序必须等于视觉顺序；不用 `tabindex` 正数。
- 上传区的隐藏 input 必须留在 tab 序列里（§8.3）；用户菜单按钮带

### 13.2 对比度（全部由脚本核算，不靠肉眼）

- 口径：正文与次要文字 **≥4.5:1**；大字（≥18.66px，或 ≥14px 且 700 字重）≥3.0:1；
  非文本 UI（边框、图标、状态点、图表元素）≥3.0:1。
- 核算脚本：`.tmp/design/contrast_check.py`（含 3 项数值自检、与 `tests/test_frontend.py` 禁用态口径的
  交叉验证、红绿色盲近似筛查），报告：`.tmp/design/contrast_report.txt`。**本轮脚本 EXIT=0。**
- **本轮裁决 (b) 已执行：改令牌值。** `--ds-color-ink-subtle` 不再跟随 `--n-500`，改取 `#6f6f6a`：
  压在 `--ds-color-canvas`（`#f7f7f6`）上 **4.712:1**、纯白底 **5.051:1**，两边都过 4.5。
  为什么选 (b) 而不是只改用法：这一档是设计系统里"最弱但仍可读"的元信息色，
  它本身就该在画布底与白底上都达标，否则每个新页面都要靠人记住"这个灰只能放在白底上"。
- **渲染层还差 4 行配对改动**（不在我的写权限内，交 frontend-engineer，见 §15.2 第 6 步）：
  `app.css` 里压在页面底上的四处 12px 元信息文字 —— `.nav__group`（`app.css:439`）、
  `.nav__flag`（`:466`）、`.sidebar__foot`（`:476`）、`.crumb`（`:494`）—— 目前仍取
  `--n-500`（`#73736e`），实际渲染值 **4.446:1**。修法：改用 `--n-600`（画布底 **6.265:1**），
