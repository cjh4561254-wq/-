发起后在运维台会发生什么

路径完整可走
  1. 01202 受理：任务入"等待中"列，状态 PENDING，此时只有 created_at。
  2. 02轮询差异：前端每 1000ms 调 GET /api/workflows/{id}，看到状态变化才写一条事件，非实时。
  3. 03阶段推进：以 step_index / total_steps 阶梯呈现，阶段级耗时需后端补时间戳后才能显示。
  4. 04任务卡：task_id / description / status / error 四列，任务态含 SKIPPED。
  5. 05终态：SUCCESS / SUCCESS_WITH_WARNINGS / FAILED；总耗时 = finished_at − created_at（真实）。
  6. 06报告：切亮色层阅读，每个数字带 T 角标可回溯到工具调用。
  7. 07不可做的事：取消、重试、暂停、删除、导出——后端没有这些接口，界面上也没有。

!空态 C · 读取失败

历史接口 500，队列无法建立基线。
文案：任务列表读取失败，并明确"当前显示的不是空队列，是不可用数据"。
出路：重试读取（GET /api/workflows/history），同时在事件流记一条采样失败。

加载态 · 采样基线建立中

首轮轮询未返回，列骨架显示占位行，标题写 建立状态基线中（第 1/2 轮采样）。

约定：加载骨架不做闪烁以外的动画，轮询刷新也不整屏闪一下。

429错误态 · 接口限流

Retry-After: 34。运维台的处理不是弹提示，而是：把该接口标为"节流"、暂停自动采样 34 秒、把事件写进底部抽屉、其余列保持上次状态不变。

401错误态 · 会话失效

HttpOnly 会话过期（默认 8 小时）。界面盖住运行区并回到登录视图，保留当前视图与筛选，重新登录后回到同一列，不丢采样窗口。
