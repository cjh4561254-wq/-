0410 套都遵守的同一条纪律：不画后端没有的东西

这条不是审美选择，是我先把后端接口逐条核对过之后的硬边界。所以你在 10 套原型里都找不到下面这些常见但虚假的元件：

  • 没有"导出报告 / 下载 PDF / 分享链接" —— 后端根本没有导出接口（现有前端也已在 index.html:637 自陈无导出能力）。放上去就是假按钮。
  • 没有"阶段耗时 / 甘特图 / 按时间的百分比" —— WorkflowState 只有工作流级 created_at/started_at/finished_at，轮询接口只暴露其中两个。所有方案一律降级成 step_index/total_steps 阶梯 + 整条任务真实总耗时，并在界面上写明"阶段级耗时需后端补时间戳"。
  • 没有"实时日志流 / 秒级推送" —— 真实机制是 1000ms 轮询，09 甚至把事件流明确标注为"轮询采样差异，中间态可能没采到"。
  • 没有通知铃铛、全局搜索、保存视图、协作评论、Token 成本、模型选择器 —— 都没有接口。数据集搜索框是保留的，因为 GET /api/datasets 的 q 参数真实存在。
  • 没有"删除/重命名数据集" —— 上传、详情、画像、列表之外没有别的写接口。
  • 反过来，改密（POST /api/auth/password）和多设备会话列表（GET /api/auth/sessions）在 04/03 等方案里出现了入口——因为它们后端真的存在，只是现有前端还没做。

每套原型都常驻一条 视觉方案示意 · 数据为占位样例 · 未接入后端，占位数字不会被当成真实分析结果。

05还有几件事我没做（如实说明）

  • 没有在你的浏览器里肉眼看视觉效果：这台机器的内嵌浏览器截图不可用。我做的验证是结构与代码层（视图数、交互实装范围、禁用项、语法、id 引用、对比度计算），视觉判断权在你。
  • 没有碰任何生产页面：app/web/ 一行没改，符合你"选择前禁止大规模重构正式页面"的要求。（app/ 下现有 18 个已修改文件是本次会话之前就存在的未提交改动，不是我这轮产生的。）
  • 多智能体是真跑的，但角色不是我自封的：本轮共 21 个子智能体（3 个研究 + 2 个只读盘点 + 16 个方案作者，含一次中断后补齐）。可用的子智能体类型只有 Explore / Plan / general-purpose 三种通用类型 + 我给的角色简报，不存在提示词第十八节列的那 8 个内置专用 Agent 预设，我不假装它们存在。
  • 方案 02 的文档有 3 处我亲自改过：原稿声称 #8A8C93 对比度 ≥4.5:1（我复算实为 3.1:1），已按 Demo 修正为 #5A5C63；任务卡的 kind 与工具 category 是两个不同真实字段，已标明。另外 02 的作者把自己文档里的"SERVICE_UNAVAILABLE 才给重试"误判成违反禁止清单——我核了 app.js:55 的 RETRYABLE，那是重试 HTTP 请求不是重试任务，合法。
